# 当前 QBS/AKV 算子仿真实验矩阵

## 1. 实验要回答什么

本轮不是把旧论文的全部脚本原样再跑一次，而是回答五个问题：

1. 当前 RTL 在真实模型算子上，相对优化 RVV 的完整调用收益是多少？
2. 收益来自少发指令、减少数据搬运、提高计算吞吐，还是软件准备复用？
3. QBS 协作、结果队列和 Resident 等新增部分是否有独立收益？
4. 换格式、矩阵形状、头维度和上下文长度后，收益及合法回退是否稳定？
5. 共享乘法器、共享 FMA 和专用请求借用资源后，普通 RVV 是否仍正确、是否退化？

旧论文 r9 的主要性能证据是 Qwen2.5 的四种投影格式、三个 Decode KV 长度、
小规模强制 Prefill 及激活重复复用。它们证明过相应版本的机制，不等于当前
Qwen3、Resident、协作和共享算术 RTL 已得到同样评价。本轮主结果全部使用新
镜像。历史数据只提供单独标识的桥接，不与新数据混合计算几何平均数。

## 2. 固定版本、输入和对照

硬件身份及构建规则见 `PLAN.md`。固定真实 CVA6、4 Lane、VLEN1024、ELEN64、
128-bit AXI，以及当前共享整数乘法器、共享 FMA、QBS 借用和 Resident QK/PV。
16 MiB RAM 是 simulation-only 容量，不是芯片 SRAM 容量，也不等价于 FPGA DDR。
不修改总线、存储容量、生产 RTL 或数值契约来追求更高加速比。

- 主模型为 Qwen3-1.7B；Llama-3.2-1B 提供不同头维度和 GQA 的真实输入。
- 每个输入标明：原生真实捕获、真实数据裁剪、重新量化、结构性派生或合成边界。
- Q4_K_M 是混合格式文件，逐张量记录实际 profile，不能把整个文件称作 Q4_K。
- QBS 主对照使用已有的 format-specific x32 多输出 RVV；单输出 RVV 仅作诊断。
- Attention 主对照保留已有较强的分块、多头复用和寄存器轮换实现；普通 Direct
  RVV 只用于分离软件分块贡献。使用 AKV replay load 的 RVV 代码属于 AKV 调度
  对照，不能重新命名为普通内存 RVV。
- 两侧使用相同权重、激活、完整 K、数值契约和输出集合。路径特有的静态权重
  重排可放在稳态 ROI 外，但单列时间、空间及首次使用成本；运行时激活量化
  和必要打包计入完整调用。

## 3. 七组实验

以下是计划范围，不是已全部编译、排队或通过的声明。实际执行以每个冻结的
manifest 和终态结果为准。避免所有维度全排列，主曲线、消融和边界各取能区分
假设的代表点；有相同输入和配置的结果只运行、统计一次。

### 1：真实线性投影性能

| 维度 | 安排 | 要回答的问题 |
|---|---|---|
| 算子 | Attention Q、FFN gate/up、FFN down 为核心；混合格式 V 投影补充 | 覆盖 Attention 投影及 FFN 的主要矩阵形状 |
| Decode | 实际 Decode 激活，M=1 | 单 token、准备开销和短命令成本 |
| Prefill | 实际不同 token 激活行，M=4、8；必要时较大 M 分块 | 不能用复制同一行代替真实批量输入 |
| K | 保留捕获张量的完整输入维度 | 不裁剪量化分组或点积归约来缩短仿真 |
| N | 主点 N=64，代表点 N=128 | 识别固定调用开销被小输出放大的情况 |
| 路径 | 优化 x32 RVV、当前 QBS | 同输入、同输出数量、同精度验收 |

当前已有 Q4_K Prefill 八条不同激活行及 Q6_K 实际 Decode 数据。Q4_K 的
M1 子集仍是 Prefill 行切片，不将其写成真实 Decode。尚缺的算子/阶段需要
补捕获后再准入，不能以重复数据假装完成。

主图展示完整调用加速比；量化、准备、SDK 提交、引擎计算、排空/写回单列。
报告有效乘加工作量、指令数、共享向量端口返回字节和输出误差。

### 2：九种权重 profile

Q2_K、Q3_K、Q4_K、Q5_K、Q6_K、Q4_0、Q5_0、Q8_0、IQ4_NL。
所有格式先覆盖 M1；M4 用于检验多行布局及复用，按运行预算扩展。

为比较硬件格式路径，可把同一真实 Qwen3 权重解量化后分别重新量化，固定
K2048/N64。此类输入必须称为受控格式转换，不能称为九个原生模型。格式
之间的结果值不要求相等；每个格式都与该格式自己的独立数值参考比较。
Q8_K 与 Q8_0 激活的块长度、块数量和元数据必须分别计算。

至少为旧论文的 Q3_K/Q5_K/Q6_K/Q8_0 提供当前 RTL 的可对照点。主表列周期、
有效乘加、返回字节、格式修正/FP 更新数，解释短块格式为何不同于 K 格式。

### 3：QBS 复用、协作和缓冲消融

| 项目 | 必须保持相同的工作量 | 对照 |
|---|---|---|
| 激活复用 | 同一真实激活、相同输出集合 | 每调用准备、软件量化复用、硬件上下文复用 |
| 跨算子复用 | 同层真实 Q/K/V 或 gate/up，确认输入字节一致 | 不复用、合法复用；不同激活不得复用 |
| M4 准备 | 四条不同激活和相同矩阵 | 四次 M1、一次 M4；区分准备和计算收益 |
| M8 协作 | 八条不同激活、相同 M/N/K | 两次 M4、M8 借用关闭、M8 借用开启 |
| 整数结果队列 | 同一个适用 QBS 调用 | 默认队列、同源 depth=0 控制镜像 |

仅全开配置比 RVV 快，不能证明借用或队列有贡献。同源结构开关镜像仅改变
被测开关，先做资格测试再运行配对点。不要求把每个格式和形状都展开消融。

### 4：完整 Decode Attention 与 Resident

执行完整 QK、score 变换、Softmax、PV 和输出归一化，不能只测 QK/PV 后
称为 Attention。主对照为优化 Tiled RVV、原生 AKV、AKV+Resident。

- 真实 Qwen3 捕获覆盖短、中、较长 KV。输入长度512/1024的首次后续 Decode
  实际有效 KV 为513/1025；横轴使用实际值，不能四舍五入成512/1024。
- 真实 Llama-3.2 数据补 D64 和不同 GQA。头数切片保留模型头到 KV 头映射。
- 从真实前缀合法取 T63/64/65、127/128/129 等点检查 tile 和尾块。
- D96/GQA3、GQA6 等派生点用于结构范围，不冒充 Qwen3 原生模型形状。
- Resident 不满足准入时记录正常回退；控制性强制执行单列，不等于 Linux
  默认可用。裸机测得的收益不能替代 Direct-U 租约或驱动的板测结果。

Resident 另取少量代表点比较 QK-only、PV-only、QK+PV，记录完整调用、fill/
refill、准备与排空。首调用、同输入重复、下一 token 的 Q 更新/KV 追加必须
分清。不能复用过期 snapshot 获得虚假收益，也不能把每次重新加载的结果称为
跨调用驻留收益。内部加速与 SDK 总开销同时报告。

### 5：因果 Prefill Attention

用真实不同查询及完整因果 mask，主点查询16/64，历史 KV128/512；依据数据和
墙钟校准选择足够大的实际点，不把过小强制路径作为全部 Prefill 结论。

对比优化 Tiled RVV、原生 AKV，以及查询分组/Panel4/适用 Register-PV 调度。
对同一输出比较数据供给次数、column 命令、logical columns、replay 字节与
实际返回字节。逻辑流量减少不能代替 AXI 计数。查询切片保留其在原序列中的
绝对位置及全部可见 key，不能把后半段查询改成局部短序列。

### 6：范围、尾块和回退

- 量化 KV：Q4_0/Q8_0 K、Q8_0 V，使用对应独立参考，不能沿用 F16 gold。
- D256：验证切分、数值调度和合法回退，不强迫现有 Resident 执行不支持维度。
- QBS M2/M3、N 尾块、K 分段；命令能力之外的 K 保留完整软件累加语义。
- Attention 非连续 stride、GQA 分组余数、mask 特征及不支持 score 变换。
- 检查实际选择、错误返回或 RVV fallback，而不是仅看到程序最终 PASS。

边界组以正确性和路径为主，性能只在代表点收集，不把大量负测试混进加速比
平均数。对于不属于架构支持范围的输入，拒绝或回退也是正确结果。

### 7：资源共享与普通 RVV 共存

先验证共享整数乘法器和共享 FMA 的普通 RVV 指令，再以 QBS/RVV/Resident
交替序列覆盖借用、归还、排空和 sticky flags。ISA/结果签名与独立参考比较。

已有共享/非共享结构控制仅用于代表点，不做未经测量的面积或功耗推断。
要求实际能力/参数展开检查，不能只根据命令行 define 认定开关生效。
普通 RVV 功能正确和性能无明显回归，分别给证据；顺序交替通过不等于已经
验证所有并发和异常交互。

## 4. 每点数据和正确性

| 层次 | 需要收集的内容 |
|---|---|
| 完整调用 | 周期、首次/重复、准备/提交/执行/排空，静态重排单列 |
| 请求与指令 | 标量/向量提交、自定义命令、实际路径、fallback 原因 |
| 真实计算 | 整数有效乘积、原生 FP 和 Resident 私有 FP 握手、有效元素数 |
| 数据供给 | 权重/激活/KV payload、replay、共享向量 AXI 读返回和写事务 |
| 阻塞 | 请求等待、队列占用、结果槽冲突、资源等待；按原 RTL 定义解释 |
| 数值与协议 | 全输出、fflags、vxrm/vxsat、vstart、输入/保护区、独立事务闭合 |

原生 FP 计数通常不含 Resident 私有请求，需单独探针。忙碌周期不是有效计算
利用率；请求吞吐不是流水级占用；不同精度不能共用未经推导的峰值分母。
引擎专属 phase 只有证明互斥且完备后才画100%堆叠图。多个可同时发生的 stall
指标不能直接相加。

正确性检查和打印安排在 ROI 外。可以把独立 gold 编译进目标程序，在目标端
逐元素、逐字节比对并输出简洁结果，避免大量 printf 主导仿真墙钟时间；
不能用单一 hash 取代逐元素数值检查。参考和被测代码不得是同一实现的拷贝。

## 5. 执行次序与完成标准

1. 当前镜像：普通 RVV 和 QBS/AKV 交接通过，核验实际展开及源/ELF 哈希。
2. 校准：真实 Q4_K/Q6_K 投影配优化 RVV、T137 完整 Attention；核验检查器、
   ROI 和墙钟速率。先校准不等于只做这些点。
3. 主性能：投影及真实上下文 Attention，优先完成当前论文可用的同输入曲线。
4. 机制贡献：复用、M8、结果队列、Resident QK/PV 代表点，补 Prefill。
5. 格式、形状及共存：补齐九 profile、尾块、量化 KV 和普通 RVV，再统一收集。

最多四路 VCS；准备、独立参考计算及数据整理可与仿真重叠。单点目标不超过
三小时，先校准后裁剪独立输出，不靠无限延长 timeout。长任务由独立 systemd
服务直接持有，不频繁人工轮询，不自动覆盖结果或修 RTL 后继续混收。

每组必须交付清单、冻结输入、逐点 CSV、原始证据、数值/独立协议判定、实际
路径和未完成项。只有当前镜像、同工作量、检查通过的配对点用于正式性能图。
最终图表建议：投影加速图、格式/形状表、复用/协作消融、Attention 上下文
曲线、Prefill 流量/周期图、真实计算活动图。完整模型收益仍由 FPGA 端到端
实验单独回答，不能把多个算子加速比相乘。
