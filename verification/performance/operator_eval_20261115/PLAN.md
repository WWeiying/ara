# 当前硬件算子级评价计划

## 目标与版本

完整范围为 QBS 投影、九种格式、复用/协作消融、Decode Attention、Prefill
Attention、扩展/回退、资源共享与共存七组。校准点通过不等于完成这七组。
不修改生产 RTL、总线、容量或数值规则以追求漂亮结果；不做综合或新板测。

主 SoC 从 `ara_dsa` 的 `dbe2b78817ef45b912444afcb85ad6e01a2be135`
提交归档。锁定依赖来自通过身份检查的
`enablement_soc_resident_deployment_20261112_022423`，四个 CVA6 门控文件
使用当前提交中的 FPGA 冻结导出，逐项核对其哈希等于审核后的主 RTL。
不是整体复制当前脏依赖；未提交 testbench 和 AKV 汇编均不得混入。

主配置固定真实 CVA6、4 Lane、VLEN1024、128-bit AXI、16 MiB simulation-only
RAM、共享整数乘法器、共享 FMA、QBS lane 借用及 Resident QK/PV 全部展开。
软件默认不选的候选单列实验，不能把“硬件展开”写成“运行时已使用”。
RAM 扩容仅用于容纳输入，不是片上 SRAM 面积或真实 DDR 性能模型。
Direct-U 门控以复位 legacy 权限执行裸机算子；这些测试不证明 Linux 租约效果。

| 编号 | 必须交付的内容 | 首批点 | 后续扩展 |
|---|---|---|---|
| 1 | 真实投影的优化 RVV/QBS 同输入对照 | Qwen3 Q4_K、Q6_K，完整 K、N64/128 | Attention、gate/up、down；M1/4/8及较大M分块 |
| 2 | 九种权重格式的数值、路径与周期 | Q4_K/Q6_K复用首批 | Q2_K/Q3_K/Q5_K/Q4_0/Q5_0/Q8_0/IQ4_NL；统一维度M1/M4 |
| 3 | 复用与协作贡献 | 真激活、同输出工作量 | fresh/软件复用/上下文复用；M4准备；2xM4/普通M8/协作M8；代表点队列消融 |
| 4 | 完整 Decode Attention 三路径 | 真实 D128/GQA2/T137 | T64/128/256/512/1024；D64/D96和不同GQA；QK/PV单独消融 |

病例必须区别：真实模型原生捕获、真实数据合法裁剪、转换格式、派生数据、合成
边界。Q4_K_M GGUF按实际张量类型分类，不假定所有权重都是Q4_K。
没有真实捕获的形状不冒充模型形状。投影完整K不可裁剪；Attention不可截短
Softmax范围后沿用原参考。小N点补第二个N规模以识别固定开销放大。

## 测量与检查

- 完整调用包括真实量化/准备、计划提交、执行、最终排空；引擎周期单列。
- 实际 GGML算子、SDK切片、引擎测试分层标记，不相互替代或外推模型加速比。
- 内核ROI内不打印结果、不新增阶段fence；需要时比较插桩/无插桩的扰动。
- 数值按既定契约比较全输出；检查flags、VCSR、VSTART、输入、保护区及实际路径。
- 独立被动协议检查必须验证请求/返回、AXI和完成债务。仅打印PASS不够。
- 计数区分真实FU接受、有效元素、忙碌周期、逻辑payload、本地重放和AXI字节。
  有重叠的阻塞观察不拼成百分之百的周期分解。
- 主文结果必须来自本轮镜像；历史数据只作单独标识的桥接比较。

## 并行与执行

先编译一份全开主镜像，固件与检查器由不同任务并行准备。先运行普通RVV
smoke和三类校准点，再按校准的周期/墙钟速率冻结正式矩阵。主调度器最多四个
VCS子进程；不同时再启动一组独立队列绕过上限。确需结构开关的镜像后续单列。

每项上限三小时，不通过放宽超时或随意改输入掩盖故障。超长点先核查进度和
合法的输出维度裁剪方案。新失败停止后续派发，已有在途项保留结果；不自动修
RTL或重新跑同一目录。长任务由systemd服务直接持有，确认执行后不频繁轮询。

输出统一在 `ara_dsa_signoff_integration/verification/out/operator_*`。
`build_soc.py`准备独立源码快照与新镜像；`campaign.py`准备有限任务清单、
执行最多四路、运行数值/协议检查并生成 `summary.csv`。
每个输出目录只运行一次，原失败不能改写为成功。

最终汇总应包括逐点CSV、源/工具/ELF/镜像哈希、原日志、数值与协议判定，
以及七组完成状态。图表输入只使用正式通过的本轮数据，缺口明确留空。
