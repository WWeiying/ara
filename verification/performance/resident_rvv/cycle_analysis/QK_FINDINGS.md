# QK：后续接入前的工作量和资源核对

这是对已通过的原始周期探针的重新计算，不是新 RTL 或新的性能通过记录。
新工具 `qk_review.py` 重新运行原 `analyze.py` 的证据/哈希/算术工作检查，然后按
四 lane、每 lane 两个 FP32 SIMD 元素核对完整 Qwen3 D128/H2/T137 的 QK 工作。
证据：验证树 `verification/out/resident_qk_work_review_20261109_01.json`。

## 1. 不能把平均工作量当作最慢 lane 的执行时间

三次 QK helper 为 T64、T64、T9，合计 9,901 周期。每个输出元素保持 128 个维度
递增顺序的 FP32 FMA。两 head 合计 35,072 个有效 FMA 元素、768 条向量 FMA 指令。

| Lane | 有效 FMA 元素 | SIMD FMA 接受 | K 源未就绪周期 | 旧累加值未就绪周期 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 8,960 | 4,608 | 3,085 | 2,482 |
| 1 | 8,704 | 4,352 | 3,501 | 2,770 |
| 2 | 8,704 | 4,352 | 3,501 | 2,770 |
| 3 | 8,704 | 4,352 | 3,501 | 2,770 |

T9 在四 lane 上分为 3/2/2/2 个 FP32 元素。lane0 的最后一拍只用一个 SIMD 元素；
两 head、128 维带来 256 个屏蔽 SIMD slot，不能算成有效 FLOP。
表中未就绪条件可能同时出现，不能相加为 stall breakdown。

平均 4,416 次接受适合计算平均投放率（44.60%），但不是最慢 lane 的时间下限。
保留当前元素到 lane 的映射，且每 lane 每周期最多接受一次 FP32 SIMD FMA时，
三 tile 的算术投放下限为 2,048+2,048+512=4,608 周期。
它不含初始化、转换、系数/列供给、所有权和最终提交，不能当作可实现周期。
若将来改变 head/token 的分配，此下限也须重算，不能称为硬件的绝对理论下限。
旧 README 中的 4,416 数字应按“平均 lane 工作量”理解，而非每条 lane 相同工作量。
旧封存说明及其 pins 保持不变，修正解释记录在这里。

## 2. 当前瓶颈来自内部搬运和累加路径，不是这些区间中的 DDR

原 paired helper 使用 `vakv2kpanel4` 一次读取四个 K 列到 v8-v11；随后按维度依次
执行两 head 的 `vfwmacc.vf`，更新 FP32 v0:v1/v2:v3。它已复用了同一个 K 列，
并非每个 head 都重新访问外存。

| QK 区间观测 | 数值 | 含义 |
| --- | ---: | --- |
| panel4 命令/成功终结 | 96/96 | 每 tile 32 条 |
| 列 bank 读取周期 | 576 | 已有列收集逻辑的实际活动 |
| replay word 完成 | 1,152 | 先经 LDU 写入 VRF |
| replay 等待最终写确认周期 | 1,281 | 不能等同于 bank conflict |
| 初始 replay 写请求被拒绝周期 | 0 | 初始接受不是该处观察到的瓶颈 |
| context bank conflict | 0 | 没有证据支持复制 SRAM 或加端口 |
| AXI AR 接受 | 0 | K 已驻留；加宽 DDR 不能直接移除这段等待 |
| FPU 输出反压 lane-cycle 总数 | 1,528 | 不同于 replay 初始接受；四 lane 汇总 |
| FPU 结果 VRF 写被拒绝 lane-cycle | 2,140 | 普通累加结果仍反复写 VRF |

这些是原始已接受区间的事实，不是可相加的“可节省周期”。尤其需要避免把
LDU replay 请求未被拒绝，误解为浮点结果写回没有压力。

## 3. QK 应复用 PV 的哪些内容

PV 先完成真实准备成本与 SoC 收益决策，再启用 QK 扩展；不新建一套独立乘加器。

- **同一份局部累加存储。** PV 的两行 D128 FP16 共 512 B；QK 两行最多 64 token
  的 FP32 分数同样为 512 B。互斥模式应复用同一物理数组，不实例化两份。
- **同一 VMFPU。** PV 使用四路 FP16，QK 使用两路 FP32。现有借用端口硬编码 FP16，
  并不能通过仅换输入数据自动支持 QK；还需明确格式、有效元素 mask、结果 tag 和状态切换。
- **保留现有 K 列收集。** 当前 context 已有四列结果暂存，不应另复制完整 K tile。
  后续从现有收集结果分拍供给，在私有状态里更新累加值，最终一次写回分数。
- **不覆盖持久 Q。** Q 在独立 Q store，跨 K/V refill 保持有效，不能拿它存 PV 概率。
  `akv_unified_context` 的 legacy replay 仲裁还禁止与 column_busy 同时读取，不能因
  SRAM 物理分开就直接删检查；先选择不冲突的 Q/K 调度，或对新并发模式独立证明。
- **查询暂存要显式计费。** 若选择缓存两 head 的一个 16-dimension query 块，需 64 B，
  另有 valid/位置状态；它不是免费复用的已有存储。也可少缓存多读取，最终由完整调用决定。
- **复用安全边界。** 沿用旧工作排空、全 lane owner、预提交错误取消、单次 flags 和
  最终写确认，不通过取消普通 hazard 检查取得速度。

FP16 的 K/query 不能把原始位模式直接送入 FP32 FMA。原生路径在 operand_queue 和
scalar 接受处做 widening re-encoding；新模式须覆盖子正规数、NaN、无穷和 signed zero。
`ara_pkg::fp32_from_fp16` 会把 NaN quiet 化且本身不返回异常标志，因此只复制该函数
并不证明 signaling-NaN 的 NV 语义正确；必须保留有效输入的异常信息，或使用现有
FPU conversion 路径，并与独立 oracle 比较。这里指出的是新路径的验证义务，尚未通过
完整指令反例判定原生 VFWMACC 是否存在另一个缺陷，也未修改普通 RVV。

## 4. 下一步决策

先等待已启动的真实 PV 准备成本测试；其正常运行不依赖上述新增文件。
若 PV 仍有完整调用收益空间，按既有 SoC 审核接入，再将共享控制扩展为 FP32 QK。
QK 的期待收益来自减少 panel-to-VRF-to-FPU 及每次累加的往返，而不是少算维度、
改变 FP32 累加顺序或给 inactive 元素算上“吞吐”。主频、lane 数、总线均保持原样。

`test_qk_review.py` 四项 host tests 核对 384 个有界几何和错误输入/账本拒绝；
几何枚举不是 384 次 RTL 仿真。新报告由完整原始探针重新计算生成，未启动新的 VCS。
