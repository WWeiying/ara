# 量化 QK 与原 RVV 点积的数值顺序核查

## 核查对象与证据层级

本项不重新运行 RTL，而是复用已通过的3336个 QBS 硬件输出和24份目标量化器
生成的 Query 字节，检查它们与原 RVV 点积的浮点运算顺序是否一致。

原 RVV 模型不是从高层公式猜测：生产 `arch/riscv/quants.c`、实际 GNU 编译
对象及已执行 ELF 的反汇编均已固定。模型同时用此前16个真实 RVV 输出及
逐点异常标志交叉核对，全部一致；之后才应用于完整矩阵和尾块。

因此必须区分：

- QBS 的3336个值是实际 RTL 结果，已通过独立 QBS 参考和协议检查。
- 16个原 RVV 值是实际 RTL 对照，也是本次顺序模型的锚点。
- 对全部3336个位置的原 RVV 比较使用主机顺序模型，不是新跑的整矩阵 RVV。
- 硬件异常标志在批量测试中只观察到每条命令的 OR，不冒充逐输出异常记录。

当前结果目录为
`verification/out/akv-quantkv-rvv-order-analysis-20261024-03`。

## 实际指令顺序

设一个32元素块的整数点积为 I，权重和 Query 的 F16 scale 分别为 dw、dq，
sum 为前面各块的 FP32 累加值。实际目标反汇编对应：

```text
原 RVV Q8_0:
    scales = round32(dw * dq)
    sum    = fma32(float(I), scales, sum)

原 RVV Q4_0:
    first  = round32(float(I) * dw)
    sum    = fma32(first, dq, sum)

QBS 当前契约:
    scales = round32(dw * dq)
    sum    = fma32(float(I), scales, sum)
```

Q8_0 与 QBS 的顺序相同。Q4_0 一般不能声称逐位等价，因为先乘整数与先乘
两个 scale 的舍入位置不同。主机模型使用显式 FP32 中间值、fmaf、RNE和
关闭隐式 contraction 的编译选项，不能把整个表达式先用 double 算完再转
回 float。Double 仅用于检查单次乘法是否精确，并不替代实际 FP32 累加。

## 当前真实数据为何一致

| K 格式 | 比较输出数，含尾块重复位置 | 块计算次数 | 最大绝对整数点积 | 原 RVV 第一次乘法发生舍入的块数 | 最终位模式不同 | 命令累计标志不同 |
|---|---:|---:|---:|---:|---:|---:|
| Q8_0 | 1668 | 6672 | 73640 | 0 | 0 | 0/20 |
| Q4_0 | 1668 | 6672 | 6702 | 0 | 0 | 0/20 |

两种格式的最大 ULP 与最大绝对输出差异均为0。完整逐位置比较保存在
`comparisons.json`，逐命令标志比较保存在 `command-flags.json`。

有限 F16 最多有11位有效数字。两个有限 F16 的乘积最多22位有效数字，
数值范围也在 FP32 正常范围内，所以这组输入的 dw*dq 精确。

当前 Q4_0 整数点积最大绝对值6702，小于8192，只需13位有效数字。
I 与 dw 的乘积最多需要13+11=24位，FP32能够精确表示。原 RVV 的第一次
乘法和 QBS 的第一次乘法因此都不丢位，后续 FMA计算同一个精确乘积加
前一累加值；按相同块顺序递进，结果和异常标志随之相同。这解释了当前
样本的一致性，而不是靠放宽误差阈值获得通过。

## 为什么不能推广成所有输入都相同

定向测试另外构造了合法 Q4_0/Q8_0 编码，使整数点积达到-32385。
此时 I*dw 可以先发生 FP32 舍入，而 dw*dq 仍然精确。测试确实检测到不同
scale 组合下的位模式或异常标志差异，说明模型不会机械地把两条路径判成
相同。这是两种运算顺序的区别，不直接等于 QBS RTL 算术错误。

运行：

```bash
python3 -B verification/akv/quantized_kv/test_rvv_order_score.py
python3 -B verification/akv/quantized_kv/test_order_precision.py
```

第一组还检查256组有限 Q8_0 随机编码的模型结果与 QBS 参考一致；这些是
主机模型性质测试，不计为新增 VCS 用例或硬件覆盖率。

本结论不改变原始容差、生产选择或新指令的数值契约。完整 Attention、
模型质量和其他输入范围仍须分别验证，不能用这里的点积分析代替。
