# MVP dirty-patch audit: measured defects

## Verdict

Keep the MVP patch quarantined. The single actual VCS run reproduced both
introduced static hypotheses and the pre-existing FP32 missing-NX case. This is
`AUDIT_REPRODUCED_DUT_FAILURES`, with DUT status `FAIL_ARCHITECTURAL_ORACLE`,
not DUT PASS. No original or verification dependency RTL was edited or patched.
The verification MVP dependency remains clean. Fingerprints of every required
dependency input were identical before and after the run.

The measured object is original MVP HEAD
`86e1f558b3c95e91577c41b2fc452c86b04e85ac` plus canonical full-index diff SHA-256
`3cc6ec1c27eca277853d85e9c47fae317f0f0cd9cfc8589a95742117d6beaf6a`.
Classification as introduced versus pre-existing also uses the preceding static
HEAD comparison; this experiment did not compile a second HEAD DUT.

## Cycle evidence

- FP64 1/1: quotient `0x100000000000000`, explicit rounding container zero,
  lower bits `00`. Raw 58-bit remainder `0x300000000000000` is signed
  `-72057594037927936` (= `-(denominator << 4)`); denominator is
  `0x10000000000000`. `remainder_nonzero=sticky=1`. RUP sets roundUp=1;
  RNE sets roundUp=0 but NX remains 1. This directly distinguishes a faulty
  exactness predicate from an inexact mathematical quotient.
- Both directed FP64 overflows: OF=1, normalized exponent `0x7ff`, normalized
  mantissa zero, explicit round bits zero, sticky=roundUp=1. Rounded mantissa
  becomes 1 while exponent remains `0x7ff`, producing the invalid infinity
  encoding shown above. RNE has the same overflow selection but roundUp=0;
  RTZ selects normalized exponent `0x7fe` and max-finite mantissa.
- FP32 overflow: remainder_nonzero=1 exists at the new interface, but FP32
  ignores it: lower/sticky/roundUp are zero, OF=1, and NX=0. This is not an
  operand boxing or result-format mismatch.
- Eight unique reset-isolated requests were accepted and eight Done indications
  consumed; final pending count is zero. Acceptance-to-post-NBA Done latency
  was 19 cycles for FP64 and 9 for FP32. Every post-NBA completion payload
  matched the following pre-edge consumption payload.
- Reset, latched operand mantissas/exponents, format, resolved RM, sign,
  precision control, known completion bits, completion count and drain checks
  all succeeded. There was no timeout or unexpected DUT result requiring a rerun.

## Reproducibility and scope

Output directory: `verification/out/mvp-patch-audit-20260922/`.

- `summary.json`: per-case classification, patch hash, command counts, zero
  harness errors, and `dependencies_unchanged=true`.
- `inputs.json`, `inputs/`: SHA-256 manifest and read-only byte-exact snapshots
  of MVP, required original common_cells inputs, bench, case manifest and plan.
- `dependency_fingerprints.json`: before/after dependency source fingerprints.
- `build/command_result.json`, `build/compile.log`: one VCS compile, return 0,
  25.03 seconds wall time; no warning/error records found in compile console.
- `sim/command_result.json`, `sim/run.log`: one simulator invocation, return 0,
  10.84 seconds wall time including startup; 0.870 seconds reported simulator
  CPU time and 1.966 us simulated time. VCS reports its ASLR bootstrap re-exec;
  the simulation executed the eight-case sequence once, without a diagnostic retry.
- `sim/results.csv`: exact bits, flags and arithmetic witnesses per case.
- `sim/trace.csv`: pre-edge and post-NBA lifecycle/arithmetic probes, about 105 KB.
- `sim/probes.vcd`: bounded top-level probe aliases, about 82 KB. The CSV is
  the primary cycle evidence; no FSDB installation or full-design dump was needed.

oracle validation, rejection of malformed/missing/duplicate evidence, and
classification that cannot label a reproduced defect as a passing control.

were created. No synthesis, CVA6/VMFPU run, backend change, RTL repair, or second
compile/simulation was performed.
