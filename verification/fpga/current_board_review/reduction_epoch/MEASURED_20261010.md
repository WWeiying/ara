# Reduction activity epoch discriminator

Frozen final02 fails the changed-VL independent-reduction pair. The failure is
measured in both the architectural output and a bounded cycle-level capture,
not merely inferred from the untagged activity OR. No RTL or shared helper was
edited and no hardware build was launched.

## Inputs and results

Sources: `epoch.S`, `epoch.c`. Adapter: `adapter.py`. All artifacts are in
`measurement01/` under this directory. The adapter reuses the checked integration
compiler/replay helpers and byte-identical sealed bare-metal startup, runtime,
and linker script. Their provenance and hashes are in
`measurement01/prepared/provenance.json`.

All tests use e16/m1, four lanes, VLEN1024, RNE, mask bit 1 alone set, and initial
VL16. First reduction: `vfredusum.vs v8,v4,v2,v0.t`, seed `0x7c01` (sNaN), active
source `0x3c00` (1.0). Second reduction uses disjoint v9/v5/v3 and only finite
1.0 operands. Flags are cleared before the pair and read after the pair; no
flag CSR access, store, scalar extract, or fence occurs between reductions.

## Measured cause

`capture.py` reruns the identical combined ELF with exactly 50 selected signals
and a 7000-7400 ns FSDB window, without forces. Execution took 26.69 seconds,
bounded to 90 seconds. `measurement01/capture01/` retains the profile, Tcl,
commands, FSDB, selected VCD, and pre-rising-edge decoded `cycles.csv`,
`events.json`, and `finding.json`. `analyze.py` reuses the existing comparison
VCD reader and asserts the ordering and values below.

Cycle means pre-edge CVA6 `cycle_q`, also used in the architectural commit trace;
the physical edge time in this run is cycle + 15.5 ns.

| Cycle | Measured event |
| --- | --- |
| 7090 | First reduction allocated, arch sequence 40, vid0. VL1 vset request also acknowledged. |
| 7101 | Second reduction allocated, arch sequence 42, vid1, before first reduction completes. |
| 7103 | Lane 0 accepts first reduction's FP return with NV=1; pending flags become 0x10. |
| 7107 | First returned SLDU token handshakes in lanes 0/1; activity vector=0010, global=1. |
| 7121 | Final old SLDU token handshakes; lane 0 enters SIMD_REDUCTION. |
| 7123 | Lane 1 finishes old reduction locally. |
| 7124 | Lane 1 accepts first micro-op of vid1/vd9, local VL0; activity changes 0010 to 0000 while lane 0 still has vid0/vd8 and pending=0x10. |
| 7130 | Lane 0 transitions SIMD_REDUCTION to MFPU_WAIT with pending=0x10 but global=0. Publication gate suppresses NV and clears pending. |
| 7131 | Lane 0 writes 0x7c01 through the empty-reduction seed mux and signals local done. |
| 7132 | Old reduction globally completes. |
| 7164 | Second reduction globally completes. |
| 7168 | End-of-pair `csrr fflags` retires with zero. |

Thus this is not a premature CSR read, lost raw FP exception, or a second
reduction raising its own NV. The CSR read follows both global completions.
The VL update is not a barrier: it is acknowledged at cycle 7090 and retires
at 7092; the second operation is allocated at 7101, well before old completion.

UCLI messages interrupt UART text at dump boundaries, splitting the changed-VL
`EPOCH_RESULT` line. The complete architectural line is in the non-UCLI replay;
the capture still has both mismatch records, `BOARD_CASE_FAIL changed_vl`, and
the same failing CSR retirement. Simulator process exit zero is not a PASS.

## Capture edge for the repair owner

A safe epoch snapshot point for the frozen four-lane unordered tree is the
first returned SLDU-token handshake, not the first local FPU issue or local TX
acceptance:

```systemverilog
mfpu_state_q == INTER_LANES_REDUCTION_RX &&
sldu_transactions_cnt_q == $clog2(NrLanes) + 1 &&
sldu_mfpu_valid_q && sldu_mfpu_ready_d
```

Capture `reduction_global_any_active_i` per reduction there and retain it through
flag publication and lane-0 result grant. In this trace that captures one at
cycle 7107, before the overwrite at 7124; the next epoch captures zero at 7139.
Offline, the captured bit would preserve NV=0x10 at publication. This is a
repair recommendation, not a simulated patched result.

Static support: frozen `sldu.sv:700` requires all lane input words before
emitting a reduction aggregate. Each lane's first partial is sent only after
its source phase completes. Later rounds require all lanes to consume the
preceding token, so no lane can finish this tree and start a younger reduction
before another lane consumes its first returned token. Local TX acceptance
alone is insufficient because independent SLDU input spill registers can
accept a fast lane before other lanes finish their sources. Merely entering
INTER_LANES_REDUCTION_RX is therefore also too early.

Both the new flag gate (`vmfpu.sv:1563`) and existing seed mux (`vmfpu.sv:2612`)
need the same retained epoch value. The live activity overwrite is at line
2234; local queue advance is at line 2553. Snapshotting only the flags leaves
the measured wrong-result failure intact.

## Scope and reproduction

This confirms an incomplete final02 NV repair, not a newly demonstrated
regression from `7d5d1829`: the numeric seed-selection epoch dependency already
existed, and the new deferred-flags gate inherits it. No before-image replay or
patched RTL test was run. Measurement covers FP16 unordered sum and four lanes,
not all min/max, lane-count, or backpressure configurations.

Run from the integration worktree, with fresh output directories:

```sh
D=verification/fpga/current_board_review/reduction_epoch
python3 -B "$D/adapter.py" build --out "$D/measurement02"
python3 -B "$D/adapter.py" replay --build "$D/measurement02" --out "$D/measurement02/soc_replay"
python3 -B "$D/capture.py" --build "$D/measurement02" --out "$D/measurement02/capture01" --start-ns 7000
python3 -B "$D/analyze.py" "$D/measurement02/capture01"
```

The replay command is expected to exit nonzero for unchanged final02. The
7000 ns capture start is tied to this ELF and image, not a general trigger.
