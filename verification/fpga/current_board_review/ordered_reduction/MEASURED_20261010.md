# Sparse Ordered FP Reduction NV: Measured Repair

## Decision

The current code was NOT already fixed. Change only the OSUM `issue_be`
expression in `hardware/src/lane/vmfpu.sv` to apply `osum_active` to
`be(1, vsew)`. This puts the exception enable in the same low-slot coordinates
as the compacted operand. No other RTL or shared verification helper was edited
by this task. No commit, Verilator, ZCC, full SoC build or board run was made.

First-slot, unmasked and all-off controls distinguish the coordinate error.

## Signoff Boundary

This is reduced RTL success, not original full-regression success. Real VMFPU
and FPnew run behind modeled instruction, operand and mask delivery and slide
transport. Result bits are checked at destination writeback; sticky flags are
formed from actual registered `fflags_ex_o` events, not from a real CSR file.
The eleven original reduced VL points are replayed with scenario-3 data;
their LMUL labels do not validate dispatcher decoding or register allocation.
The deployed run selects the exact deployed VMFPU with current, pinned FPnew
and common-cell dependencies, not an entire reconstructed deployed image.

The archived board evidence did not print raw result bits. This test compares
simulated raw results to original fixtures; it does not retrospectively prove
raw-bit equivalence of that board run. Full original ELFs, other reduction
scenarios, actual CSR retirement, frontend/VRF/mask/slide integration and a new
whole-image/board campaign remain outside this result. The patch is stable for
the parent's later integrated image validation.
