--parent-review to identify the actual independent review JSON, not the prose
authorization file. The previous interface did check the actual ENTRY separately,
but used the prose path as that command argument. Narrow successor correction
checks the actual review path/hash directly, retains decision/plan/worker/checker/
READY hashes and independent pins, and pins authorization prose separately.

host_worker02.json remains an actual eight-test PASS for that prior code.
host_worker03.json tests this changed interface plus all unchanged numeric and
protocol boundaries. No source, reference, helper, oracle or image was changed.
Fresh prepared03 is the only candidate for actual Tesla entry admission.

Its ready envelope includes the known actual ENTRY.json path and an explicit
__ACTUAL_ENTRY_SHA256__ placeholder. This is NOT an accepted review digest and
cannot pass the runtime gate. After the actual review exists, the sole launcher
must replace that argument with its actual hash and retain the full substituted
service argv in a new launch receipt. The review is not added to the plan, avoiding
circular identity binding; it is pin-checked at launch and terminal.
