# VLDU Public-Port Exception A/B

## Scope

Host VCS, real VLDU plus the same `stream_register` used on each lane's
operand_requester load-result input. Stimulus drives only public ports. A bank
model writes its byte-array VRF only on the final grant, independently of initial
requester acceptance. Internal counters in the CSV are read-only diagnostics,
not stimulus or the architectural byte oracle. No production RTL was edited by
this consumer-test owner. This is not a SoC, Sv39, trap/CSR or QBS-arbitration test.

Six tests use four lanes, VLEN1024, AXI256, e16. Four-lane bank backpressure is
released at cycle35. Every case includes a later independent normal load after
the exception cleanup observation. The byte oracle checks the full 128-byte
destination, including inactive elements, pre-vstart bytes and tail preservation.
The FOF case sets the actual `fault_only_first` request bit and supplies the
ordered terminal exception descriptor; it does not model the sequencer's VL CSR
update or prove trap suppression.

### Premature Prefix Completion

`baseline02/partial_exception/{cycles.csv,run.log,window.vcd}`:
vstart1, VL8, active odd elements, data/skip descriptors for elements1..4,
exception descriptor at element5. Four meaningful bytes (elements1 and3) enter
the requester buffers at cycle12. Done is observed at cycle15 with written=0;
the bank writes these four bytes at cycle35. Full final data is eventually
correct, but completion precedes writeback. FOF has the same observed ordering.

The identical candidate test preserves accept12/write35 and delays done to37.
No missing prefix bytes, prefix/tail corruption or duplicate completion occurs.
The combinational `load_complete_o` precedes registered done by one cycle:
baseline14 versus candidate36. Both forms of baseline completion precede the
cycle35 writeback; both candidate completion observations follow it.

### Empty Fault Accounting Versus Data Completion

`baseline02/first_exception/run.log`: done at10, no meaningful byte writes at
any time. At cycle51 (settled, before external flush), issue/commit bytes are
16/16, result occupancy is0, mask valid is0 and idle is0. At cycle60 after a
public `lsu_ex_flush_i` pulse plus eight settle cycles, the same16/16 residue
remains. This is distinct from unfinished prefix data. The subsequent normal
load overwrites the counters and recovers idle; no inevitable Linux deadlock
is inferred. `ara_idle_o` is not the VLDU `idle_o` signal measured here.

The candidate issues no dummy result for this empty prefix, completes at9,
clears both counters and reaches idle without waiting for nonexistent bank work.

### Legal Mask Flush Boundary

For `candidate03/older_full_then_partial`, cycle79 has issue=0, commit=0,
result_count=0 but mask_valid=1111, idle=0. The two-entry mask spill can retain
another mask window for the aborted instruction. After the explicit external
flush, cycle88 has mask_valid=0000 and idle=1. The fixture does not demand idle
on the done cycle or misclassify this residual mask as uncleared byte counters.

## Original Fixture Error Preserved

`measurement01/first_exception` stopped on BAD_WRITE_ADDR for a BE=0 dummy request
whose address was zero. That assertion was too strict: with no byte enables,
there is no architectural write to validate. Its log, waveform, frozen input
and PROBE_ERROR status remain untouched. `baseline02` corrects only that oracle
qualification for the original four cases, adds an active-descriptor/R check,
and adds two separately named boundary cases. It does not change the prefix
data, final-grant or completion oracle to accommodate the RTL failure.

## Arrival Contract Review

The candidate's unconditional exception-head / early-illegal gating of
`pe_req_ready_o` is a separate risk, not covered by the six PE-first cases above.
VLSU broadcasts `normal_pe_req_valid` separately to AddrGen and VLDU
(`vlsu.sv` connections around225 and301). AddrGen accepts in IDLE without VLDU
ready qualification (`addrgen.sv` around309); top-level broadcast gating is
for lane/mask/slide readiness, not an explicit consumer-accepted descriptor tag.

At the isolated consumer boundary, a terminal head before first instruction
acceptance would deassert ready while the exception FSM requires an issued
instruction to remove that same head. Qualifying this admission gate with
`vinsn_issue_valid` avoids that local circular wait while preserving exclusion
when an actual issued instruction is being terminated. This is a static
interface concern; full-system reachability under sequencer credits and common
broadcast timing is not proved by arbitrary port-order stimulus.

The separate `vldu_arrival_tb.sv` tests descriptor-before-request,
descriptor-same-cycle, and the corresponding early-illegal-sideband sequences.
It does not alter the six-case A/B fixture. Arrival results are reported
separately and are not included in the successful six-case exception result.

`arrival_candidate04` freezes the same `19fd5b69...` VLDU. The separate arrival
TB SHA256 is `d2d7d2ffaff63bb699c746c753291a3b80329870f19a11be98abdf5958c9a5ca`.
All four probes finish their fixed observation windows with accepts=0, dones=0,

desc_valid=1, desc_ready=0, pops=0. In the sideband cases the early-illegal pulse
has already gone low, but the pending latch still prevents first acceptance.
These are failed admission-contract observations, not PASS results; the runner's
PROBES_COMPLETE reports successful collection only. The candidate state is idle
with no issued instruction throughout, so merely waiting longer cannot create

The same arrival TB in `arrival_baseline05` on original RTL accepts and completes
all four cases exactly once. For descriptor/sideband first, acceptance is at7
and done at13; for same-cycle cases, acceptance is at4 and done at10. Descriptor
cases pop exactly one token; sideband-only cases pop none. Original RTL still
retains the known16-byte issue residue and idle=0. Comparing its pins against
`arrival_candidate04` separates the new admission regression from the preexisting
exception cleanup defect. These original and faulty-candidate runs are preserved.

Final result: **PASS_6_EXCEPTION_4_ARRIVAL**, recorded in `ab_summary07.json`.
All four successor arrival cases accept and complete once and finish idle=1.
First-arrival variants accept at7 and complete at12; same-cycle variants accept

sideband-only variants pop none. The arrival baseline, faulty candidate and

All six PE-first observation dictionaries are identical between candidate03
and successor06, and the ordinary control exactly matches the original RTL.
No earlier result was overwritten or reclassified.

The latest independent review identifies a separate sequencer integration risk:
an unmasked FOF response can precede VLDU cleanup, permitting another load to
reach AddrGen before VLDU can accept it, or leaving more than one consumer
instruction at an exception head. The 6+4 consumer boundary result does not
prove that this integrated scheduling is safe. A real-sequencer public-port
reproduction is the next priority; no end-to-end closure is claimed here.
