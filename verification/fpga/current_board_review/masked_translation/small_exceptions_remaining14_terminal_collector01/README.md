# Remaining14 Terminal Collector

Minimal successor of unit_fof_e64_suffix_two_terminal_collector01. No DUT,
reference or CSV semantic traversal. One direct bounded service waits for
the producer's real ExecStopPost service_exit.json using the existing inotify
wait_terminal.py. Service exit without complete.json is a terminal failure,
not permission to retry or infer acceptance.

After closure it verifies exact14 membership/child0, raw28-log failure veto,
generic/strict counts, four memory owners per member, full source oracle/CSR
and exact ABI receipts, actual exited/0/success and all input/output hashes.
Only original sc0 final output slots5..8 are undefined. CSVs are hashed, not
parsed again. Per-case audit.py subprocesses retain their actual numeric waits;
the producer's in-process source checker has no fabricated separate wait0.

binding.json is created exclusively from the final reviewed plan/launch before
collector launch. Its own source, hook, event waiter and binding hashes are
preserved in collector launch provenance. First failure stops and publishes
NOT_ACCEPTED_NO_RETRY. RuntimeMaxSec7200, KillMode=control-group, Restart=no.
No effect on producer or any external simulator; no repaired/relabelled logs.
