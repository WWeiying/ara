## New Stimuli

Sixteen `vcoverage_gap33_e{8,16,32,64}_m{1,2,4,8}` tests cross legal SEW/LMUL
with VL=1, a lane-word boundary plus one, VLMAX-1 and VLMAX. Masks include zero,
all-one, alternating and sparse patterns. Each case exercises `vcpop`, `vfirst`,
`vmsbf`, `vmsif`, `vmsof`, `viota`, `vcompress` and variable-offset `vslidedown`.
The intent is to drive long mask consumption, multi-register transfers,
prefix propagation and slide data delivery, rather than add more short repeats.
This is a targeted reachability hypothesis; measured coverage deltas decide
whether it actually closes new points.

An independent scalar oracle computes each active result and checks the store
extent with sentinels. It does not compare unspecified mask tails or compress
tail elements. Registers v8/v16/v24 are aligned and disjoint even at LMUL=8.
VSTART remains zero for these operations, as required for compress/prefix work.

`linux_csr_gap33` uses the M-mode initialization hook to test CSR set/clear
readback of M/S scratch, EPC, TVAL, cause and counter-enable registers, masked
machine interrupt enables, and cycle/retired-instruction monotonicity.
It masks global interrupts and restores every written CSR. This is a CSR
prerequisite test, not Linux boot or comprehensive MMU verification.

All 17 programs passed Spike prechecks before VCS dispatch. The compiler is
the existing non-ZCC LLVM toolchain. Runtime objects are built in isolated
directories without replacing shared objects.

## Execution And Admission

`run_gap33_20261001.py` runs at most eight VCS workers using the unchanged
repaired image. Each case has a bounded 900-second host timeout; no RTL watchdog
or functional checking rule is relaxed. Ordinary functional failures retain
their first evidence and are excluded from verified coverage. Infrastructure,
source/image drift or checker failure stops the queue.

The existing runner checks application selfcheck, complete commit trace and
independent artifact audit. Spike is an independent precheck of the same test
source; these directed cases do not claim instruction-by-instruction RTL/Spike
comparison. PASS VDBs must match the expected image/test identity and checksum.

Output: `verification/out/gap33-current-20261001-01/`.

- `checkpoint.json`: progress for 17 new cases.
- `new-collection.json`, `dve/summary.csv`: newly run cases alone.
- `collection.json`, `combined-dve/summary.csv`: original 600 plus new PASS cases.
- `coverage-delta.json`: top-level percentage-point change from the 600-case report.
- `results/`, `outcomes/`, `scheduler/`: individual evidence and worker history.

The combined report preserves all 600 current-image PASS databases and never
re-runs them merely to add new test software. It verifies inputs before/after
DVE and checks exact selected-test membership. Coverage improvement is not
claimed until that report exists.

## Remaining Work

This wave does not close all gaps. SV39 permission/ASID/page-size and PTW fault
crosses, Dispatcher overlap/flush boundaries, and QBS child-FSM condition
combinations require a separate point-level review. Disabled features and
debug-only logic need reviewed exclusions, not unsupported PASS claims.
