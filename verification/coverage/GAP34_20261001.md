# Gap34: Sv39 permission and page-walk coverage

## Evidence before adding stimuli

The preceding 17-case extension passed, but mostly changed data and toggle
activity rather than control decisions. More SEW/LMUL combinations alone do
not force new page-walk permission paths.

The baseline contains 617 independently audited PASS tests from the same VCS
image. `gap34-baseline-20261001-01/points.json` decodes the actual VDB bit vectors,
not approximate coverage inferred from source lines:

| Direct instance | Branch points | FSM points |
| --- | --- | --- |
| CVA6 MMU | 34 / 96 | No FSM definition in this image |
| CVA6 PTW | 35 / 87 | 17 / 35 |

These direct-instance numbers are not hierarchical module percentages.
Uncovered PTW decisions include invalid/reserved PTEs, terminal non-leaf PTEs,
superpage alignment, instruction permissions, and data A/R/W/D/MXR checks.
MMU decisions additionally check privilege, U permissions and SUM.

## Stimulus selection

Three C tests share a 21-scenario body: load, store and instruction fetch.
Each scenario starts from a fresh page-table setup and invalidates translation
state. The matrix includes:

- Valid 4 KiB, 2 MiB and 1 GiB translations; global mappings.
- Invalid root/middle entries; reserved PTE bits; invalid R=0/W=1 entries.
- Non-leaf entries at the final walk level; misaligned superpages.
- A=0, D=0, W=0 and X=0 permission cases.
- Execute-only pages with MXR disabled/enabled.
- S-mode access to U pages with SUM disabled/enabled.
- U-mode access to supervisor and user pages.

Not every scenario produces a different outcome for every access type. D=0
must fault for store but must not fault for load; SUM cannot authorize an S-mode
instruction fetch from a U page. These distinctions exercise the access-specific
permission logic rather than merely increasing the number of addresses.

The independent scalar oracle checks trap count, exception cause, exact EPC
and TVAL, successful load value and store/fetch memory integrity. Spike runs
use the same source with PMP regions disabled to match the frozen configuration.
All three Spike prechecks passed; this does not substitute for RTL verification.

## Measured acceptance gate

`run_gap34_20261001.py` reuses the existing frozen VCS image without RTL edits.
It first runs only the load test. An independently audited PASS is necessary
but insufficient: the test must also set at least one previously uncovered
MMU/PTW branch or FSM point. The point comparison validates checksums and widths
and preserves all historical covered bits.

Only after this measured gate passes are store/fetch dispatched. Their PASS-only
VDBs are merged with the preceding 617 PASS tests through DVE. Failed tests are
excluded, source/image drift stops execution, and new VDB directories are used.
The automated artifacts include `coverage-gate.json`, `point-delta.json`,
`coverage-delta.json`, and `combined-dve/summary.csv`.

This wave targets branch/condition coverage. It does not promise new PTW FSM
states: disabled RVH paths and PMP access failures with zero PMP entries cannot
be reached by these stimuli. Flush-during-walk/reset transitions need separate
concurrency-oriented tests and are not implied by permission coverage.

## First measured result

The VCS load case completed its 21 scenarios and 85 checks with zero failures.
Independent audit admitted its VDB. Compared with the 617-test baseline,
`coverage-gate.json` records six newly covered branch points:

| Direct instance | Before | Baseline plus load | New branch points |
| --- | --- | --- | --- |
| CVA6 MMU | 34 / 96 | 36 / 96 | 2 |
| CVA6 PTW | 35 / 87 | 39 / 87 | 4 |

PTW FSM coverage remains 17 / 35. The store and fetch tests were then dispatched
in parallel; their results and the final DVE aggregate are not implied by this
first measured result.

These tests intentionally exercise scalar MMU/PTW paths and send no vector
commands. The image's unconditional CVXIF/VID no-traffic UVM diagnostics are
therefore not vector-protocol evidence. Admission here is explicitly the scalar
architectural self-check plus independent complete-trace audit contract, not
a claim that the vector UVM traffic contract was exercised.

## Commands

From the validation worktree:

```bash
python3 verification/tests/build_sv39_gap34.py --output verification/out/gap34-build-20261001-01
python3 verification/coverage/run_gap34_20261001.py --output verification/out/gap34-current-20261001-01 --prepare
python3 verification/coverage/run_gap34_20261001.py --output verification/out/gap34-current-20261001-01 --launch
cat verification/out/gap34-current-20261001-01/coverage-gate.json
cat verification/out/gap34-current-20261001-01/checkpoint.json
```

Build and run output directories must be new. Do not automatically retry a
failed gate or mix databases from a different compiled RTL image.
