## 请求路径和根因假设

MMU 有两组不同拍的输出：

- `lsu_dtlb_hit_o/lsu_dtlb_ppn_o`：当前 DTLB 查询当拍的 hit 和物理页号。
- `lsu_valid_o/lsu_paddr_o/lsu_exception_o`：寄存请求的后继响应。

`load_unit` 用提前 PPN 判断非幂等访问，进而决定是否等待提交资格及
store/write buffer 排空。因此，最终物理地址正确不代表提前 PPN 正确。
当前 SoC 的两个非幂等区域是 UART `0xc0000000..0xc0000fff` 和
CTRL `0xd0000000..0xd0000fff`。

旧代码把 `dtlb_is_page_q` 用于当前查询的 PPN，连续切换页大小时可能
使用上一请求的规则。同时，旧拼接将物理地址的 bit 编号直接用于 PPN，
忽略 PPN bit0 实际对应 PA bit12。修正保留后继物理地址逻辑，仅让提前
PPN 使用当前 `dtlb_is_page`，并在 PPN 的低位填入当前 VA 的相应 VPN 位。

独立期望公式为：设页大小为 S，页表给出的物理基址为 B，
则 `PA = B + VA % S`，`PPN = PA / 4096`。
这里的 B 必须满足对应页大小的对齐要求，不能用非法大页条目证明正确性。

例如，1 GiB 页将虚拟基址 `0x40000000` 映射到物理基址
`0xc0000000`。访问 `VA=0x40001000` 应得到 `PPN=0xc0001`，
属于 UART 页之后的普通页。若上一请求是 4 KiB 页，旧逻辑不补入
大页的页内 VPN，提前 PPN 仍是 `0xc0000`，误判为 UART。
反过来，上一请求也是 1 GiB 页时，旧拼接还可能破坏 PPN 的基址高位，
使真正的 UART 页不再被识别为设备页。这些是运行前按源码推导的判别
输入，不能代替实际 DUT 的周期观测。

## 定向测试要求

| 场景 | 必须观察和检查的行为 |
| --- | --- |
| 4 KiB、2 MiB、1 GiB 页 | 提前 PPN、后继 PA、valid 和异常分别核对 |
| 三种页大小的九种有序切换 | 当前输出跟随当前请求；寄存输出属于对应已接收请求 |
| 页内偏移和边界 | VPN 各低位、页首/页尾、字节偏移不误入 PPN |
| 物理页号高位 | 大页替换只影响页内 VPN 部分，不破坏物理基址高位 |
| 非幂等区域 | UART/CTRL 页及相邻普通页的分类与独立地址公式一致 |
| 翻译关闭 | 使用物理直通，不继承前一虚拟请求的大页状态 |
| 旧版本负向验收 | 同一 oracle 必须检出旧 RTL 的具体数值错误，不能只验证成功标志 |

测试应编译实际 MMU 及其依赖，不以复制出来的表达式替代 DUT。
若在 TLB refill 边界注入合法条目，需要明确这种测试不覆盖真实页表遍历；
不得 force 被检查的输出或内部地址拼接结果。

## 结果状态

2026-10-09 已完成宿主机 VCS 定向验收。三次正式实验使用完全相同的
278 个场景，每次执行 3060 项 SV 检查；Python 再按独立地址公式复核
`observed.tsv`，不只检查 PASS 字符串。

| RTL | 场景数 | 提前 PPN 错误 | 非幂等区域分类错误 | 其余检查错误 | 结论 |
| --- | ---: | ---: | ---: | ---: | --- |
| 迁移前原版 | 278 | 175 | 8 | 0 | 检出原有错误 |
| 吸收主线修正后 | 278 | 0 | 0 | 0 | 全部通过 |
| 仅故意恢复上一拍页大小的负向版本 | 278 | 160 | 8 | 0 | 检出请求归属错误 |

这里的错误数是检查失败数，不是独立 bug 数。最后一行只修改实验目录中
的源码副本，将新拼接中的 `dtlb_is_page` 改为 `dtlb_is_page_q`，证明激励
能够检出页大小错拍，而非仅检出旧版的位编号错误；没有改动工作区 RTL。

已通过的场景组成如下：

- 80 个翻译模式切换场景：三种页大小及关闭翻译共 16 种有序组合，每种
  5 个偏移，包括页首、页尾和字节偏移；其中包含九种页大小切换组合。
- 81 个虚拟页号逐位场景：三种页大小各检查 27 个 VPN 位，包括 canonical
  高半区地址。这不是非法地址异常测试。
- 105 个物理页号逐位场景：覆盖各页大小下合法、无需被页内 VPN 替换的
  PPN 基址位，检查高位不会被错误覆盖。
- 12 个设备区域场景：2 MiB/1 GiB 映射下的 UART、CTRL 页及其相邻普通页。

每个场景核对上一请求的寄存响应、当前查询的 hit/提前 PPN/设备区域分类，
以及下一拍的 valid/物理地址/异常有效位。测试还检查空闲和排空时无虚假
响应。实际观测的页大小也由 Python 核验，防止 TLB 安装错误造成假通过。

### 测试边界

测试编译实际 MMU、TLB 和 load unit，仅在 PTW 到 DTLB 的 refill 边界注入
合法条目，不强制被检查的地址输出。它不覆盖实际页表内存遍历、TLB miss、
权限异常或 SFENCE 语义；安装前的 flush 只是测试准备，不计作 flush 功能覆盖。
load unit 的 `valid_i=0`，因此验证的是其真实 `paddr_ni` 分类逻辑，不是
非幂等请求的等待、提交、重试或缓存事务。场景统计是定向功能覆盖，不是
全芯片代码覆盖率；RVH、Sv32 和完整 SoC 执行也不在本次验收范围内。

## 独立审查边界

提前 PPN 的消费者是非幂等区域判断。cache tag 和 PMP 使用后继完整
物理地址；本 SoC 的 PMP 表项数为零，本次不能宣称验证了 PMP 权限。
修改没有增加流水寄存器、状态或请求握手，不据此推断综合时序或全部应用性能。

独立静态审查指出，原有翻译分支还受 `!misaligned_ex_q.valid` 门控。
因此“上一请求未对齐，当前请求对齐且 DTLB 命中”可能出现当前 hit
与提前 PPN 不一致。是否会形成整机错误仍取决于 load unit、异常和 flush
对后继请求的接收约束。本次迁移没有更改这个条件，也不能通过忽略它
宣称已修复；若单元刺激触发，应作为独立的原有边界问题保留。
当前地址的 canonical 检查参与后继响应判定也需要同样的请求归属审查。
不得直接把后继响应中的所有 `_q` 替换为当前输入来解决此类问题。
