# Direct Gate Contract Correction v3

This successor supersedes the universal terminal prerequisite in the pinned
v1/README.md and v2/README.md, and qualifies REVIEW_V1_20261113.md. Those
files remain unchanged to preserve worker identities. This document does
not change the compiled overlay or certify board readiness.

## Instruction classes

External-memory FULL/REFILL and Resident operations must retain the original
request/transaction through terminal success or fault before the CPU can
transfer the architectural boundary to an interrupt/trap. Fault termination
must drain outstanding external reads. The controlled Linux policy kills the
owner on a user fault; it never retries FULL/REFILL or resumes a cleared
context. This is the requirement to review, NOT "every custom instruction
is terminal before every interrupt."

Valid LOAD/COLUMN_LOAD is local context-to-VRF replay and explicitly permits
early acknowledgement (akv_engine.sv:391). Replay may still be running at a
later CPU boundary. That is allowed only with both protections below:

1. Before lease teardown, first acquisition, context reset, MM invalidation,
   or granting another owner, the kernel's explicit CSR-vl read/fence must
   finish pending replay and memory work before RELEASE/ownership transfer.
   Permission-gate closure alone is insufficient.
2. Before switching VRF ownership, Linux vector context save/restore must
   drain any outstanding replay. Timer preemption is not an exception to
   this requirement. Skipped-save paths need a valid no-pending-work proof;
   do not substitute a bare vsetvli for a drain.

## Scoped evidence, not an integrated proof

In the current Ara dispatcher, all vector CSR accesses pass through
WAIT_IDLE (ara_dispatcher.sv:4662), which leaves only on ara_idle_i with no
outstanding dispatcher request (:1235). RELEASE (:5353) waits for idle and
acknowledges ara_resp_valid; it invalidates both native/resident context
flags (akv_engine.sv:979), and does not enter the VRF replay-write state.

The FULL/REFILL paths are ara_dispatcher.sv:5077 and :5158, with response
acknowledgements at :5114 and :5196. Resident PV/QK paths start at :5203
and :5260. The previously cited :4985 is the QBS path, not an AKV FULL path.
The read-engine fault condition at qbs_read_engine.sv:226 requires an empty
outstanding-burst FIFO and no stalled AR. CVA6 commit_stage.sv:391 checks
interrupts with a valid commit head; request eligibility/flush handling is
in acc_dispatcher.sv:365. These facts still require integrated review.

For Linux 6.19.6 standard V, arch/riscv/include/asm/vector.h provides:

- :130 __vstate_csr_save reads VSTART, VTYPE and VL before VRF save stores.
  With the above CSR semantics this is the drain before saving a dirty
  outgoing vector context (:196, :306, :369).
- :233 __riscv_v_vstate_restore restores VRF after enabling V and vsetvli.
  Restore does NOT independently prove an unconditional idle drain: Ara's
  OPCFG path (ara_dispatcher.sv:1685) can acknowledge without idle. Safe
  ownership transfer therefore relies on the outgoing CSR-save drain or
  established prior quiescence, including deferred-restore cases.
- The save is conditional on saved VS=DIRTY. CVA6 acc_dispatcher.sv:422
  marks V dirty for an acknowledged ACCEL commit, and csr_regfile.sv:2013
  applies that to status. The interrupt/early-ack/commit relationship must
  ensure a pending local replay cannot bypass that dirty-save path. This
  is not established merely by compiling Linux or reading the two blocks.

## Acceptance boundary

The v2 overlay is a compiled-candidate target only. Integrated timer IRQ,
early-ack replay, dirty-state tracking, skipped-save/deferred-restore and
teardown behavior remain pending review and runtime tests. If that review
cannot establish the ownership-switch drain, add an explicit safe drain in
a successor overlay before advertising the environment as ready. Do not
weaken this condition or claim that a vsetvli or a gate write proves it.

The safe absent-CSR probe, VS/VSTART-preserving RELEASE sequence, root-only
task/mm-bound lease, strict-at-boot TEST isolation and old-broker rejection
are unchanged. Host tests and Image compilation are not custom arithmetic,
old-bitstream, board-lifecycle or full-model acceptance.
