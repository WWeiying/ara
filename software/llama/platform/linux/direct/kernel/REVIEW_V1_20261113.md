# Direct Gate v1: Scoped Static Review and Build Status

This is an isolated TEST-kernel candidate, not a drop-in kernel, deployed
board environment, old-bitstream compatibility claim or full-model result.
On supported gate hardware, boot permanently selects STRICT: unleased native
AKV/GGML is denied, and the old ara_resident module is rejected. RVV and QBS
remain outside the AKV permission gate. Absent gate hardware returns ENODEV
from the device; missing hardware cannot provide isolation by software alone.

## Build successors

The v1 overlay and hooks are under kernel/v1. Use the successor helper
verification/performance/resident_deployment/direct_cost/linux/build_v2.py.
build_v1.py is preserved: its first service attempt demonstrated that the
base ACPI_PROCESSOR selected ACPI_PROCESSOR_IDLE and therefore CPU_IDLE,
preventing CONFIG_RISCV_AKV_DIRECT from enabling. The successor additionally
disables ACPI_PROCESSOR, without weakening the !CPU_IDLE dependency. It also
uses a separate copied UAPI include directory for host tests.

The requested configuration remains RV64/MMU/FPU/V, UP, PREEMPT_NONE, no RT,
no suspend/hibernation, no CPU idle and no KVM. ACPI_PROCESSOR is also off.
Every dependent change is reported in config.diff, not hidden in this summary.
Use the same prepared TEST kernel for both benchmark modes.

The builder freezes Linux, the UAPI, overlay, hooks and tests into a new
signoff output; live SDK sources are never modified. It retains original
and patched source inventories, source-pins.json, linux-hooks.patch,
base.config, test.config, config.diff, command logs and result.json. It first
compiles the driver and every modified callback site, then the complete Image.
Success means COMPILED_TEST_CANDIDATE_RUNTIME_PENDING, never a runtime PASS.

## Scoped RTL references

References below are to the working hardware sources read on 2026-11-13.
They are supporting static evidence, not an integrated interrupt proof or a
binding to a bitstream. Hardware review and the board lease-smoke are separate.

- hardware/src/ara_dispatcher.sv:4662: vector CSR operations always enter
  WAIT_IDLE before completion. At :1235 the wait leaves only when no pending
  Ara request remains and ara_idle_i is asserted. CSR vl is read at :4719.
- hardware/src/ara_dispatcher.sv:5353: RELEASE validates its zero register
  fields and VSTART0, waits for ara_idle_i, and acknowledges only on
  ara_resp_valid. The kernel encoding is exactly 0x0000505b.
- hardware/src/vlsu/vlsu.sv:847: AKV admission requires idle normal VLSU and
  no AKV/QBS/resident ownership; :851 defines terminal success/fault. At
  :1162 the address-generation acknowledgement uses terminal unless that
  command already took the explicitly permitted early-ack path.
- hardware/src/vlsu/akv/akv_engine.sv:744: RELEASE goes directly to SUCCESS;
  :979 clears context_ready_q and context_v2_q. VRF requests are generated
  only by REPLAY_WRITE at :670, not RELEASE. Payload success at :546 requires
  all issued ranges completed and context writes finished.
- hardware/src/vlsu/qbs/qbs_read_engine.sv:226: a read fault is exposed only
  when the burst FIFO is empty and no stalled AR remains. The AKV engine
  consumes that reader fault at :571 and clears context readiness at :1043.
- hardware/deps/cva6/core/acc_dispatcher.sv:365: request dispatch waits for
  non-speculative/committing eligibility and excludes unissued flushes;
  :386 forwards response validity and exception. The complementary
  commit_stage.sv:391 head-valid interrupt condition and Ara FULL/REFILL
  response paths at ara_dispatcher.sv:4985/:5203/:5260 must be reviewed as
  a complete integration, not treated as separate assertions of IRQ safety.

Important limitation: akv_engine.sv:391 permits early acknowledgement of a
valid LOAD/COLUMN_LOAD. Do not infer that every AKV instruction retires at
engine terminal. The explicit CSR-vl drain is necessary, including to finish
pending scratch-to-VRF replay before teardown. The complete preemption path
still needs runtime validation; these references do not substitute for it.

## Remaining acceptance

No integrated hardware preemption, MMU fault, signal, teardown or supervisor
RELEASE run has been performed by this build. The absent-CSR exception fixup
is compiled, not proven on old hardware by compilation alone. Kernel cleanup
uses no vector/FPU begin API in atomic context, preserves actual VS/VSTART,
drains before/after temporary SALLOW RELEASE, and poisons new grants on
cleanup failure. Memory safety on that failure still requires terminal/drain
completion; the permission gate is not itself a quiescence mechanism.

Leased user faults are fatal, with no FULL/REFILL retry. Benchmark setup must
complete code/stack/data/stdio/vector initialization and prefaulting before
ACQUIRE. Prefaulting/locking pages is a performance precaution, not proof of
correct hardware translation or lifecycle isolation.
