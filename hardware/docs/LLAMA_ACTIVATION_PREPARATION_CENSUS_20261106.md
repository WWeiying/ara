# 当前完整 Qwen3 模型的激活准备复用

## 1. 这次统计与旧记录的区别

本批复用了当前已核验完整模型的静态库，只重编译入口，开启已有 M4 准备和
生命周期日志；没有更换量化器、图策略、模型或 Attention 数值路径。真实
Qwen3-1.7B Q4_K_M 在两种 Attention 选择下分别运行 Q8_0/Q8_0 与 Q4_0/Q8_0
K/V 配置，每种配置包含 40-token Prefill 和两步 Decode。

6 次 logits 比较、911616 个数值、最终 CSR、token 及 native Attention 工作
均保持一致。`collect_followups.py --study preparation` 又重算全部逐组记录，
复核 73700 项源码/运行输入，并重新核对 native QBS QEMU 构建身份。这里的
QEMU 用于功能与实际路由，不报告硬件周期。

正式回执：验证树 `verification/out/e2e_preparation_census_audit_20261106_01/`，
状态为 `PREPARATION_CENSUS_REAUDITED`。

## 2. 实际统计结果

两种 Attention 选择的准备路由完全相同。下表按一种选择统计，不把相同工作
重复相加成更多模型覆盖。

| 项目 | 次数 | 准确含义 |
| --- | ---: | --- |
| prepared buffer 记录 | 844 | 实际完成准备后的缓冲记录，不等于所有投影调用 |
| 完整 M4 组 | 3860 | 每组包含四个真实输入行 |
| 字节缓存命中 | 1328 | 原始输入快照及身份检查成功后，复制已有 packed 数据 |
| 进入缓存但未命中，执行 RVV 准备 | 880 | 不是 RTL cache miss，也不一定本来可以复用 |
| 直接执行 RVV 准备 | 1652 | 包括不适用图策略的输入和超过组号上限的输入 |
| 第九组及之后的直接准备 | 772 | `group>=8`，并非全部都是冗余计算 |
| 重复 prepared buffer | 166 | 完整量化结果与此前记录相同 |
| 重复 buffer 中的直接准备组 | 332 | 潜在待复用对象；不自动等于原始 FP32 字节相同 |

有两个不同的命中率：

- 在实际查询缓存的 2208 组中，命中 `1328/2208=60.1449%`。
- 在全部 3860 个完整 M4 组中，命中 `1328/3860=34.4041%`。

它们的分母不同，不能互换，也都不是省周期比例。没有进入该 M4 软件缓存的
Decode M1 路径，仍可能使用已有的硬件 activation context；不能由此推断
Decode 完全没有激活复用。

## 3. 剩余重复来自哪里

| Prefill 输入类别 | 全部 M4 组 | 命中 | 缓存未命中后准备 | 直接准备 | 重复 buffer 中的直接组 |
| --- | ---: | ---: | ---: | ---: | ---: |
| Q/K/V 共用的 `attn_norm` | 1680 | 896 | 448 | 336 | 224 |
| gate/up 共用的 `ffn_norm` | 1080 | 432 | 432 | 216 | 108 |
| Wo 的 Attention 输出 | 560 | 0 | 0 | 560 | 0 |
| down 的 `ffn_swiglu` | 540 | 0 | 0 | 540 | 0 |

前两行确实存在组号上限造成的未复用候选。后两行主要是单消费者输入，不应
通过扩大缓存就假定可以命中。已经完成的准备复用也不能再次包装为新增收益。

按每组真实 K 加权，实际重新量化涉及 29589504 个输入元素；332 个重复候选
组对应 2719744 个输入元素，约 9.1916%。这只表示候选工作规模：仍需证明原始
输入一致、生命周期安全，并计入比较/复制及容量成本。它不是 9.19% 的准备
周期，更不是 9.19% 的模型时间。

## 4. 对优化选择的约束

不因命中率低于 100% 就优先扩大缓存或增加量化硬件。应将本统计与全 N 的
真实准备摊销、FFN 长 K 和 Decode 权重供给测量合并判断。N128 切片中的准备
高占比不能直接推广到完整投影；同样，当前数据也不排除更长 prompt 或不同
batch 下准备复用成为更重要的瓶颈。

后续若优化准备路径，必须保留 exact-byte、producer、frm/vstart、图 epoch、
可能写入的别名范围以及 source 生命周期检查。不能只凭地址相同或量化结果
相同就把新输入当作可复用。当前结论优先支持把主要硬件测量补齐到 FFN、
词表输出和 Decode 数据供给，而不是立即增加准备缓存容量。
