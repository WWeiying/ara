# 现有 AKV 资源的完整调用优化计划

## 出发点

[当前 profiling](INFERENCE_CHAIN_PROFILE_CURRENT_20261107.md)已经说明：在真实
Qwen3 D128/GQA2/137-token F16 切片上，generic QK/PV 占插桩完整调用的
61.64%。同一 KV 被两个 query head 分别重放；RTL 已支持 PANEL4，SDK 已有
配对 head 实现。本轮先验证这些现有能力，不增加硬件资源。

## 实施顺序

| 阶段 | 工作 | 完成标准 |
|---|---|---|
| 固定版本与完整 A/B | 同一 VCS 镜像、真实原始输入和同一 ELF，generic/paired/paired/generic | 完整数值、CSR、输入/guard、native 工作量、独立协议及身份检查通过；得到四次完整调用周期 |
| 适用边界 | 奇数 head 末尾回退、D64/D96/D128、短尾块/跨 tile、原六头专用路径 | 当前镜像代表性回归通过，host capability/type/shape 拒绝测试通过，不用旧 RTL PASS 替代 |
| 运行时选择 | 根据实测决定是否将合格路径纳入主要 GGML 执行 | 选择发生在 FULL 之前，调用局部、不修改全局环境；能力不足或不匹配仍走原路径 |
| 交付 | 记录证据、完整调用收益和明确支持范围，按节点提交 | 可复现构建/运行入口、固定源码和数据、回归及运行时选路说明 |

## 判定收益

以同一 ELF 中未插桩完整调用为分母，不把 K-column 的条数缩减等同于加速比。
优先保留逐 head 的 K 维度/token 更新顺序、F16/F32 边界与 sticky flags。
有至少 5% 的周期下降、同臂重复波动明显小于收益、且第二个代表性形状也有
正向结果，才考虑提高默认选择程度。若未达到，则保留当前默认并记录原因。

基线每次 1046 条 AKV 命令；GQA2 配对/PANEL4 候选预期每次 237 条：
FULL1、REFILL2、K-panel96、V-row137、RELEASE1。数学工作量和外部 KV
payload 不变。检查器必须验证真实硬件签名，而不是接受程序自行声明选中了候选。

## 范围约束

- 在主线 `ara_dsa` 上工作，结果在唯一验证工作树的独立输出目录，不新建 worktree。
- 保留当前未提交的 SDK/llama 工作，首轮使用提交归档；不将 dirty 汇编暗中纳入交付。
- 保持普通 RVV、QBS、generic AKV、D128/GQA6 和运行时 fallback 正确。
- 每个 VCS 任务不超过三小时；确认实际执行后不做短间隔轮询。
- 不跑综合，不改 FPGA 位流，不扩计算阵列、SRAM、接口或队列。
- 未取得新的完整调用和正确性证据前，不改生产默认、不宣布板级或整模型收益。
