# 相邻分组边界调整的独立实验

原型位于 `verification/akv/quantized_kv/prefill/boundary_plan.h`，没有接入
生产入口。保持组数不变、每组最多八行、不重排行，只在相邻两组之间重新
分配行数。候选必须同时满足 V 解码、QK 命令和 panel 数不增加，且至少一项
减少。它不是估计周期的加权打分，不假定一条命令等于多少解码成本。

## 结果

`python3 -B -m unittest test_boundary_plan` 通过 GCC 和 Clang UBSan。
测试执行真实 C scheduler 的回调，核对成本模型与实际 callback 计数逐项
相符，同时验证有效 QK 工作量不变、常量算术结果正确。
160 个 causal 形状中 22 点至少一项计数改善，全部点三项计数均不增加。

| query/past/GQA | 固定分组 → 调整边界 |
|---|---|
| 2/16/5 | QK 命令 5→4，V 解码 36→35 |
| 4/16/3 | QK 命令 8→8，V 解码 39→38 |
| 4/16/5 | QK 命令 9→8，V 解码 58→57 |
| 4/16/7 | QK 命令 12→12，V 解码 77→74 |

这不是性能测试，算术数据是合成常量；尚未执行真实模型数据回放或 RTL
周期测量。为将旧扫描函数作为测试 helper 编译，给其原 main 增加显式
`return 0`，未改变扫描或原型调度行为。

## 为什么暂不安装

单次反向调整依赖尾部不足八行产生的空间。如果所有组均为八行，相邻
两组总长十六，边界没有移动空间。因此 query=8/16/40 的不少 GQA=5/7 点
依旧保留原分组成本，不能宣称之前发现的全部缺口已修复。

此外，当前成本构造遍历 KV tile，长上下文下规划开销可能大于节省，
不能因为 callback 数更少便默认启用。后续若推进，需要有界代价计算或
更简单的形状策略，并将规划成本计入完整调用 RTL 测量。已通过的 Qwen2.5、
Qwen3 和两种格式实验保持原实现，不受本原型影响。
