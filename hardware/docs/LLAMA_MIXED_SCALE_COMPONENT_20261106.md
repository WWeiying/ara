# 用小型混合精度通路减轻量化投影的浮点端口压力

## 1. 它解决哪一个已经确认的问题

QBS 的整数点积不是量化投影的全部计算。以 Q4_K 权重和 Q8_K 激活为例，
每次 K block 更新还要转换整数结果、计算两个 scale，并按规定顺序完成两次
FMA。当前两个 scale MUL 和两次 FMA 共用一个算术发射口。真实 Qwen3 四行
QKV 的测量已核对每条命令的浮点工作量，见
`LLAMA_PREFILL_ARITHMETIC_RESOURCE_STUDY_20261106.md`。

若继续提高整数点积吞吐，仅扩大整数阵列会暴露这个浮点端口限制。本候选先
验证一条低成本的独立 scale 通路：不复制完整 FPU，不改变 FMA 累积顺序，
利用权重 scale 来自 FP16、激活 scale 为 FP32 的实际数据精度。

本阶段只完成实验部件及真实输入准入分析，**尚未接入 QBS 调度器**。没有
新增指令，没有修改普通 RVV，没有进行综合，也没有新的模型性能或面积结果。

## 2. 为什么只需要 11×24 位有效数乘法

FP16 正规数的有效数有 11 位，FP32 有 24 位。一个 FP16 scale 精确展开成
FP32 后，低 13 位有效数字为零。因此相乘只需 35 位整数积，再进行规格化和
FP32 的 RNE 舍入；不必使用一般 FP32×FP32 的 48 位有效数积。

这里必须保留舍入和 NX 标志。它不同于既有的 FP16×FP16 helper：后者至多
22 位有效积，可以在 FP32 中精确表示，不需要 FP32 舍入。

核心文件：`hardware/src/vlsu/qbs/experimental/qbs_mixed_scale.sv`。

| 流水级 | 实际工作 |
| --- | --- |
| 第一级 | 保存 24×11 位有效数积、指数和、符号和 entry tag |
| 第二级 | 根据最高位选择 24 位有效数，计算 guard/sticky、RNE 增量与 NX |
| 第三级 | 处理舍入进位并形成 FP32 结果、NX 和原 tag |

允许每周期接受一个请求，返回延迟为三个寄存器阶段。数据寄存器不复位，
valid/reset/clear 管理其有效期；无效结果不能提交。

设两个 FP32 编码的有偏指数为 Ea、Ew，初始结果指数为
`B = Ea + Ew - 127`。核心仅接收正规 FP32 激活，以及精确展开的正规 FP16
权重，并要求 `1 <= B <= 252`。这个保守范围保证规格化和 RNE 进位后仍为
有限正规 FP32，因此本通路只需产生 NX；其他数值类别必须走原完整 FPU。

## 3. 真实权重的 FP16 次正规数不能忽略

真实数据核查发现，仅支持正规 FP16 不够：

| 已接受的真实测量区域 | 动态 scale MUL 数 | 正规 FP16 条件可接收 | 因权重 FP16 次正规而遗漏 |
| --- | ---: | ---: | ---: |
| 首个 Decode 的七类 N128 投影 | 13312 | 8184，61.4784% | 5128 |
| 四行、完整 N 的 Prefill QKV | 229376 | 196216，85.5434% | 33160 |

这些是逐次 scale MUL 的数量，不是指令数、周期比例或整模型覆盖率。数据包括
Q4_K 的 d/dmin 两次乘法和 Q6_K 的 d 一次乘法；M4 激活按实际交错布局解析。
源文件、量化 payload 和权重字节均绑定到已接受的原实验构建。

为复用已验证的正常核心，新增
`hardware/src/vlsu/qbs/experimental/qbs_fp16_f32_scale.sv`。对于展开后的 FP16
次正规权重，FP32 指数处于 103--112；其 FP32 数值本身仍是正规数。将：

```text
权重 scale 的指数 +10      等价于精确乘 2^10
激活 scale 的指数 -10      等价于精确除 2^10
```

有效数字和符号不变，二者乘积也不变，因此可以复用同一个 24×11 位乘法核心，
不新增乘法器，不增加流水级。这是位级指数重编码，不是先执行两条浮点乘除。

只有重编码后两输入仍为正规数时才允许操作。对于满足原结果范围的 FP16
次正规权重，激活有偏指数至少为 16，减 10 不会成为次正规数；权重指数加 10
后处于 113--122。最终仍需通过核心的完整准入检查。

加入此条件后，上述两组真实数据分别为 13312/13312 和 229376/229376 可接收。
这只证明这些输入的数值准入，不证明整个模型或全部量化 profile 已完成性能验收。

## 4. 哪些情况仍交给原 FPU

- 零、NaN、Inf 或 FP32 次正规激活。
- 零或非有限权重，以及不满足有效数精度要求的权重。
- 可能产生 FP32 次正规、上溢或边界舍入结果的指数范围。
- 不符合该通路数据契约的其他输入。

原有 FP16×FP16 精确 helper 也不需要被替换。后续接入时应保留其原准入优先级，
混合通路只接管适用的 scale MUL，I2F 和最终 FMA 保持不变。

部件不是 profile 专用解码器：它只消费两个 scale 数值和 tag，不依赖模型、
矩阵尺寸或运行时名称。因此可以用于多个具有相同 scale 数值契约的 profile，
但不能仅凭这点称全部 profile 的调度和异常行为已验证。

## 5. 验证完成到哪一层

正常核心先与宿主 IEEE FP32 MUL 和原 FPnew RTL 同时对照。随后在不修改核心
的情况下，用扩展测试验证重编码 wrapper：

| 扩展部件检查 | 实测数量 |
| --- | ---: |
| 输入场景 | 112071 |
| 数值准入 | 80330 |
| 拒绝，保留原 FPU 路径 | 31741 |
| 完成结果/flags/tag 对照 | 80222 |
| reset/clear 取消的在途请求 | 108 |
| 新增真实 FP16 次正规编码 | 2046，含两种符号 |
| reset / clear 次数 | 28 / 82 |
| 最长连续逐周期发射 | 127 |
| 返回延迟 / 发射间隔 | 3 / 1 cycles |

80222 个完成请求的结果位、NX 和 tag 同时匹配宿主 oracle 和原 FPnew；取消
的 108 项不计作 RTL 数值比较通过。oracle 另覆盖 tie-even、tie-odd、舍入进位
及精确乘积。还有 131072 个指数/低位组合的准入重编码检查，以及全部有限
FP16 编码与标准 binary16 转换的对照。

## 6. 接入前必须完成的检查

1. 在 16-entry 调度表中为适用 scale 建独立发射口；不允许同一 entry 被两个口
   同时发射，非适用 scale 必须保留原 FPU 路径。
2. 原 FMA、I2F、混合 scale 可同时完成不同 entry；一次性 OR 所有 flags。
3. 用返回 tag 选择 entry 和旧累积值，保持 activation scale 到最后一次 MUL
   完成前仍有效；不错误使用同时返回的原 FPU tag。
4. 核查新增累积值读口或寄存器的资源代价，不能只统计 24×11 乘法器。
5. 配对验证全部结果、操作数顺序、flags、失败恢复和默认关闭时的原周期。
6. 先测现有 dot 配置下的完整调用，再判断是否值得协同调整计算吞吐；不依据
   算术发射下界直接承诺模型收益。

此候选旨在为量化投影解除下一项吞吐限制。它没有取代对默认 F16 Attention、
Decode 权重供给和整模型剩余算子的分析，也不以“部件已通过”作为总目标完成。
