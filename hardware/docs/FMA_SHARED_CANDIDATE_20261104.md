## 组织方式

原版每个 64 位 lane 的 ADDMUL 分别实例化四个 FP16、两个 FP32 和一个
FP64 运算单元。候选复用现有 `fpnew_fma_multi`，组织为：

| 子通路 | 可执行格式 | 最大操作数宽度 |
|---|---|---:|
| 0 | FP16 / FP32 / FP64 | 64 bit |
| 1 | FP16 / FP32 | 32 bit |
| 2、3 | FP16 | 各 16 bit |

仍可在一条请求中并行计算四个 FP16、两个 FP32 或一个 FP64 元素。
不是将四个 FP16 元素串行交给一个乘法器。所有子通路目前采用五级分布式
流水，FP16/FP32 的短依赖链延迟相对原版可能增加，不能将持续吞吐不变等同于
应用性能不变。是否采用该组织必须由后续面积与性能比较决定。

## 为什么需要额外的同步逻辑

不同精度使用的子通路数量不同。如果只向参与计算的子通路发送 valid，
各流水的占用可能不同，背压时就可能将不同请求的部分结果拼在一起。
候选让四条流水携带相同的事务序列：不参与当前计算的子通路执行合法的
FP16 占位运算，但其结果和异常标志不参与输出。所有子通路原子接收、原子
退休，并检查 valid、ready、tag、输出格式的一致性。

掩码按元素宽度重新选取。输入掩码以 16 bit 为粒度：FP16 使用四位，
FP32 使用第 0、2 位，FP64 使用第 0 位。不能直接用第 0、1 位作为两个
FP32 元素的掩码，否则可能泄漏被屏蔽元素的异常标志或丢掉有效异常。

输入使用常量位置切片，避免为格式选择引入可变移位网络。输出按退休事务
携带的格式拼接，不使用当前输入格式。标量输出保留 NaN-boxing，未参与的
高位填一；标量输入的 boxing 信息按请求传递。

## SoC 集成与验收安排

`simd_fpnew` 在共享关闭时直接实例化原 `fpnew_top`；开启时只替换 ADDMUL
opgroup，保留原 DIVSQRT、CONV、NONCOMP 和同一层 round-robin 返回仲裁。
共享实现当前要求 64 bit lane、FP16/32/64 格式配置；其他格式配置仍使用默认
原版，不能声称共享实现已经支持 FP8/BF16。

VMFPU 的 `fpu_latency` 仅将 ADDMUL 的延迟更新为五周期，整数乘除、转换、
比较和浮点除法不变。延迟比较矩阵、切换门控和归约调度继续调用这一个函数，
不另建一套不一致的延迟常量。现有跨 opgroup 顺序限制保留。

最新冻结测试目录为 `shared_fma_soc_20261104_03`。该目录构建两套相同来源的
SoC 镜像，只有 `EnableSharedFma` 的取值不同；与已有验收快照核对基础 FPU
和算术依赖身份，未直接使用工作区中未经交付的其他依赖修改。
31 个程序各运行原版和共享版，共 62 次，最多六路并行。包括普通浮点加乘、
带符号乘加、widening、四类求和归约，以及转换、除法、开方、min/max、整数
旁路回归和六个真实 llama.cpp 微内核。每项必须有程序数值 PASS、正常 EOC、
四个 lane 的正确配置探针和完整 FPU 请求/返回记录。周期变化单独报告，不将
数值通过自动解释为性能通过。
