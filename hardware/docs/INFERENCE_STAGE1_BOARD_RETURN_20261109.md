## 探针扰动不能忽略，也不能误判为硬件退化

plain的Decode均值为33.2373485秒，即每步8.309337125秒。相比该均值：

- metadata增加0.5866765秒，约1.765%；
- timed在metadata之上再增加0.681861秒；
- timed合计增加1.2685375秒，约3.817%。

timed的节点内合计33.073149秒，未归因区间1.434392秒。大部分总差值在量级上
可由记录和时钟开销解释，但没有plain的逐节点时间，**不能证明额外耗时全部位于
节点外**，也不能直接减掉1.2685375秒来构造“修正后真值”。时钟读取、元数据写入
和缓存扰动均可能影响后续节点。当前只确认探针扰动，不是新发现的RTL性能回归。

Prefill扰动约-0.290%，满足原项目阈值。两阶段合计仅变化约+0.081%，是长Prefill
掩盖Decode开销的结果，不能用总时间通过来覆盖Decode未通过。

## 对后续方向的影响

1. **优先归因完整投影内部。** 区分fresh量化、prepared/context复用、SDK规划提交、
   权重供给、点积及结果回写。不把MUL_MAT的84%/87.5%直接称为QBS硬件busy占比。
2. **Prefill与Decode分开设计。** Prefill重点FFN多行投影的数据复用与计算节拍；
   Decode同时关注FFN和词表输出的权重流量、命令与结果组织，不改外部总线。
3. **QK/PV保留为有条件方向。** 本短上下文测得Attention仅约7%/5%；其局部提升
   不能替代主要投影瓶颈优化。长上下文比例可能不同，尚不能外推或永久放弃Attention。
4. **不立即增加新的Norm/激活专用单元。** Prefill中这些算子并非零成本，但在
   投影的内部瓶颈明确前，优先级不足以支撑新增资源。

以观测份额做说明性的Amdahl估算，假定各自整个节点区间快2倍且无新开销，
投影可对应约1.72倍Prefill、1.78倍Decode；Attention则约1.04倍/1.03倍。
这些是假设预算，不是预测，更不是已获得收益；真实硬件通常只能消除节点内一部分时间。

  先减少探针工作，不能原样增加Decode步数并期待扰动自动消失。
- 投影内部准备/供给/执行的划分尚未测得，不能据总占比直接定案第二项新机制。
- 本轮不自动启动板测、VCS或RTL修改；先使用已有原始记录完成重点路径的源码核对。

因此当前可接受的是：正确性、执行工作一致性，以及短上下文的主要优化对象排序。
尚不可接受的是：精确的Decode无探针算子份额，以及最终新机制的收益承诺。
