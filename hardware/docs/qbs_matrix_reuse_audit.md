# QBS 矩阵级复用：下一步的定量依据

## 1. 范围和复现

本次不改 RTL、不启动综合，不把静态流量当成性能。工具直接调用正式运行时的
`qbs_recommend_activation_storage`、`qbs_plan_create` 和 `qbs_plan_next`，
枚举实际命令，而不是重新写一套分块算法。

```sh
make -C software/qbs traffic-audit
software/qbs/build/qbs_planner_traffic
```

输出 CSV，160 个组合包括 Q4_K/Q8_0、M=1/4/8/16/32、四种 N/K 形状、
global/segmented R4、M4/adaptive 两种策略。每项检查输出边界、K 范围和 MAC
总数守恒；两组已手算的典型形状有固定期望值检查。`make check` 包含此检查。
前三种形状对应已有 Qwen2.5-1.5B 的投影维度，N37 用于尾块；M 是静态形状扫描，
不是新采集的模型激活，不声称已执行这些 Prefill 矩阵。每项是一份整矩阵计划，
使用 reference capability（VLEN=1024），不是 GGML 多线程切片后的命令统计。
边界与总量守恒不是逐区域无重复/无遗漏证明；planner 正确性仍依赖已有执行和
寻址回归，不能仅凭这个流量工具判定正确。

字段定义：

- `commands`：实际 planner 发出的命令数。
- `input_tiles`：输入 token 方向分块数。
- `weight_once_bytes`：有效权重编码只读一次的字节数，不含 R4 尾部填充。
- `weight_logical_bytes`：全部命令要求的有效权重 payload 总量。
- `activation_direct_bytes`：不使用驻留 context 时的激活 payload 总量；M8 布局
  按八行存储计数，与引擎的读取范围一致。
- `activation_operation_bytes`：若当前计划允许并启用单次算子 context，则只填充
  一次激活；否则等于 DIRECT。这不是跨算子复用，也不证明模型实际启用了该选项，
  且不包含片上 context replay 的内部流量。
- `macs`：M*N*K；仅数学工作量，不是执行周期或指令数。

这些字节不含 descriptor、激活量化输入/输出、CPU gather、输出写回、AXI 对齐
放大、cache line 填充和重试。缓存会改变实际 DDR 流量。该工具不能输出总线带宽、
利用率、加速比或能耗。自适应策略的选择也不等于 GGML 默认启用了 wide-M。

## 2. 已确认的复用矛盾

Q4_K，M32/N1536/K1536：

| 调度 | 命令数 | 权重逻辑读取 B | 激活 DIRECT 读取 B | 两者合计 B |
|---|---:|---:|---:|---:|
| M4/N32 | 384 | 10,616,832 | 2,691,072 | 13,307,904 |
| M8/N16 | 384 | 5,308,416 | 5,382,144 | 10,690,560 |

wide-M 已将权重重读减半，但每条命令最多提交 128 个结果，M 翻倍使 N 减半，
激活重复读取翻倍，命令总数没有减少。逻辑输入总量只下降约 19.67%，不是 50%。
单份权重为 1,327,104 B，M8 调度仍读取四遍。

这意味着不能把“支持 M16”当作自动翻倍收益。保持结果容量不变会继续缩小 N；
扩大结果容量又会影响部分和存储、结果提交及寄存器占用。必须同时检查两种输入的
复用、累加状态和异常边界，而不是只看权重读取减少。

Q8_0，M4/N1536/K8960：

| R4 布局 | 命令数 | 权重逻辑读取 B | 激活 DIRECT 读取 B |
|---|---:|---:|---:|
| global，split-K | 768 | 14,622,720 | 14,622,720 |
| segmented，256-block | 96 | 14,622,720 | 1,827,840 |

这是已实现 segmented R4 的作用，不能再次计作下一项创新。它恢复 N32 分块并
减少激活重读，但没有减少这组矩阵的权重读取，也未解决跨 M 块重读。

## 3. 下一项设计必须回答的问题

优先比较两个候选，而不是立即增加乘法器：

1. **扩大激活驻留适用范围**：多 token 激活在多个 N tile 之间重用，消除上表
   wide-M 增加的激活流量。当前 context 只有一个，最多 M1、16 个 Q8_K block。
   例如 M8/K1536 的整份 Q8_K 需要 14,016 B，不能声称现有 4,672 B 容量足够。
   可考虑按 K 分段驻留，但需要计入部分和读写及命令开销。
2. **权重小块跨 token 块驻留**：同一权重块服务更多 M 分组。若把 K 循环放到
   token 分组之外，需要同时保存更多输出部分和；若保留当前每命令完整 K 的顺序，
   又需要更大的权重驻留范围。单纯交换软件循环不能凭空得到硬件复用。

当前较有希望的是受容量约束的双输入复用调度，而不是固定扩大 M/N。先用当前
共享执行资源做结构评估，再决定是否扩展 descriptor 或增加有限的片上状态。

## 4. 最小判别实验与安全条件

下一次 VCS 采用真实模型输入中的同一连续矩阵区域，先在普通 K 比较 M4/M8 的中等规模点。
固定完整算术工作与输出检查，记录 command fire/terminal、weight/activation range
握手及字节、各阶段等待、部分和读写、提交阻塞；输出定时窗口与实际 DDR 请求分开。
另取一个自然 split-K 点，只比较 M4 下的 global/segmented R4：当前 planner 不允许
wide-M 与 split-K 组合，不能把退回 M4 的运行标为 M8。不用人为重复短输入冒充
长模型上下文。

可证伪假设是：跨命令重复递送处于关键路径，而非已被缓存或计算完全隐藏。
若减少逻辑读取不能降低等待与总周期，就不据此增加驻留硬件。已有 activation
lookahead 和权重双缓冲必须保留，不能把它们的既有收益重复归因。

任何新的驻留/累加机制要定义 owner、数据版本、释放、fault drain、提交原子性，
并保持标准 RVV fallback、数值顺序及已经验证的 GGML alias 屏障。本轮没有放宽
dispatcher 的全局空闲条件，也没有把未验证的异步并发接入正式路径。
