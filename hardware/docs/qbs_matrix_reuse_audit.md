# QBS 矩阵级复用：下一步的定量依据

## 1. 范围和复现

本次不改 RTL、不启动综合，不把静态流量当成性能。工具直接调用正式运行时的
`qbs_recommend_activation_storage`、`qbs_plan_create` 和 `qbs_plan_next`，
枚举实际命令，而不是重新写一套分块算法。

```sh
make -C software/qbs traffic-audit
software/qbs/build/qbs_planner_traffic
```

输出 CSV，160 个组合包括 Q4_K/Q8_0、M=1/4/8/16/32、四种 N/K 形状、
global/segmented R4、M4/adaptive 两种策略。每项检查输出边界、K 范围和 MAC
总数守恒；两组已手算的典型形状有固定期望值检查。`make check` 包含此检查。
前三种形状对应已有 Qwen2.5-1.5B 的投影维度，N37 用于尾块；M 是静态形状扫描，
不是新采集的模型激活，不声称已执行这些 Prefill 矩阵。每项是一份整矩阵计划，
使用 reference capability（VLEN=1024），不是 GGML 多线程切片后的命令统计。
边界与总量守恒不是逐区域无重复/无遗漏证明；planner 正确性仍依赖已有执行和
寻址回归，不能仅凭这个流量工具判定正确。

字段定义：

- `commands`：实际 planner 发出的命令数。
- `input_tiles`：输入 token 方向分块数。
- `weight_once_bytes`：有效权重编码只读一次的字节数，不含 R4 尾部填充。
- `weight_logical_bytes`：全部命令要求的有效权重 payload 总量。
- `activation_direct_bytes`：不使用驻留 context 时的激活 payload 总量；M8 布局
  按八行存储计数，与引擎的读取范围一致。
- `activation_operation_bytes`：若当前计划允许并启用单次算子 context，则只填充
  一次激活；否则等于 DIRECT。这不是跨算子复用，也不证明模型实际启用了该选项，
  且不包含片上 context replay 的内部流量。
- `macs`：M*N*K；仅数学工作量，不是执行周期或指令数。

这些字节不含 descriptor、激活量化输入/输出、CPU gather、输出写回、AXI 对齐
放大、cache line 填充和重试。缓存会改变实际 DDR 流量。该工具不能输出总线带宽、
利用率、加速比或能耗。自适应策略的选择也不等于 GGML 默认启用了 wide-M。

## 2. 已确认的复用矛盾

Q4_K，M32/N1536/K1536：

| 调度 | 命令数 | 权重逻辑读取 B | 激活 DIRECT 读取 B | 两者合计 B |
|---|---:|---:|---:|---:|
| M4/N32 | 384 | 10,616,832 | 2,691,072 | 13,307,904 |
| M8/N16 | 384 | 5,308,416 | 5,382,144 | 10,690,560 |

wide-M 已将权重重读减半，但每条命令最多提交 128 个结果，M 翻倍使 N 减半，
激活重复读取翻倍，命令总数没有减少。逻辑输入总量只下降约 19.67%，不是 50%。
单份权重为 1,327,104 B，M8 调度仍读取四遍。

这意味着不能把“支持 M16”当作自动翻倍收益。保持结果容量不变会继续缩小 N；
扩大结果容量又会影响部分和存储、结果提交及寄存器占用。必须同时检查两种输入的
复用、累加状态和异常边界，而不是只看权重读取减少。

Q8_0，M4/N1536/K8960：

| R4 布局 | 命令数 | 权重逻辑读取 B | 激活 DIRECT 读取 B |
|---|---:|---:|---:|
| global，split-K | 768 | 14,622,720 | 14,622,720 |
| segmented，256-block | 96 | 14,622,720 | 1,827,840 |

这是已实现 segmented R4 的作用，不能再次计作下一项创新。它恢复 N32 分块并
减少激活重读，但没有减少这组矩阵的权重读取，也未解决跨 M 块重读。

## 3. 下一项设计必须回答的问题

优先比较两个候选，而不是立即增加乘法器：

1. **扩大激活驻留适用范围**：多 token 激活在多个 N tile 之间重用，消除上表
   wide-M 增加的激活流量。本轮初始基线 context 只有一个，最多 M1、16 个 Q8_K block；
   后续容量受限扩展见 `qbs_activation_tile_context.md`，不能将该基线限制当作扩展后的限制。
   例如 M8/K1536 的整份 Q8_K 需要 14,016 B，不能声称现有 4,672 B 容量足够。
   可考虑按 K 分段驻留，但需要计入部分和读写及命令开销。
2. **权重小块跨 token 块驻留**：同一权重块服务更多 M 分组。若把 K 循环放到
   token 分组之外，需要同时保存更多输出部分和；若保留当前每命令完整 K 的顺序，
   又需要更大的权重驻留范围。单纯交换软件循环不能凭空得到硬件复用。

当前较有希望的是受容量约束的双输入复用调度，而不是固定扩大 M/N。先用当前
共享执行资源做结构评估，再决定是否扩展 descriptor 或增加有限的片上状态。

## 4. 最小判别实验与安全条件

下一次 VCS 采用真实模型输入中的同一连续矩阵区域，先在普通 K 比较 M4/M8 的中等规模点。
固定完整算术工作与输出检查，记录 command fire/terminal、weight/activation range
握手及字节、各阶段等待、部分和读写、提交阻塞；输出定时窗口与实际 DDR 请求分开。
另取一个自然 split-K 点，只比较 M4 下的 global/segmented R4：当前 planner 不允许
wide-M 与 split-K 组合，不能把退回 M4 的运行标为 M8。不用人为重复短输入冒充
长模型上下文。

可证伪假设是：跨命令重复递送处于关键路径，而非已被缓存或计算完全隐藏。
若减少逻辑读取不能降低等待与总周期，就不据此增加驻留硬件。已有 activation
lookahead 和权重双缓冲必须保留，不能把它们的既有收益重复归因。

任何新的驻留/累加机制要定义 owner、数据版本、释放、fault drain、提交原子性，
并保持标准 RVV fallback、数值顺序及已经验证的 GGML alias 屏障。本轮没有放宽
dispatcher 的全局空闲条件，也没有把未验证的异步并发接入正式路径。

## 5. 同一输出区域的 VCS 配对结果

2026-10-23 的正式配对以 Qwen2.5-1.5B 的 Prefill `attn_q` Q4_K 和
`ffn_down` Q6_K 捕获张量为输入，各取真实的前 8 个 token、前 32 个输出通道，
保持完整 K。每个区域分别执行两个 M4/N32 命令或两个 M8/N16 命令；不是比较
两个只有 MAC 数量相等、实际输出区域不同的命令。

新构建的 VCS 引擎通过全部 8 条命令。每个 profile 的 256 个输出逐位一致，
合并 fflags 均为 1。测试台逐项核对结果、fflags、有效乘积数、dot 周期、FP
微操作、累加更新和读流量。生成器还对真实模型输出执行原有误差检查，没有放宽
容差。源代码、捕获数据、向量、镜像及动态库均冻结并核验哈希。

| 完整区域 | M4 两命令周期 | M8 两命令周期 | M8 周期增加 | M4/M8 payload B |
|---|---:|---:|---:|---:|
| Q4_K，M8/N32/K1536 | 13,850 | 15,456 | 11.60% | 69,344 / 55,712 |
| Q6_K，M8/N32/K8960 | 80,078 | 90,152 | 12.58% | 552,192 / 398,752 |

这里 payload 是独立引擎测试台实际接收的逻辑数据，包含每条命令的 16 B descriptor，
不是板上 DDR 事务统计。没有 CPU 量化、GGML 调度、cache、DDR 延迟及 RVV 共存开销。

### 5.1 周期差异的严格归因

| 两命令合计，M8 减 M4 | Q4_K | Q6_K |
|---|---:|---:|
| activation phase | +1,666 | +10,482 |
| weight phase | -60 | -408 |
| compute + overlap phase | 0 | 0 |
| 其余 phase | 0 | 0 |
| 总周期 | +1,606 | +10,074 |

`compute` 与 `overlap` 不是两个可以独立消除的执行工作量；overlap 表示该计算
状态同时有 reader 活动。M8 的 compute 增加恰好抵消 overlap 减少，所以不能
把它解释为乘法或浮点算术增加。两种调度的 dot、FP issue、cast/half-scale
issue 数量也相同。改变的是供给与计算重叠的时机。

这与 RTL 相符：M4 DIRECT 可把下一 K block 装入空闲 activation bank，M8
两 bank 都保留当前 K 的四行 context，直到最后一个输出 row group 消费完毕。
M8 每个 K 边界重新加载激活。最后一个 row group 之前不能提前覆盖任一 bank。

### 5.2 算术吞吐上限约束设计选择

`qbs_dot_array.sv` 明确保留 4x8 个乘积槽。M1、M2 和 M4 只是分配这些槽的方式
不同，M8 则执行两个四行 wave。无填充浪费的配对点至少需要 `M*N*K/32` 个整数
发射周期，分别是 12,288 与 71,680。当前 M4 的整数发射周期占比为 88.72% 和
89.51%。这是指令窗口内的发射周期比例，不是芯片所有计算单元的利用率。

即使假设所有其他周期都免费，保持 32 个乘积槽的命令级最大加速上界也只有
约 1.127x 和 1.117x；实际还必须保留 FP、启动、排空与提交。因此：

- 不能仅凭 M8 少读权重，就承诺它在理想供给下明显快于 M4。
- 给 M8 增加双缓冲可能主要是追平既有 M4，而不是获得新的大幅提升。
- “权重复用更多”和“实际吞吐更高”必须分别核验；不能把省流量直接写成加速。
- 若真实系统供给更慢，较少的 payload 仍可能有价值，需要测出选择条件。

首轮入口为 `verification/qbs/run_matrix_reuse_pair.py`，原始结果在
`verification/out/qbs-matrix-reuse-pair-20261023-01/`，摘要归档于
`verification/qbs/results/matrix-reuse-pair-20261023.json`。

后续 `verification/qbs/replay_matrix_reuse_pair.py` 复用上述已冻结镜像与所有输入，
仅通过既有 `QBS_RESPONSE_GAP` 测试台选项，在每次 R 握手后插入 2 或 4 个空闲
周期。两个点用于区分计算上限与供给瓶颈，不是为了找到最漂亮的参数，也不代表

这一实验尚不能证明应增加第三 bank、跨命令驻留或放宽 dispatcher idle 门槛。
只有确认目标供给条件下的数据复用收益，再结合完整投影的量化/搬运成本，才选择
后续 RTL 改动。原有正确性与异常原子性不因性能筛选而放宽。

## 6. 设计筛选：为什么暂不增加第三 activation bank

三 bank 的滚动方案在技术上可以研究，但不是免费调整。现有 M8 payload 把八个
context 的 quants 逐元素交错，scale 和 bsums 也有独立的交错规则；下一 block 的
一个 128-bit beat 常常同时更新两个逻辑半块。一个空闲 bank 并不能接收完整的
next-K range。若新增 two-M4-half layout，还要增加 ABI/capability、打包器、读范围
和 bank 归属控制，并回归 M5..7 尾块、fault drain 与版本恢复。

仅用两 bank，在最后一个 row group 的 wave0 后退休 bank0，最多得到 wave1 的
重叠窗口。Q8_K 四行半块为 1168 B，即 73 个 beat。gap2/4 在握手后分别空闲
2/4 周期，持续传输口径约需 219/365 周期，已经超过一个四行 wave 的 128 个
整数发射周期；还没有计入请求和末拍等开销。因此不能承诺只改 bank 退休时间
就能隐藏受限供给下的全部 activation 成本。

更大的方向仍是矩阵级双输入复用。现有两条 M8/N16 命令会重复读取整份 M8 激活；
让它跨 N 驻留可减少真实输入需求，而提前加载只改变时间。这也有明确的容量代价：
Q4_K 的 M8/K1536 激活为 14,016 B，Q6_K 的 M8/K8960 为 81,760 B，都超过现有
4,672 B context 有效容量。不能借用一个 DIRECT 命令去覆盖尚有效的 M1 context，
因为其软件契约明确规定 DIRECT 不改变已提交 context。

下一项结构评估须把三种资源一并计入：

1. 一个 K 条带中驻留的多行激活；
2. 在该条带上复用的权重块；
3. 条带之间保持同一数值顺序所需的输出部分和。

选择 K 条带可限制激活容量，却不能把输出部分和当作免费状态。当前 qbexec 在
命令开始清空 accumulator、完整完成后提交；跨命令保留部分和需要新生命周期
契约，软件 spill/reload 则必须核算流量、精确舍入与异常可见性。实现前要选择其中
一种并给出固定容量上限，不以增加 M、静默更换累加顺序或无限扩大 SRAM 代替设计。

目前保留 M4 默认、M8 显式选择及原有 fallback。上述分析不是取消第一优先级，
而是拒绝只为追平 M4 引入新 bank，并把其实施目标收敛到实际减少跨 tile 数据需求。

## 7. 受限供给的实测结果与实施门槛

上述 gap2/4 的 16 条命令全部通过，结束后再次核验 355 个源码/镜像/输入/日志
哈希不变。连同 gap0，共有 24 次 VCS 命令执行。每次使用同一冻结 reference，
逐位结果、fflags、MAC 工作、dot/FP issue、读字节和范围均通过检查。

| R 握手后的空闲周期 | Profile | M4 两命令周期 | M8 两命令周期 | M8 相对 M4 加速比 |
|---:|---|---:|---:|---:|
| 0 | Q4_K | 13,850 | 15,456 | 0.896x |
| 0 | Q6_K | 80,078 | 90,152 | 0.888x |
| 2 | Q4_K | 16,912 | 19,800 | 0.854x |
| 2 | Q6_K | 116,904 | 117,872 | 0.992x |
| 4 | Q4_K | 23,852 | 24,144 | 0.988x |
| 4 | Q6_K | 185,500 | 145,592 | 1.274x |

gap4 的 Q6_K 周期下降 21.51%，不是下降 27.4%；后者是吞吐加速比例。其两命令
weight phase 减少 90,414 周期，同时 activation phase 增加 50,506 周期，净少
39,908 周期。Q4_K 的 weight phase 虽减少 7,758 周期，activation phase 却多
8,050 周期，净多 292 周期。两个 profile 的 compute+overlap 合计仍不变。

这说明两个输入方向必须一起优化。当前 M8 权重复用已在 Q6_K 受限供给下形成
真实周期收益，但激活重复读取及串行加载抵消了一部分；Q4_K 更容易被这个代价
抵消。不能仅按压缩位数或逻辑字节减少比例选 M8，也不能由这两个受控 gap 宣称
真实 DDR 或整模型收益。现有 M8 默认关闭的选择不因本轮实验而改变。

后续实施目标是有界的跨 N 多行激活复用，同时保留跨 M 权重复用。比较方案必须
覆盖以下项目，不能只观察单条命令 activation phase：

- 完整等输出区域的权重、激活、部分和读写及命令数；
- 理想与受限供给下的周期、真实数学工作和相同输出检查；
- 最大 context/部分和容量、占用时间、所有权与失败后的恢复；
- M1/M4 原路径以及普通 RVV 不退化；
- 完整投影的量化准备和所有 N tiles 的摊销，而非只测一个 N32 切片。

跨 N 驻留若需要跨命令部分和，必须先定义 start/update/finish 的数据版本与提交
边界，不能偷偷复用上一条命令的 accumulator；若保持现有命令语义而增加存储，
则必须证明增加的容量能覆盖代表模型的实际形状。两种设计不能混写成已经具备。

本次独立 reviewer 对 replay helper 未发现阻断问题。后继测试台宜回显实际生效
的 response gap 并让 checker 核对；当前证据由冻结测试台、实际启动命令和其
确定的 plusarg 解析路径建立，不修改正在运行的 helper 来补写日志。

## 8. 实施顺序与研究依据

### 8.1 不是在点积和 GEMM 之间二选一

QBS 已将同一量化权重微块用于多行激活，并保存命令内部的输出部分和。因此它不是
逐输出调用一次 scalar dot 的实现，也不是完整的通用矩阵处理器。现阶段的限制是
复用范围、命令边界和供给方式，而不是软件是否将算子命名为 GEMM。

令 X 为 M×K 激活、W 为 N×K 权重，Y=XWᵀ。单请求 Decode 通常 M=1；增加
输出 N 不能制造不同 token 之间的权重复用。Prefill 或批量 Decode 才能沿 M 重用
同一份权重。无填充时，32 个乘积槽给出 MNK/32 个整数发射周期的下界；有限阵列
的矩阵数据流主要减少供给等待，不会自动越过这个算术下界。

| 对照工作 | 值得吸收的具体组织方式 | 本项目不能直接照搬的部分 |
| --- | --- | --- |
| SpacemiT GGML IME 路径 | 激活量化、权重 repack 与多行矩阵 kernel 成套选择 | 不同 IME 算术资源和 ISA 的吞吐不能当作当前 QBS 的能力 |
| MARLIN | 压缩权重布局、异步搬运与计算流水共同优化，覆盖小到中等 batch | GPU Tensor Core、缓存与并发线程资源不同，不能移植其加速倍数 |
| Gemmini | 分开管理输入 scratchpad 与输出 accumulator，定义数据流和依赖 | 不能只加一个矩阵阵列而忽略存储、翻译和精确异常代价 |
| FlashAttention | 按 tile 消费 K/V，保留 online softmax 和输出状态，减少中间矩阵外存往返 | 当前 AKV 已有分块与 online 路径，不能将其重复描述为未实现功能 |
| KIVI | K/V 的统计性质与量化轴不同，压缩 KV 能减少长上下文流量 | 其量化格式不等于 GGML 的 Q8_0/Q4_0，数值质量和布局必须独立验证 |

### 8.2 四项优先级与验收边界

| 顺序 | 工作 | 当前已具备 | 仍须完成的关键验收 |
| --- | --- | --- | --- |
| 1 | QBS 矩阵级双输入复用 | M4/M8、权重双缓冲、容量受限的多行 activation context | 完整 N 输出区域总成本；长 K 的条带驻留与部分和生命周期；正式 GGML 选择 |
| 2 | 激活准备复用与流水 | 部分跨算子量化复用及显式 context 所有权 | 量化、打包、首次 FILL、后续 REUSE 的完整摊销；可安全重叠的边界 |
| 3 | AKV fill/replay 与 RVV 计算协同 | token-axis view、GQA 分组、Prefill 分块 | 区分 SRAM replay、VRF 写入、QK/PV 算术、softmax 与 idle 屏障；缩短已证明的关键等待 |
| 4 | 量化 KV 的正式快速路径 | 独立探索路径不等于正式 backend 已闭环 | 先接 GGML 常用格式，再核对增量写入、尾块、数值质量与真实模型 dispatch |

第 1 项当前先测 Q8_0 的完整 N896/K896、M4 投影，因为 3808 B 激活能装入
现有 4672 B context，不需要先增加 SRAM。选择两组不同的真实输入，每组的
28 个 N32 tile 使用不同的捕获权重和对应 golden。首次命令必须 FILL，最后一次
必须 RELEASE；不能把所有命令都按稳态 REUSE 的周期计算。

`verification/qbs/run_context_projection.py` 新建 VCS 镜像并配对每个输出 tile。
它核对结果/fflags、计算工作、读流量和生命周期，读取前后核验源码与输入哈希。
DIRECT 和 context 命令交错用于数值和状态对照，周期采用各命令 busy 周期之和；
这不是模拟 CPU 连续派发的墙钟时间，也不包含激活量化和打包。独立 native app
需另测准备开销和整体区间。gap0/4 是受控供给条件，不是 DDR 的校准模型。

### 8.3 长 K 条带不能省略的状态

若后续将 K 分为多条带，在每条带内复用激活于多个 N tile，原来的 128 个
accumulator 无法同时保存任意多个 tile 的部分和。必须明确以下两种方法之一：

1. 显式保存、恢复有限数量的 FP32 部分和，并逐项保持原 K block 顺序；
2. 一次命令拥有有限的更大结果 tile，直到全部 K block 完成才提交。

当前 `qbs_compute_engine` 启动命令会清空 accumulator；`qbs_fp_accumulator`
的 first-block 标志决定新输出初始化，fflags 也按命令清除。因此不能只阻止
数据清零便宣称支持跨命令续算。还需要绑定输出 tile、权重/激活版本、K 游标、
累积异常标志和提交状态。中途访存错误应使未提交部分和失效，或支持有定义的精确
恢复，不能把已累加条带在重试时再加一次。

仅为说明容量代价：M8/N64 的一份 FP32 部分和是 2048 B。其是否需要额外备份、
读写端口及标签由异常方案决定，不能将 2048 B 当作最终新增资源。用软件把两个
完整 dot 结果相加通常会改变舍入顺序，不可冒充位级等价的部分和保存/恢复。

实现门槛仍是完整输出区域、同一输入、相同数值契约下的实际收益。减少流量但
计算已饱和的形状可以保留 DIRECT/M4；不能为了让新机制普遍启用而让既有路径变慢。
