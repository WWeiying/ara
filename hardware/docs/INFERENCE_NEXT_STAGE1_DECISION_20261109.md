## 3. 对瓶颈的结构判断

### 3.1 线性投影：先区分准备、供给和计算

当前 Q6_K/M1/R4 的840 B权重，在128-bit接口上至少需要53个握手周期；
点积发射只需32周期。实测严格等待权重的周期中89.27%仍有数据接收。
因此不能仅增大乘法吞吐就承诺消除这一等待，也不能不改变数据量就把带宽上界消掉。
本计划不改外部总线；只考察有效复用、消除重复读、内部衔接及控制开销。

真实数据 N64切片中的量化准备占41.14%，但不能外推到完整模型：准备约为
O(MK)，投影约为O(NMK)，全 N更大，而且同源Q/K/V及gate/up已有准备复用。
当前基线必须启用已交付的 packed、parallel sums、prepared cache和上下文复用，
不能重复领取旧generic实现到优化软件的收益。

### 3.2 Attention：驻留计算有价值，但不是直接接上一个 MAC 就结束

PV已有共享FPU和局部累加存储，QK尚未完成同等路径。候选是在同一套资源上
增加QK模式，减少循环内的操作数递送与中间结果往返。QK/PV顺序执行，
不添加第二套累加数组或第二套FPU，不承诺两者同时计算。

第一轮保留原来的 score、scale/mask、softmax、PV及最终归一化边界。
当前在线softmax包含跨tile重缩放和FP64求和；不能把这些当成无关开销直接删去。
“其余调用”区间也不全是softmax，必须通过节点/函数分解进一步确认。

## 4. 候选方案及准入条件

| 候选 | 可复用部分 | 新增或修改 | 决策 |
|---|---|---|---|
| 共享FPU驻留QK/PV | 每lane16个64-bit累加槽，共512 B；现有FPU、K列缓存和握手链路 | QK模式、FP32格式、Q块选择、尾部有效lane和结果写回 | 第一候选；先修PV边界，再完成QK |
| 激活量化结果直填QBS context | RVV归约/量化计算、现有4672 B context | 受控写入生产者、所有权和commit/abort协议 | 有条件候选；先测完整同源投影链准备占比 |
| Attention中间结果衔接 | 当前scale/mask/softmax和QK/PV存储 | 需先明确哪些往返可省，保持重缩放和数值顺序 | 有条件候选；不首轮隐藏整个Attention状态 |
| QBS tile handoff | 双bank、lookahead、双correction context | 细化输入捕获、dot入账、结果释放时点 | 保留小优化，不当作主要新机制 |
| long-K continuation | 既有分段及上下文接口 | 重复提交、seed和恢复顺序需重新设计 | 已有负收益，暂不启用 |

QK具体设计见 [共享QK计划](../../verification/performance/resident_rvv/qk_shared/PLAN.md)：
两头16维Q块共64 B，候选复用reader现有2×256-bit存储，不能再另建同容量数组；
Q响应全部捕获后才启动K列收集，不放宽现有端口冲突断言。FP32元素掩码、
NaN/NV、T尾部和Q行选择必须显式验证，不能直接照搬FP16 PV控制。

量化结果直填不等于量化计算加速。若保留原RVV量化计算，只增加context写入口，
可省的是量化结果落内存及context重读，不能把归约、scale、转换和分组和耗时
都计为收益。要加速这些计算，需要另行设计执行控制与接口，不能算作只增加写入口。

量化直填的硬限制来自现有接口，而非软件命名：Q8_K先确定块scale后才能量化，
必须暂存或重读256个F32；M4与M1的舍入/平局规则不同。Q8_0还要保留FP16 scale契约。
现有context最多32块/4672 B：Q8_K M1最多K4096，M4最多K1024；Q8_0整context
也受32块限制。fill_begin会使旧context失效，abort不恢复旧token，fill/replay不能
凭空并发。阶段3不得以新增双缓冲或更大容量替代对这些问题的论证。

## 5. 缺测的最小实验，而不是再跑大规模盲测

采用冻结 unified 软件构建独立探针 ELF，不使用当前脏SDK/汇编。首轮保留相同
135-token真实prompt，并先用4到8次固定历史Decode完成工具验收；正式测量长度
根据逐步稳定性决定，不能据短上下文推出长上下文收益。

计时方式：在GGML CPU原执行循环包住整个fuse/forward分支，用CLOCK_MONOTONIC
纳秒计时，不添加fence，不用callback_eval拆图。单worker在内存累计，完整
llama_decode及已有synchronize返回后输出；不在每节点/每graph中串口打印。
融合节点作为一个区间，不能虚构其中各算子的独立时间。

必须分层报告：

1. 模型加载、context创建、Prefill、逐步Decode、结果导出。
2. 投影各类、Attention、Norm、RoPE、激活/逐元素、copy及其余节点。
3. 投影内部准备/缓存命中/SDK提交等若单独测量，是第2层的子区间，不能重复相加。
4. 节点时间和完整调用差值保留为未归因项，包含调度及探针开销，不能全称为软件浪费。

同ELF运行探针OFF/ON，对照全部logits、token、节点融合跨度、QBS/AKV工作量。
ON/OFF完整时间扰动目标不超过2%；超过则降低记录成本或仅分层采样，不凭经验
减去固定探针开销。该2%是本项目测量验收阈值，不是行业标准。无fence节点区间
只表示CPU执行跨度，不单独证明异步硬件已经完成；最终drain纳入完整调用。
不得为了计时改变板卡内核用户计数器权限，也不以QEMU时间替代板卡/RTL周期。

板卡由另一个会话占用时，只准备冻结程序、命令和核对清单，不争用UART或重启板卡。

## 6. 收益判断与停止条件

候选覆盖当前完整调用的比例为f，局部加速为s，新控制成本占原完整调用h时：

```text
S_complete = 1 / ((1-f) + f/s + h)
```

其中f必须是可被该候选消除的、符合准入条件的实测区间，不是所有同类节点时间。
对量化结果直填，f仅包含可省去的存储和重读部分；无fence CPU区间若含异步重叠，
在独立周期证据拆清之前只能用于乐观上界，不能当作严格可加和的服务时间。
即使局部无限快，f小于4.7619%也达不到完整调用1.05倍；若局部只能快2倍，
f至少需要9.5238%，尚未计入新增控制成本。因此准备直填必须先通过完整QKV链
预算，不能用N64的41%启动大量硬件工作。

第一轮实现推进目标是代表完整调用至少1.05倍，且收益超过对照波动；这是选择
投入方向的门槛，不是对实际收益的承诺。若该类调用累计占模型时间p，
模型加速比应为 `S_model = 1 / (1-p+p/S_call+h_model)`，而非调用倍率乘阶段占比。
p是这些调用的实际累计份额，h_model是新增开销占原模型时间的比例；仅时间下降
比例可按份额加权。局部通过、模型占比低时，可以保留实验但不强制默认开启。

普通RVV、fallback、数值契约、异常及恢复不允许为性能让步。资源评估先列新增
存储字节、端口、算术单元和控制状态；本阶段无综合，不报告虚构面积/时序结果。
