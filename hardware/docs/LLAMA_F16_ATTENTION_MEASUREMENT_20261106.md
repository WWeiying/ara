# 默认 F16 KV 路径的真实输入与阶段测量

## 1. 本节点要回答的问题

完整 llama.cpp 推理的优化不能只依据某个量化 KV 内核。当前已有的完整 Qwen3
板测对照采用 F16 K/V；量化 KV 的 Output-Tile 不在这些调用中执行。因此，本
节点补齐实际 F16 Attention 的输入和有界原生测量，确定后续应该投入算术、
KV 供给、片上存储，还是准备与调度通路。本节点不修改 RTL，也不进行综合、
功耗或 FPGA 测试。

## 2. 实际模型输入

使用固定的 Qwen3-1.7B Q4_K_M 权重与已封存的 host llama.cpp 二进制，在同一
次真实模型执行中捕获第一层 Prefill 和首次 Decode。K/V 明确配置为 F16；
没有从量化捕获反量化出一份 F16 数据，也没有把 Prefill 的最后一行称为 Decode。

| 张量 | Prefill | Decode | 类型 |
| --- | --- | --- | --- |
| Q | `[128,136,16,1]` | `[128,1,16,1]` | F32 |
| K/V | `[128,256,8,1]` | `[128,256,8,1]` | F16 |
| mask | `[256,136,1,1]` | `[256,1,1,1]` | F16 |
| 输出（合并 head 的视图） | `[2048,136,1,1]` | `[2048,1,1,1]` | F32 |
| 实际可见 KV | 第 i 个 query 看到 i+1 项 | 137 项 | 严格因果前缀 |

256 是已分配的 KV 容量，不是每个 query 都参与运算的长度。Prefill mask 的
有效前缀依次为 1 至 136；Decode 在原 prompt 和首个生成 token 后看到 137 项。
形状、stride、实际字节范围、有效数据的有限性及 0/-Inf mask 均经检查。

捕获目录：
`ara_dsa_signoff_integration/verification/out/e2e_qwen3_f16_attention_capture_20261106_01/`。
结果 SHA256：`d4ab9d3cd381a5e8831a7fe7cf9300f82cfc121d53f83868dfa4eab57dd1e985`。
这是 host 功能捕获，不是硬件性能数据，也不证明 native backend 已准入。

## 3. 控制仿真规模，但保留真实工作

原生测试取 KV head 0 及其对应的 Q head 0、1，保留 D128/GQA2：

| 区间 | 工作 | 每次调用输出 |
| --- | --- | ---: |
| Decode | 原始 query，全部 137 个可见 KV | 256 个 F32 |
| Prefill | 原始前 64 个 query，其可见 KV 为 1 至 64 | 16384 个 F32 |

Prefill 的 64 个 query 对应实际 native query block，不用 M4 切片代替运行时
M>=64 的准入条件。Q、K、V、mask 和 golden 均按原始 stride 提取原始字节。
为独立运行而物化为紧凑布局，保留 KV 容量 256 和 mask 行长；这不包含完整
GGML adapter 的布局检查、锁和全 head 调度时间，不能标为完整节点耗时。

Qwen3 源码以 `1.0f/sqrtf(float(n_embd_head))` 建立 scale。D128 对应的 F32
值为 `0x3db504f3`。捕获 JSON 仅打印有限位十进制，不能把其中 `0.0883883`
当成精确二进制参数；本节点绑定原始 graph 源码及 D128，而不是静默使用该
舍入后的文本数值。

## 4. 为什么 Prefill 和 Decode 不能共用一个参考顺序

host GGML 的这个 Prefill 路径使用 F32 输出累加；Decode 则把 Q 转成 F16，
并在逐 token 的输出递推中保留 F16 舍入。二者输入同为 F16 KV，并不意味着
中间精度和累加顺序相同。

数据映射检查分别使用独立标量参考：Prefill 使用高精度 dot、稳定 Softmax
和加权和；Decode 重建 F16 Q 转换、逐 token F16 输出舍入，以及 F32 的
Softmax 状态。固定门限均为 `2e-5 + 2e-5*abs(reference)`，不是失败后放宽。

| 映射检查 | 最大绝对误差 |
| --- | ---: |
| Prefill 原始 16384 个输出与独立参考 | 5.238983235567041e-7 |
| Decode 原始 256 个输出与独立 F16 递推参考 | 5.960464477539063e-8 |
| Decode 原始输出与不保留中间舍入的 F64 数学结果，仅作诊断 | 7.759972959636152e-4 |

首次导出把 F64 数学结果也用于 Decode 映射验收，因而失败。原目录
`e2e_qwen3_f16_native_data_20261106_01` 的 FAIL 保留；没有将其改判为 PASS。
后继 `_02` 使用与源码对应的独立参考并通过。该参考验证真实数据的映射和
数值来源，不是 native SDK 的逐位参考：SDK 的分块与输出递推仍要单独验收。

通过目录：`verification/out/e2e_qwen3_f16_native_data_20261106_02/`，结果 SHA256：
`0fb5797dfed0d5d6bfaaf1e7b611f110b9b0a625fa1b67977ba86ce7a9e3581a`。

## 5. 原生测量及验收方法

原始 SDK 与只插入观察语句的 SDK clone 采用相同 ELF、相同输入、相同编译
浮点选项及 ABBA 顺序。两侧均显式开启已有配对 head 和配对 PV 实现，不以
较弱的未配对实现放大后续收益。普通 SDK 的源文件与汇编内核不修改；探针
变换可逐项反演，恢复原来的计算语句。

完整区间包含 Decode 的 Q 转换和 plan 创建，使用相同的已完成状态 CSR
读取及 fence 边界。内部阶段区分 preflight、query、init、KV FULL/REFILL、
QK、Softmax、PV、release、normalize 和 schedule。Decode 的 query 准备发生在
外部 caller，因此另列 preparation，不会虚构为内部 QUERY。

有两点必须特别注意：

1. 内部前 11 个 phase 区间互斥；`barrier_subset` 与它们重叠，而且包含等待
   前序真实工作完成的时间，不能再加一遍，也不能作为纯探针开销减掉。
2. FULL/REFILL phase 是命令 issue/return 的观察区间，单凭一个 fence 不能
   宣称得到了独立 DMA 完成时间。必须结合实际 AKV 命令及读响应记录解释。

检查器核对每次调用的完整命令序列、tile 尾部、搬运字节、错误状态及最终
汇总。两阶段共 8 次调用，预计 17468 条 AKV 命令。目标程序检查全部 66560
个输出、原始/观察版本逐位一致、golden 门限、CSR、输入 Query 转换、尾部
和保护区。日志只输出逐 query 的结果指纹，不输出全部单独结果字，以免串口
打印主导仿真耗时；不能把这些指纹说成外部逐字 dump。

只有数值、CSR、命令记录及独立协议检查均通过，才接受原生结果。两组配对
完整调用的正、负时间扰动均不超过 5%，才允许使用精确阶段比例；否则保留
功能结果和原始记录，但不据此给出精确瓶颈占比。本测量不是新优化的加速比。
即使扰动门通过，phase 仍描述插桩调用的阶段窗口，不能宣称精确恢复了未
插桩执行的并发关系，更不是各功能单元的实际运算利用率。

原始编译已完成全部对象，但首次链接重复加入了主汇编已 include 的两份
paired 汇编；原 FAIL 保留。第一次保守的全 `.text` 拼接核对还发现了独立
对象尾部的两字节对齐填充，不能把它误当函数差异。最终后继工具
`complete_f16_native.py` 按符号大小逐一比较三个函数正文，核对无重定位、
正文逐字节相同，随后仅删除两个重复链接对象，零重编完成 ELF。

最终 build：`verification/out/e2e_qwen3_f16_phase_final_build_20261106_01/`。
build SHA256：`98976e2b4e7b9e3a9fcf6916dd902df29230d0b50581bed6296bd81e45dfb948`。
ELF SHA256：`8f03e4ce74a037a16fd07966734a8aee804144264b07da437f1847eec79e3e6d`。
通过 26 项 host tests；最终 ELF、数据符号和链接取舍已独立审查。构建通过
不等于 RTL 执行通过，后续结果由 `run_f16_native.py` 在独立目录收集。

## 6. 对后续结构选择的作用

如果 KV 搬运主导，应先比较读端口、驻留、布局和双缓冲；如果 QK/PV 主导，
再比较复用现有 RVV 算术与增加适量算术资源；如果准备或 Softmax 主导，先
核查具体的转换、规约、状态更新与软件串行部分，不能笼统称作 memory-bound。

这些结果还须与完整投影及其他算子的实际执行账目共同使用。它既不能由量化
KV 的局部结果替代，也不能反过来代替所有量化 KV、所有模型或长上下文测量。
本阶段以准备、调用边界和真实数据归因为重点，不把一项测试通过当作整个
端到端性能面积目标已经完成。
