# 完整推理优化：Attention 输出驻留候选

## 1. 它在总体目标中的位置

总体目标是以合理的面积增量改善端侧 llama.cpp 完整推理，而不是只压缩 QBS/AKV
的局部周期，也不是规定以后不能新增硬件。本轮先建立一个低成本对照候选：检查
Attention 的中间输出反复读写是否值得消除。它使用现有 RVV 寄存器和算术资源，
可以帮助后续判断究竟应增加计算吞吐、片上存储，还是改进算子之间的组织方式。

目前没有修改 RTL，没有启动综合，也没有替换生产 llama.cpp 后端。
该候选尚不能代表完整模型已经获得新的加速。

整体选型仍有三条路径：

| 主要瓶颈 | 应比较的方案 | 不能省略的检查 |
| --- | --- | --- |
| 投影的权重供给或矩阵复用 | 权重缓冲与预取、跨输入复用、适度专用计算 | 供给是否匹配吞吐，额外存储和准备开销是否抵消收益 |
| Attention 的中间数据搬运 | RVV 输出驻留、小型累加缓冲、QK/Softmax/PV 流水协同 | 保持数值递推，计入 KV 解码和完整调用成本 |
| 激活准备与命令控制 | 量化结果复用、批量提交、必要的硬件辅助 | 当前软件是否已实现，调用频率是否真的转化为显著周期占比 |

应以当前最佳有效软件为基线，避免把已解决的运行时开销再次算成硬件收益。
完整模型的阶段归因仍是主线，不能用本试验代替。

## 2. 原路径与候选路径

原 Register-PV 路径已避免把解码后的 V 整行写回内存。但是，每处理一个历史
token，仍要读取输出向量、必要时缩放、执行 FMA，再写回输出。

候选每次处理最多 32 个历史 token：

1. 保持原 QK 分组、描述符和回调顺序，获得该 tile 的 scores。
2. 按原 token 顺序递推最大值和 Softmax 分母，记录缩放系数与新值系数。
3. 每次取两个 query head、至多 128 个输出元素，在 RVV 寄存器中依次执行该
   tile 的所有输出更新，最后写回。
4. 所有 tile 完成后，沿原路径执行最终归一化。

改变的是不同递推之间的交错方式，不是每个输出元素的乘法/FMA 顺序。
不能把在线 Softmax 换成一次普通规约后仍声称位级等价。

实现要求调用期间输入、回调和配置不变，不观察中间输出或中间 fflags，使用 RNE、
有限且已准入的数据及可见前缀。已有 mask/类型/形状准入仍由原 runtime 执行。
只有入口拒绝可以 fallback；执行过回调后的失败不能重新从普通路径重算。

## 3. 存储与流量代价

设 query head 组大小为 H、每头维度为 D、可见历史长度为 T。
仅对输出更新的显式向量 load/store 字节数，排除初始化与最终归一化：

```text
原路径：8 * H * D * T
候选：  8 * H * D * ceil(T / 32)
```

例如 H=2、D=128、T=32，从 65,536 字节降为 2,048 字节。
这是源码对应的指令访问量，不是 DRAM 流量，也不是已测周期下降 32 倍。
缓存、端口、执行重叠和其他工作都会改变性能收益。

代价也必须计入：

- 系数临时数组为 2,176 字节，每次调用复用，不随完整上下文长度增长。
- 两个输出使用两个 LMUL=4 寄存器组，并需要 V 解码暂存；不是零资源占用。
- H>2 时，每一对 head 重新读取和解码一次 V，物理解码次数乘以 ceil(H/2)。
  因而不能以逻辑 `value_decodes` 计数推断硬件上的解码次数不变。
- 标量系数读写、准入检查、指令供给和寄存器搬移仍有成本。
- 当前针对 VLEN=1024；其他 VLEN 返回拒绝，由已有路径处理。D 支持 32..256
  的 32 倍数，H 支持 1..8，尾 tile 不要求满 32 个 token。

已检查叶子函数反汇编：输出保留在 v4/v8 寄存器组中，token 循环内没有输出的
向量存储或函数调用；退出 tile 后才存储。存在标量栈访问及向量组搬移，不能宣称
整个循环完全没有存储访问或额外开销。应对实际 RTL 构建再次检查其反汇编。

### 本轮捕获的候选实现问题

完整 runtime 测试发现：新代码错误复用了要求 4 字节对齐的 FP32 span 检查，
因而拒绝了合法 Q8_0 地址。Q8_0 每个 block 是 34 字节；D=32 且多个 KV head
交错存储时，第二个 head 的地址可能是 2 字节对齐而非 4 字节对齐。

探针记录 `h=1, d=32, t=1, token_stride=68`、输入地址末尾 `...c22`、
`frm=0, vstart=0`、online 返回 BAD_ARGUMENT，定位到数据布局准入而非计算。
修正仅针对量化字节缓冲：保留非空、范围、溢出和别名检查，不再要求 FP32 对齐。
浮点输出及系数的对齐要求不变。新增 +1/+2/+3 字节 payload 测试。
失败记录保存在 `e2e_output_runtime_20261106_01`、`_02`，没有覆写或改判。

所有上述运行目录都在唯一验证工作树的
`/home/wangwy/openproject/ara_dsa_signoff_integration/verification/out/` 下。
最终通过目录分别是 `e2e_output_tile_20261106_03`、
`e2e_output_online_20261106_04`、`e2e_output_runtime_20261106_03`、
`e2e_output_entry_20261106_02`。具体命令、依赖和输出身份随每个目录保存。

## 5. 下一步及停止条件

1. 将本候选用于真实 Qwen3 Q/K/V 与生产 GGML 量化、QBS 执行的完整调用，
   比较输出、fflags、native 命令数、准备次数与 fallback。
2. 选一个典型 GQA2 点和一个可能退化的较大 GQA 组，进行成对 VCS 验证。
   测量包括准备、QK、Softmax、PV 和最终归一化，不只测驻留叶子。
3. 如果完整调用收益稳定，才增加 llama.cpp 的显式 opt-in 和自动选择条件；
   若只减少访存却未降低周期，依据指令、队列和执行活动定位成本，不盲目扩大 tile。
4. 在端到端周期账目上与投影供给、矩阵复用等硬件方向比较，选择主要架构工作。
   本候选不自动晋升为下一篇论文的主创新，也不意味着整体 goal 已完成。

本阶段不做综合，不宣称新增硬件面积或完整模型加速。后续允许适度新增硬件，
前提是它解决了实际瓶颈，而且性能收益与资源代价相称。

## 6. 较大 GQA 与真实历史长度的完整调用结果

在较早 Qwen3 GQA2/D128/T20 完整调用配对取得约 1.25--1.27x 后，补充了真实
Qwen2.5 第一个 KV 组的 GQA6/D128/可见历史 128 点，检查更多 head 分组和跨
32-token tile 的成本。它使用原捕获的真实 Q/K/V、原 mask 和原数值容差；
token-major 转换经过反向布局核验，不靠重复短数据扩展历史。

同一 ELF、同一宽点积 SoC 上按 ABBA 执行 Register-PV/输出驻留两种软件调度：

| 试次 | 软件调度 | 完整调用 cycles | QBS busy cycles | 输出数 | 最终 FCSR/VCSR |
| ---: | --- | ---: | ---: | ---: | --- |
| 0 | Register-PV | 410737 | 9300 | 768 | 9 / 5 |
| 1 | 输出驻留 | 344912 | 9300 | 768 | 9 / 5 |
| 2 | 输出驻留 | 344355 | 9301 | 768 | 9 / 5 |
| 3 | Register-PV | 410241 | 9300 | 768 | 9 / 5 |
| 两次均值 | Register-PV | 410489 | - | - | - |
| 两次均值 | 输出驻留 | 344633.5 | - | - | - |

总时间比为 **1.1910885x**，完整调用周期减少约 16.04%。计时包括准备、真实
QK、在线 Softmax、PV 和最终归一化，不含检查与输出打印。四次全部输出及
最终 FCSR 逐位相同；与原捕获参考的最大绝对误差为 `1.4007091522216797e-6`，
保持原 `2e-5+2e-5*abs(reference)` 容差，没有为本实验放宽数值标准。

每次均为 8 条 QBS 命令、98304 个 QK 乘积，key bytes 为 17408，QBS busy
基本不变。收益来自完整软件调度，而不是把 QK 点积再次加速。本点的 QBS
profile 为短块路径，不因宽点积候选而改变每条指令的 dot 步长。

这里覆盖 6 个 query head 的一个 KV 组，不是模型全部 12 个 query head；
两个 ABBA 样本不构成统计置信区间，也不证明更长上下文的收益相同。
`value_decodes=128` 仍是逻辑 V 行数，不能把它解释为新调度只物理解码 128 次。
多个 head pair 会再次读取 V，其成本已包含在完整调用时间中。

正式独立复核位于验证树
`verification/out/e2e_output_gqa6_audit_20261106_01/`，状态
`GQA6_OUTPUT_CALL_REAUDITED`。收集器重查 756 项输入、实际镜像、原始输出、
CSR、命令工作量和独立协议检查，不仅依赖 worker 的 PASS。该结果仍不作为
完整模型加速比或新硬件面积结论。
