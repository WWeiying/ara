# 共享 SIMD 整数乘法器

## 范围和状态

本实现只修改 lane 内整数乘法路径，不修改浮点运算、QBS、AKV、访存或软件。
编译时定义 `ARA_SHARED_SIMD_MUL` 启用共享核心；不定义时使用原来的四组乘法器。
在面积、时序和整机回归完成前，不将共享实现设为默认，也不替换 FPGA 交付副本。

## 共享什么

原实现按 SEW 分别生成 8 个 8 位、4 个 16 位、2 个 32 位和 1 个 64 位乘法。
同一个 lane 每次只向其中一组送入有效操作数。
新实现将这些互斥的乘法合并为一个可分区的部分积网络和进位保存压缩树。

| SEW | 每个有效输入的运算 | 完整乘积总位数 | 内部乘积寄存器级数 |
|---|---|---|---|
| 8 | 8 组 8×8 | 128 | 0 |
| 16 | 4 组 16×16 | 128 | 1 |
| 32 | 2 组 32×32 | 128 | 1 |
| 64 | 1 组 64×64 | 128 | 1 |

这里的级数不包括 VMFPU 入口寄存器和结果队列。16/32/64 位使用同一组寄存器，
8 位绕过该寄存器。单一位宽无背压时可每周期接受一个 64 位操作数对，不通过
串行执行换取面积。混合位宽切换必须服从共享资源和结果顺序，不能再把四套
独立流水的全部 ready 信号视为共享实现的逐周期契约。
实际最高主频和应用性能尚需验证。

这不是将 8 个完整的 8×8 乘法器串行复用成 64×64。
完整 64×64 运算需要所有交叉部分积；只保留 8 个小乘法器无法同时保持原吞吐。
以 8 位为最小 SIMD 分区，共享内容包括部分积、压缩树、两个符号修正加法器、
一套乘积流水、一个后处理加法器以及最终饱和选择。符号修正和乘加处在不同
流水阶段，保留独立的物理加法器，不能为了进一步复用而破坏每周期吞吐。
不同位宽仍需各自的静态取位、边界判断和舍入条件，但不再各自生成宽加法器。

## 算术逻辑

`simd_mul_shared_product.sv` 首先生成 `a[i] & b[j]`。
SEW 决定哪些部分积属于同一个元素，跨元素乘积不参加求和。
每个 N 位元素的完整乘积放到独立的 2N 位区间。
每三行部分积通过 XOR 与多数逻辑压缩为两行，最后进行进位传播加法。

无符号完整乘积不会溢出其 2N 位区间，因此压缩树中的非负中间和不会产生
跨元素的有效溢出。符号修正另行在每个元素的高 N 位局部完成：

```text
low  = unsigned_product.low
high = unsigned_product.high
       - (signed_a && a.sign ? b : 0)
       - (signed_b && b.sign ? a : 0)
```

这是二进制补码乘法模 2^(2N) 的等价式。局部减法截断到 N 位，防止符号修正
影响相邻元素。VMULHSU 的 signed 标志遵循现有端口方向，而不是按端口字母猜测：
内部 B 为有符号源，A 为无符号源。

符号修正将各元素的高半乘积紧凑排列为 64 位，经过两个共用的可分区减法器，
然后送回各自的完整乘积位置。不是按四种位宽各生成两套减法电路。

`simd_mul_shared.sv` 保存乘积、C 操作数、mask、饱和位、操作码和 SEW。
输出侧选择乘积的低半、高半或定点小数部分，统一送入
`simd_mul_partition_add.sv`，完成乘加、乘减或舍入增量。
这个加法器由八个字节片段和三级字节进位前缀网络构成，元素边界切断前一元素的
进位，并注入该元素自己的减法初始进位或舍入位。
饱和时输出相应位宽的最大正数。
旧 `simd_mul.sv` 和它的外部乘积选项保留供对照，不实例化在新共享路径中。
VXRM 保持原来的输出侧可见语义，本次未更改 CSR 时序契约。

## 接入与握手

共享核心读取 VMFPU 已寄存的公共 A/B 和操作码。
位宽由与它们同步的 `vmul_simd_in_valid_q` 单热标签解码，不能使用可能已经
指向下一条指令的 issue 状态。有效请求进入唯一的共享通路。
输出的 SEW 随乘积保存，由它生成原 VMFPU 所需的单热结果有效信号。

背压由共享流水传回入口；入口停顿时操作数和有效标签保持不变。
8 位旁路仅在共享流水为空时生效，不能越过尚未取走的宽位结果。
无有效入口时必须仍允许入口寄存器装入新请求，不能因默认 SEW=8 而错误地
等待 8 位出口 ready；这一条件显式体现在 ready 逻辑中。
不同位宽的结果仍按原有顺序控制读取，本次不解除跨位宽发射限制。

黄金 RTL 固定为 `f636824e9b5a347666401bba40a6a17925b9a402` 的 `simd_mul.sv`。
VCS 测试输出放在唯一验证 worktree 的 `verification/out/` 下。

| 检查 | 结果 | 输出子目录 |
|---|---|---|
| 共享符号修正、流水及后处理，4 SEW × 3 流水深度 × 2 固定点配置 | 24 配置通过，196,296 次周期检查，84,464 个退休事务独立算术检查 | `full_shared_mul_r2_20261030/mul` |
| 实际 VMFPU 接线、位宽混合、背压、复位、连续发射 | 接受 9,640 项，正确退休 9,639 项，复位清除 1 项；各 SEW 连续 256 次发射均满足 II=1 | `full_shared_mul_stream_r3_20261030/bank` |
| VMFPU 开启共享后的语法分析 | 通过 | `full_shared_mul_analysis_20261030/vmfpu` |

旧 `shared_mul_*_20261030` 输出验证的是只共享乘积核心的第一版，不能作为本版
共享流水和后处理的验收结果；其原日志保留，不覆盖。
本轮早期 stream 包装缺少 `strb_t` 定义，修正后又发现测试比较器在 `#1` 等待后
读取了下一周期的输出有效位。后者通过先保存时钟沿的输出快照修正，未修改 RTL
来迎合测试；原失败日志也保留。最终 r3 使用修正后的检查器运行通过。

独立算术模型检查九种内部操作、四种舍入模式、符号边界、饱和、随机数据、
反压及复位；固定流水测试逐周期检查 valid 和 ready，并在有效时检查结果、mask、
vxsat。混合位宽测试按实际接受顺序排队，用旧乘法器检查退休值，另检查事务无丢失、
无乱序，以及每种位宽连续 256 次发射的 II=1。

`extract_shared_mul_bank.py` 还可直接提取 VMFPU 实际修改的乘法器实例和选择逻辑，
生成小型测试包装，避免手写测试接线与实际接线不一致。包装替代了输入隔离单元，
不包含整个 VMFPU 的发射、时钟门控和结果队列，因此不能替代整机回归。

## 复跑

在项目根目录执行；每次使用新的 BUILD 目录：

```sh
make -C verification/timing mul-check \
  REFERENCE=f636824e9b5a347666401bba40a6a17925b9a402 \
  MUL_DEFINES=+define+TEST_FULL_SHARED_SIMD_MUL \
  BUILD=/absolute/path/to/new-test-output
```

动态位宽测试目标为 `shared-mul-bank-check`，VMFPU 语法分析目标为
`shared-mul-vmfpu-analyze`。普通 `mul-check` 不传 MUL_DEFINES 时检查旧路径。

实际接线测试示例（`OUT` 必须使用新的独立目录）：

```sh
OUT=/absolute/path/to/new-bank-output
python3 verification/timing/extract_shared_mul_bank.py \
  hardware/src/lane/vmfpu.sv "$OUT/extracted"
make -C verification/timing shared-mul-bank-check \
  REFERENCE=f636824e9b5a347666401bba40a6a17925b9a402 \
  BUILD="$OUT" MUL_DEFINES=+define+ARA_SHARED_SIMD_MUL \
  MUL_BANK_TOP=shared_mul_stream_tb \
  MUL_EXTRA_SOURCES="$OUT/extracted/bank.sv"
```

## 面积和时序验收

共享逻辑并不自动意味着面积更小。SEW 路由、多级压缩、最终宽加法和局部符号
修正均有成本；当前采用直接部分积而不是 Booth 编码，综合器对原 `*` 的优化
可能比显式逻辑更好。必须使用同一工艺库、约束、负载比较整个整数乘法子系统，
包括选择器、流水、后处理和门控，不能只比较乘法核心。

尚未完成 DC 面积/时序对照、完整 SoC 的乘法相关 RVV 程序回归及 FPGA 验收。
当前结论仅为共享乘法 RTL 已实现并通过所列局部功能验证，不是 PPA 优势已证实。
