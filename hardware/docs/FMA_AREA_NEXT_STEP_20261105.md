# 浮点共享后的面积空间与下一步选择

## 结论

保留已通过功能回归的浮点共享候选，暂不重写尾数乘法阵列。
已测的 21.7649% ADDMUL 面积下降是主要低风险共享收益。进一步显著压缩
不能只靠缩短 tag，也不能将几个小乘法器的理论面积直接算成可节省面积。

该方向现已完成：保持五周期延迟和 SIMD 并行能力，将重复的宽数据延迟
寄存器移到较窄的最终结果侧。本轮面积比上一共享版再降低 9.5615%，
成对 SoC 回归与上一版的周期和输出记录完全一致。保留本轮候选，默认开关
不变。全部时序组尚未收敛，不能仅凭 clk_i setup 通过就作生产交付。

下列结构分析基于上一版已完成的综合；后续实施与验证状态见文末。

重新 link 并导出资源报告、标准单元清单及组合逻辑锥。没有调用 compile。

`verification/timing/report_fma_structure.tcl`。DDC、库、脚本均记录哈希。
叶单元面积累加为 35,576.688000 平方微米，与原报告的 35,576.687576
一致到报告打印精度；有效标准单元数为 30,337。

DC 数据库还包含 584 个 `**logic_0**` 虚拟常量对象，不是有面积的标准

这不是改变映射电路或豁免功能检查。

## 为什么不优先重做乘法阵列

映射后 `report_resources` 显示，每个子通路的以下操作已被提取为同一个
DesignWare 数据通路：

- `mult_416`：尾数乘法；
- `add_458`、`add_458_2`：对齐加数和修正位相加；
- `sub_462`：相应的符号处理。

FP64 通路中可见两个 53 位乘数、106 位内部乘积、163 位对齐输入和
164 位加法输出。FP32/FP16 通路的乘数分别为 24/11 位。
这是综合器已做融合的证据，不表示所有门的最优性已经得到证明。

映射网表不再保留独立的 `product`、`sum_raw` 等边界网。报告中的这些
单独逻辑锥面积为 null，不能写成零。`mid_sum_input` 从实际中间结果寄存器
的 D 引脚回溯到上一时序边界，其面积还包括对齐、格式选择、控制和乘加，
不能称为纯乘法器面积。

| 子通路 | 总面积 | 中间和输入组合逻辑锥面积 |
|---|---:|---:|
| FP16/32/64 | 21,704.256 | 13,038.984 |
| FP16/32 | 7,461.720 | 3,847.872 |
| FP16，第 3 元素 | 3,031.728 | 1,250.928 |
| FP16，第 4 元素 | 2,943.360 | 1,273.104 |

后三条通路上述组合锥去重合计 6,371.904 平方微米，约为部件面积的 17.91%。
其中对齐、加法和符号处理仍要为不同 SIMD 元素服务，无法因为共享乘法就
全部删除；同时新的分区选择、隔离和路由也需要面积。因此不能承诺更深的
乘法共享还能轻松省掉部件面积的二三成。

若以后研究一个 53 位可分区阵列，需要明确覆盖 1x53、2x24、4x11 位
乘法、完整乘积保留、跨元素进位隔离和四元素独立 FMA 后处理。不能将几个
尾数拼到普通乘法输入就认为完成了 SIMD 乘法，也不能先舍入乘积再做 FMA。

## 更优先的候选：流水位置调整

上一版 `NumPipeRegs=5`、`DISTRIBUTED` 对应：

```text
输入寄存器 x2 -> 乘加组合逻辑 -> 中间寄存器 x2
             -> 规格化/舍入组合逻辑 -> 输出寄存器 x1
```

同一组内连续的两个寄存器级之间没有新的算术计算。它们保存的是宽操作数、
中间和及其附带信息，用于延迟和弹性缓冲。可以评估以下候选：

```text
输入寄存器 x1 -> 乘加组合逻辑 -> 中间寄存器 x1
             -> 规格化/舍入组合逻辑 -> 输出寄存器 x3
```

保持总共五级有效位和背压容量，不合并两个主要算术组合段。提前得到最终
窄结果后，用输出级承担剩余延迟，减少长时间保存宽中间量的开销。
这不是让时钟周期翻倍，不减少 SIMD 元素数，也不靠多周期串行乘法省面积。

从映射后的寄存器名字逐项汇总，以下不包含时钟门控单元：

| 寄存器级 | 单元数 | 面积，平方微米 |
|---|---:|---:|
| 输入第 1 级 | 557 | 1,684.368 |
| 输入第 2 级 | 557 | 2,088.912 |
| 中间第 1 级 | 731 | 3,565.296 |
| 中间第 2 级 | 731 | 2,349.144 |
| 输出第 1 级 | 240 | 783.216 |

用现有单元面积做粗略代理计算：

```text
输入第2级 + 中间第2级 - 两个新增输出级
= 2088.912 + 2349.144 - 2 x 783.216
= 2871.624 平方微米，约当前部件面积的 8.07%
```

这是立项筛选用的估算，不是新的综合结果或严格上限。驱动强度、门控、
使能网络和布线会变化，同样的寄存器位数也不保证同样面积。
尤其输入有效位的停顿、清空、满流水反压和跨精度事务对齐必须重新验证。
总延迟和容量相同并不自动证明逐周期接口完全等价。

## tag 精简的实际规模

实际网表仅第 0 子通路保留完整 80 位 tag 的五级存储；其余通路的未使用
tag 已被裁掉。原版型 tag 中的 64 位 `operand_a` 在 ADDMUL 路径不消费，
但其他 opgroup 的估计、比较处理仍需要对应信息，不能全局删除。

当前 tag 数据寄存器为 400 个，面积 1,209.600 平方微米；附属门控为
10 个，面积 30.240 平方微米。只删除其中 64x5=320 位的直接寄存器面积
代理约为 967.680 平方微米，即部件面积的 2.72%，并非四倍这个数字。
实际收益仍需综合验证，且归约控制、异常掩码和调试身份必须保留。

所以 tag 精简值得做，但不是单独的大幅降面积方案。

## 执行门槛

下一项若实施，先只做流水位置候选，暂不叠加去复位、tag 精简或新乘法阵列：

1. 保留当前默认关闭的共享实现和已通过版本。
2. 在可追踪的本地实现或依赖补丁中增加明确的流水分配参数，不直接漂移
   未纳入版本管理的依赖库。
3. 同一输入事务逐项检查结果、fflags、tag；覆盖 reset、flush、满流水、
   随机背压、混合格式和逐周期接收/退休。保留独立 SoftFloat 检查。
4. 通过部件验证后，运行现有 31 程序、62 次成对 SoC 验收和微内核计时。
5. 只启动一轮同条件部件 DC；若面积未下降、关键路径明显变差或引入停顿，
   不采用该候选。没有证据就不默认开启。

## 流水重分配候选与验证进展

已在 `hardware/src/lane/simd_fma_shared.sv` 实施单一候选，不修改 FPnew
算术源码。增加 `CompactPipeline` 参数，置零可恢复原来的流水分配。
总级数为五时，实际结构为：

```text
四个子通路各自：输入 x1 -> 乘加 -> 中间 x1 -> 规格化/舍入 -> 输出 x1
四路结果合并为 64 位结果、fflags 和 tag -> 公共输出寄存器 x2
```

新增输出级复用 `common_cells/stream_register.sv`，同时传递数据、异常标志
和事务标签，支持背压与 flush。`busy` 覆盖核心和新增输出级；子通路对齐
断言在核心输出处检查，不能错误地用延迟两级后的接口有效位检查核心标签。
总延迟仍为五周期，保持原 SIMD 元素数和每周期接收能力。

与上文面积代理估算不同，两个新增级位于四路结果合并之后，而不是分别在
四个子通路复制。其面积与时序必须以本轮综合为准，不能直接认定节省 8.07%。

已完成的 VCS 部件检查：

| 检查 | 实测结果 |
|---|---|
| 与上一版冻结共享 RTL 的逐周期对照 | 23,966 个周期通过 |
| 事务计数 | 接收 14,586；校验 14,358；flush/reset 中止 228 |
| 背压观察 | 8,135 次 stall 计数，握手、busy 及有效输出一致 |
| 独立 SoftFloat 算术参考 | 7,200 组通过 |
| 四态标签一致性 | 相同 X 位可正常通过；人为破坏标签时断言正确拒绝 |

逐周期对照包括 ready、valid、busy，以及 valid 时的结果、fflags、tag，
也检查停顿期间的有效输出。它是有限仿真的证据，不是全状态形式等价证明。
独立数值参考不因流水变化而放宽容差。

证据在验证工作树 `verification/out/`：

- `shared_fma_pipeline_20261105_01/`：冻结旧实现及逐周期检查。
- `shared_fma_softfloat_20261105_01/`：独立算术检查。
- `shared_fma_tag_20261105_01/`：标签正反向检查。

后台流程入口为 `verification/timing/run_shared_fma_compact.py`，顺序如下：

1. 冻结输入、依赖和检查器，运行 31 个程序的原版/候选成对 SoC 检查，
   共 62 次，仿真最多六路并行。
2. 与 `shared_fma_soc_20261104_03` 逐项比较完成时刻、程序周期及微内核
   输出记录；要求完全一致，失败时停止，不直接进入综合。
3. 通过后对上一版共享实现与本轮紧凑流水实现做同库、同约束部件 DC。
   目标周期仍为 1 ns，setup uncertainty 为 0.15 ns，不进行全局综合。

上述为启动时的验收安排，现已完成，结果如下。`ara_pkg::EnableSharedFma` 仍为零，
生产默认路径和 FPGA 副本均未切换。独立原版、已测共享版和本轮候选的
数据必须分开保存；后续采用还需要审核所有时序组，不能只看面积。
