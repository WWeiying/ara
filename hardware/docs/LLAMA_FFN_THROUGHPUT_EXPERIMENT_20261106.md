# 真实 Qwen3 FFN 投影的吞吐验证

## 1. 本批要回答什么

当前宽点积候选的 SDK 性能证据首先来自 QKV。完整模型工作量账目表明，FFN
是更大的投影工作来源，因此需要补齐 gate/up/down 的真实输入，尤其是 down
的 K6144，验证数据供给、整数修正及 FP 累积能否继续支撑候选吞吐。

本批没有进一步修改 RTL、ISA 或 SRAM。它复用同一对已核验的原点积/宽点积
SoC 镜像；宽点积仍默认关闭。本阶段不运行综合，也不宣称面积收益。

## 2. 输入来自怎样的模型执行

复用已通过完整模型配对检查的 llama.cpp 静态库，只重建观测入口。模型是
Qwen3-1.7B Q4_K_M，使用原来的 40-token 自然语言 prompt、单 worker、Q8_0
K/V cache，以及已有 native QBS 和 grouped Prefill 路径。回调在后端同步后
读取第一层的三个 F32 张量：

| 捕获点 | 原张量形状 | 捕获行数 | 用途 |
| --- | --- | ---: | --- |
| `attn_norm-0` | 40×2048 | 4 | 与先前 QKV 捕获逐位核对 |
| `ffn_norm-0` | 40×2048 | 4 | gate/up 共用的真实激活 |
| `ffn_swiglu-0` | 40×6144 | 4 | SiLU 与逐元素乘法之后，down 的真实输入 |

每个捕获点的四行均来自不同真实 token，检查有限值、尺寸、步长和行不重复。
捕获在第一个 down 投影执行前主动退出，不将它称为完整模型生成通过。
原始 GGUF 与 guest 模型盘的对应关系沿用已核验的嵌入文件身份，并重新核对
两侧文件哈希；权重取自原始 GGUF，而不是临时重排缓冲。

验收同时核对捕获边界之前的 6 个量化投影调用及 5760 条真实 native 命令，
并要求 grouped Prefill 实际执行成功。它不是仅设置环境变量后就假定命中了
快速路径。

## 3. 观测门控的一次修正

第一轮完整输出了三个张量，但缺少逐条命令日志。源码确认该日志同时受
`GGML_RISCV_QBS_TRACE` 与 `GGML_RISCV_QBS_TRACE_LIFETIME` 控制；原入口只开
了前者。第一轮仍保留 FAIL，不降低原检查标准。

第二轮同时开启两个观察开关，计算库和模型配置未变，完成原定全部检查。
两轮的 2564 条捕获 token/shape/data 记录逐位一致；这项比较只证明日志门控
变化没有改变捕获输入，不将第一轮重新标成 PASS。

已接受捕获位于唯一验证树：
`verification/out/e2e_ffn_capture_20261106_02/`，状态
`REAL_QWEN3_FFN_CAPTURED_NOT_BENCHMARKED`。

## 4. SDK 配对的精确范围

| 投影 | 权重格式 | M | 采样 N | 保留的真实 K | 原始完整 N |
| --- | --- | ---: | ---: | ---: | ---: |
| gate | Q4_K | 4 | 128 | 2048 | 6144 |
| up | Q4_K | 4 | 128 | 2048 | 6144 |
| down | Q6_K | 4 | 128 | 6144 | 2048 |

gate/up 对相同输入准备一次 Q8_K M4 数据，down 单独准备。这个复用是已有
执行契约的使用，不作为本轮新增优化。计时包含两次准备、admission、SDK
执行和调用控制；原始权重重排在计时外完成。

三个投影共执行 12 条 native 命令、5242880 个有效整数乘积，检查全部 1536
个输出、量化 payload、FCSR/VCSR 和前后 guard。独立 C 参考比较 row-major
与 R4 权重布局的输出及异常标志；参考执行器不链接进性能 ELF。

**这不是完整 FFN 层。** N 被采样，SiLU/multiply 不在此 ELF 的计时区间内；
down 使用从真实完整图捕获的输入，而不是由此处采样的 gate/up 输出重建。
它验证的是三类 FFN 投影的完整 K SDK 调用组，不是完整 FFN、整个 prompt
或模型增量加速。准备占比也不能由这个 N128 程序外推到完整 N。

## 5. 构建与收集

`build_ffn_native.py` 复用九个已核验公共 object，只重建 caller 和 data 两项，
并保留 host oracle、反汇编及 L2 准入记录。两套 16 MiB SoC 均已确认 ELF
需要的 L2 范围为 1195016 字节。

`run_ffn_native.py` 默认仅做 preflight；显式使用 `--execute-reviewed` 才运行
VCS。每侧独立目录，最长 90 分钟，关闭 FSDB；完成后执行独立协议检查和
源文件/镜像身份复核。程序的计数与数值检查不因硬件宽度而放松。

`watch_ffn_pair.py` 通过文件事件等待两侧结果，再由
`collect_ffn_native.py` 重读原始日志和全部身份信息，比较相同工作下的周期。
down 准备发生在前两个投影之后，不预先假设两侧准备周期必然相等；实际
周期必须如实列出，不能为得到漂亮的时间比而删除不同的准备成本。

运行结果未闭合前，不填写本批加速比。FFN 证据与全 N QKV、较大 GQA Attention
及完整模型准备复用统计共同用于下一项结构选择，而不是直接相乘成端到端收益。
