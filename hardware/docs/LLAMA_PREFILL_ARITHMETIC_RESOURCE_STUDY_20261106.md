# Prefill 的下一项投入：点积、浮点端口与供给必须一起判断

## 1. 本轮结论

当前不能依据“整数 dot 发射占比较高、FP 反压为零”，直接把整数乘法器再加倍。
真实 Qwen3 QKV 调用组中，Q4_K 每条命令的整数 dot 发射周期为 4096，浮点
算术端口也必须完成 4096 次操作。单独缩短 dot 之后，原先被计算节奏隐藏的
浮点需求会成为限制。这是源码和已完成 RTL 计数共同给出的资源约束，不是
新硬件的性能测量，也不意味着当前每个 busy 周期都在进行浮点运算。

优先级因此调整为：保留已验证的 Decode 供给改善；测清 Attention 的剩余
完整调用成本；若继续提高 Prefill 点积吞吐，必须同时解决随之暴露的比例
计算、累积端口和子组修正吞吐，而不是只复制整数阵列。

## 2. 实际证据与范围

配对为同一 ELF、M4、K2048、Q/K/V 的 N=2048/1024/1024，共 128 条命令、
16384 个输出。两侧矩阵计算配置相同，只改变物理供给宽度及匹配的入口。
调用区域包括激活准备和准入，不包括冷启动权重重排。

| 指标 | 128-bit 供给 | 256-bit 供给 |
| --- | ---: | ---: |
| 完整测量区域 cycles | 803294 | 759604 |
| SDK execution cycles | 740075 | 701323 |
| QBS busy cycles | 693319 | 656103 |
| dot 发射周期 | 524288 | 524288 |
| FP 微操作握手总数 | 688128 | 688128 |
| 部分和更新次数 | 131072 | 131072 |
| R beats | 404608 | 240768 |
| weight phase cycles | 91847 | 54631 |
| compute-only + overlap cycles | 565248 | 565248 |

busy 减少 37216，恰好等于 weight phase 的减少。compute-only 从 175704
变成 301140，overlap 从 389544 变成 264108；二者之和不变。内存更早结束后，
原本归为 overlap 的一部分时间变成 compute-only，因此不能把后者变大解释
为计算变慢。其他诊断 counter 可能相互重叠，不可加入这组 phase 分区求和。

本轮重新检查两路原始输出、计数、源文件和镜像身份，以及独立协议回执。
诊断记录为验证目录中的
`e2e_supply_prefill_diagnosis_20261106_01/result.json`，SHA256：
`581ecd31248e3c192e8a96c6e42dac9a450955f704431c6e991cef1bdd60c183`。
该记录不代替完整模型计时，也不代表所有层、格式或存储系统均有同样比例。

## 3. 实际浮点资源并不是四个并行算术端口

`qbs_fp_accumulator.sv` 的实例有一个 FP32 算术发射口；整数到浮点转换有
独立端口，特定 FP16×FP16 的 scale 计算还有独立通路。这里不能依据 RVV
有四个 lane，就把 QBS 的浮点算术吞吐按四个端口计算。

本批激活为 Q8_K，activation scale 是 FP32，因此不满足 FP16×FP16 通路
的准入条件。每个输出、每个 K block 的状态推进如下：

| profile | 独立 I2F 端口 | 单个算术端口 | 握手总数 |
| --- | --- | --- | ---: |
| Q4_K | dot、aux 各转换一次 | scale、min-scale 各一次 MUL；dot、min 各一次 FMADD | 6 |
| Q6_K | dot 转换一次 | scale 一次 MUL，dot 一次 FMADD | 3 |

每条 M4/N32/K2048 命令更新 `4*32*8=1024` 个部分和。实际计数分别为
6144、3072，与上述状态数完全一致；本批有 96 条 Q4_K 和 32 条 Q6_K 命令。
第一次 K block 使用零初值，并不省略这里列出的算术状态。

| 每条命令的服务需求 | Q4_K | Q6_K |
| --- | ---: | ---: |
| 当前 dot 发射周期 | 4096 | 4096 |
| 单算术端口的最少发射周期 | 4096 | 2048 |
| 独立 I2F 端口的最少发射周期 | 2048 | 1024 |
| 256-bit 平台实际 R beat 数 | 1737 | 2313 |
| 假设整数吞吐改为 128 products/cycle 后的 dot 发射下界 | 2048 | 2048 |

这些服务可以重叠，不能相加成预测运行时间。即使忽略全部流水首尾、依赖、
仲裁和软件开销，Q4_K 仍受 4096 次算术发射约束；Q6_K 则至少还需要处理
2313 个 R beat。零输入反压是当前速率下的观测，不证明未来加倍速率也不会
反压。`probe_fp_busy_cycles` 还包含有效 entry 的生命周期，不能命名为
“浮点功能单元实际计算利用率”。

本轮诊断绑定实际编译的浮点源码 SHA256：
`13a400d7daa62779e6f829237365c4df7b31fbd4f2f6024491c1fb59468f4d60`。
其字节与当前主线对应文件一致。未来更改状态数、端口或数值路径后，需要
重新建立这份资源账目，不能直接沿用本表。

## 4. 候选的取舍

1. **只继续加宽供给：**当前 Prefill 完整区域收益约 1.058x。剩余严格 weight
   wait 为 22231 cycles，不能单凭这个方向承诺显著的进一步模型收益。
2. **只增加整数乘法器：**没有同时处理上述算术约束，不作为当前实施方案。
3. **协同提高 dot 和浮点比例计算吞吐：**值得进一步比较；例如将 scale MUL
   与累积 FMADD 分开服务，或在有可靠仲裁和完成跟踪的前提下借用空闲 RVV
   算术资源。前者需要核算新增乘法、寄存器和 tag，后者需要核算跨模块传送、
   资源所有权、普通 RVV 竞争及异常恢复。两者均尚未实现，不能标为收益。
4. **先减少 Attention 的完整调用成本：**现有 QK/PV 加速不覆盖在线 Softmax
   的全部软件开销。先以不改变数学运算的阶段探针，测 QK、系数计算、PV、
   量化和准备/收尾，并用未插桩调用衡量观测扰动，再决定是否值得增加资源。

选择标准仍是完整 Prefill/Decode 的收益与资源投入，不要求所有改进来自
QBS/AKV，也不要求新增面积为零。本阶段不进行综合、功耗或 FPGA 闭环。
