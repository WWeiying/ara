# 矩阵链路平衡优化：完整控制器验收

## 1. 设计和验证范围

本候选不是单独增加整数乘法器。它面向 256 元素量化块、每波三个或四个输出行，
同时调整点积输入窗口、子组修正吞吐及 FP16×FP32 scale 计算，使缩短后的整数阶段
不会立即被下一阶段完全阻塞。每个累积结果仍保持原来的浮点运算顺序，特殊值保留
完整 FPU 路径；短块格式、M1/M2 和不满足条件的尾波沿用原路径。

此前的 compute 部件结果见 `LLAMA_BALANCED_COMPUTE_ACCEPTANCE_20261106.md`。
本次补入完整命令控制器、读引擎、payload、context 和提交路径，而不是把 compute
周期当成一条命令的全部周期。三种镜像均使用 256 位外部读响应和相同矩阵配置：

| 镜像 | 控制器与计算模块 | 候选开关 |
| --- | --- | --- |
| original | 原模块 | 无 |
| disabled | 隔离候选模块 | 0 |
| enabled | 隔离候选模块 | 1 |

每个镜像执行 84 次直接功能命令，并执行 context 生命周期、故障及恢复测试。
直接命令包括 36 项连续返回、36 项间隔返回及 12 项 context 集合的直接命令。
测试保留原始输出和 fflags 检查、四类原子故障、后续块 fault/reset replay、
context FILL/REUSE/RELEASE 与权重故障重试；没有改动数值期望来适配候选。

## 2. 实测结果

以下周期仅为每个集合中直接命令的周期之和，不包含故障注入和生命周期操作的
全部执行时间，也不包含 SDK 准备或 GGML 调用。

| 直接命令集合 | 命令数 | original cycles | enabled cycles | 比值 | 改善 / 不变 / 退化 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 连续读响应 | 36 | 23148 | 20290 | 1.14086× | 15 / 21 / 0 |
| 读响应间隔为 3 | 36 | 37889 | 35642 | 1.06304× | 15 / 21 / 0 |
| context 形状的直接命令 | 12 | 16796 | 15919 | 1.05509× | 5 / 7 / 0 |

original 与 disabled 的全部已记录输出、周期、工作量、context 行为和读事务
统计一致。enabled 保持有用运算、提交字数、逻辑读范围和实际 AXI 读工作量一致。
未获准使用候选的 M1/M2 与短块命令，其直接命令周期也与原版完全相同。

这个结果说明完整控制器没有吞掉全部 compute 收益，同时也说明仅看计算部件会
高估完整命令收益。供给变慢时，原版与候选的周期比从约 1.141× 降至约 1.063×；
下一阶段必须测量真实调用，不能继续只扩大计算部件规模。

## 4. 下一步的准入条件

`prepare_balanced_soc.py` 仅创建独立构建输入。它要求本次控制器验收和独立的
非零 seed / 分段 K / 取消恢复测试均通过，并核对各测试与 SoC 使用的候选
模块逐文件一致。保留已接受的普通 RVV、标量及依赖源文件，只改变候选 VLSU
接入及新增的隔离模块；256 位物理存储宽度、4 lane、VLEN1024 和 16 MiB
容量不变。编译诊断必须与既有 SoC 的已知诊断逐项一致，否则停止并审查。

随后先运行真正使用 M4 的 QBS→AKV→普通 RVV→QBS 交接，再复用真实模型
数据和相同 ELF 测量 QKV、FFN。以上均未在本回执中宣称完成。

完整控制器通过不证明真实 MMU/PMP、Linux 或 FPGA 通过；这里的 AXI 和
翻译故障来自测试夹具。尚未进行综合、面积、功耗或端到端模型性能验收。
