# 同平台 Decode 投影对照与周期账目

## 实验对象

使用真实 Qwen3 首个 Decode token 的输入，保持完整 K，取 N64 输出前缀。
普通 RVV 使用原生产 GGML 算术对象；native 使用现有 QBS SDK。两种实现置于
同一 ELF 内，按 ABBA 顺序执行，计时边界包含匹配的 CSR 完成和 fence。
128/256 位平台分别执行相同 ELF，保持 4 lane、VLEN1024 和 16 MiB 容量。

为满足单次仿真时间限制，调用分成两份 ELF，而不是缩短 K 或替换真实输入：

| 分组 | 调用 | K | N |
| --- | --- | ---: | ---: |
| 0 | Q/K/V、gate/up、词表投影 | 2048 | 64 |
| 1 | down | 6144 | 64 |

以下总账是两个独立分组的 ABBA 均值相加，**不是一次连续七项调用的测量**。
四组激活准备分别只计一次，不按每个消费者重复计费；单个投影的完整区域时间
没有独立测量，故不把共享准备时间强行摊给每一项。

## 实测数据

单位为实际 RTL cycles。区域时间包含准备、准入、执行和其间的调用开销，
因此不要求恰好等于前三列的和。

| 物理宽度 | 路径 | 准备 | 准入 | 执行 | 区域总账 |
| ---: | --- | ---: | ---: | ---: | ---: |
| 128 | 普通 RVV | 68487.5 | 723.5 | 2086445.5 | 2156709.5 |
| 128 | QBS SDK | 68595.0 | 12979.0 | 77831.5 | 160557.0 |
| 256 | 普通 RVV | 65354.5 | 723.5 | 2075933.5 | 2143064.5 |
| 256 | QBS SDK | 65461.5 | 12979.0 | 62790.5 | 142382.5 |

普通 RVV 与 QBS SDK 的区域周期比分别为 13.43267×、15.05146×；
仅执行部分的周期比分别为 26.80721×、33.06127×。这些是所选 N64 投影的
对照，不是模型 token/s，也不是本轮 balanced M4 候选的增量收益。
本组是 M1 Decode，尚未运行该新候选。

物理供给从 128 改为 256 位后，SDK 执行和区域均有所改善；普通 RVV 改变较小。
N64 时准备占比很高，但不能据此直接选定激活量化硬件：扩大 N 会摊薄这部分
成本，已有完整 N QKV 的准备占比明显不同。结果也不能按全模型输出列数机械
放大，忽略固定成本、重用、外部带宽和各层差异。

## 正确性和证据

每个 guest 检查全部所选输出、激活 payload、guard 和 CSR。普通 RVV 的参考
来自先前 N128 exact-ELF Spike 结果的精确 N64 前缀；native 则使用独立 QBS C
参考。两套参考分别检查，未强迫两条不同舍入路径逐位相同。分组后的混合 ELF
没有单独在 Spike 执行，不能把继承参考描述为该 ELF 的新 Spike 通过。

独立 collector 重放四份原始功能日志及其 UVM/AXI/backend 证据，核对完整镜像、
关键 RTL、编译输入、数据前缀与软链接目标，记录 381 项选定文件和 382 项路径
身份。继承的完整清单被绑定，但未重新散列其中每一项；不将该范围扩大表述。
