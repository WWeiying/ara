# Attention/KV Streaming Milestone 5 Results

## 1. Scope and evidence boundary

Milestone 5 connects the Attention/KV streaming (AKV) mechanism to the real
llama.cpp/GGML CPU backend. The integration selects a strict Decode
`GGML_OP_FLASH_ATTN_EXT` shape at runtime, uses the shared AKV runtime and
native assembly kernel, and leaves every unsupported operation on the
unchanged CPU/RVV path. QBS and AKV can be compiled into the same backend and
remain independently selected.

The model-level result below is a functional QEMU comparison. It proves graph
dispatch, fallback, runtime planning, complete-model execution, and numerical
agreement; it is not a hardware cycle measurement. Native AKV performance and
numerical error are established by the real-model RTL operator results from
milestone 4. No synthesis was run during milestone 5.

## 2. GGML integration

The adapter is inserted at the beginning of the F16 Flash-Attention compute
path. It accepts an operation only when all of the following hold:

- Decode query length and batch are one;
- Q is F32, K/V/mask are F16, and the output is F32;
- head dimension is 128 and the GQA ratio is six;
- Q, K, V, mask, and output layouts satisfy the native descriptor strides;
- scale is finite and positive, and sinks, ALiBi bias, and softcap are absent;
- the mask is one finite active prefix followed by exact F16 negative
  infinity; and
- emulation is requested, or native capability discovery reports the required
  AKV profile.

Eligibility is decided before an AKV plan or hidden context is created. An
unsupported operation therefore returns directly to the original GGML
implementation without an AKV side effect. Once a strict plan has been
accepted, a planning or execution failure is fatal rather than silently
executing the operation twice.

For each K/V head, the adapter converts its six F32 query rows to F16 and
invokes one immutable AKV plan. The shared native kernel then keeps the query
group and online-Softmax state resident while streaming each K/V token once.
The two K/V heads of Qwen2.5-1.5B consequently produce two AKV groups per
Attention node.

GGML calls each compute node on every worker. AKV v1 owns one hidden context,
so all workers make the same support decision, worker zero executes the AKV
groups, and the other workers join GGML's existing post-node barrier. This
prevents context aliasing without introducing a private synchronization path.
Coverage is counted once per operator by worker zero.

## 3. Model-level validation

The reproducible check uses this configuration:

| Item | Value |
|---|---|
| model | Qwen2.5-1.5B-Instruct Q4_K_M |
| model structure | 28 layers, embedding 1536, FFN 8960 |
| Attention shape | 12 Q heads, 2 K/V heads, D=128, GQA=6 |
| prompt / generation | 10 prompt tokens / 2 generated tokens |
| backend workers | 4 |
| QEMU ISA | RV64GCV, VLEN=1024, ELEN=64, Zfh, Zvfh |
| comparison | standard RVV versus AKV software emulation |
| QBS | disabled in both runs to isolate Attention |

The standard run leaves AKV disabled. The second run enables AKV emulation but
uses the same static llama.cpp binary, model, prompt, sampler, and GGML graph.
The complete full-vocabulary logits record is captured at both generation
steps, rather than checking only the selected token.

The emulation callback deliberately reuses GGML's standard RVV
`ggml_vec_dot_f16`, `ggml_vec_scale_f16`, and `ggml_vec_mad_f16` helpers. This
keeps the functional model on the same F16 accumulator and reduction contract
as the fallback. It remains distinct from the native assembly's vector
exponential approximation, so native numerical tolerance still comes from the
RTL operator benchmark.

## 4. Discriminating failures and fixes

The first complete model run exposed a framework integration error. The
adapter required `nth == 1`, but GGML invoked each of 56 Attention nodes on
four workers. The trace consequently reported 224 candidate callbacks and 224
threading fallbacks, with no execution. Source inspection showed that GGML
already places a barrier after every node. Restricting execution to worker zero
while letting the other workers join that existing barrier removed the false
threading restriction; no private barrier was added.

The next complete run executed all 28 Decode nodes and generated identical
text, but its maximum logits difference was 0.874824524. The AKV emulation had
used a scalar sequential FMA loop for Q-K dot products, whereas the standard
RISC-V path used the GGML RVV widening accumulation and reduction helper. That
different accumulation order was sufficient to amplify through 28 layers.
Replacing the scalar dot, F16 scale, and F16 accumulation loops with the same
GGML helpers reduced both maximum absolute and relative logits differences to
zero. This was a numerical-model correction, not an RTL or timeout tuning
experiment.

## 5. Native operator evidence

The shared native assembly kernel is the same kernel measured at milestone 4
on real Qwen2.5 captures. Those RTL results remain the native performance
evidence:

| Effective KV | RVV cycles | AKV cycles | Speedup | Mismatches |
|---:|---:|---:|---:|---:|
| 16 | 137,961 | 50,881 | 2.7114x | 0 |
| 128 | 796,177 | 382,001 | 2.0842x | 0 |
| 256 | 1,551,299 | 760,366 | 2.0402x | 0 |

The reference is the upstream one-dot-at-a-time RVV operator on the same RTL
environment. The speedup therefore demonstrates the combined benefit of
grouped software scheduling and AKV resident/reuse semantics. A portable
multi-row tiled-RVV baseline is still required to isolate how much of that
benefit is achievable without the AKV hardware contract.

## 7. Reproduction

Build the shared llama.cpp backend and run a fresh model check:

```bash
hardware/scripts/akv/build-llama.sh
hardware/scripts/akv/run-qemu-model-check.sh
```

Each run writes its artifacts under `hardware/akv_jobs/qemu_model_*`. A
completed serial log can be checked without rerunning the model:

```bash
hardware/scripts/akv/run-qemu-model-check.sh \
  --check-log hardware/akv_jobs/qemu_model_*/qemu.log
```

The validator requires nonzero AKV execution, zero threading fallback, at
least one complete logits record, equal top-1 logits and generated output, and
a maximum absolute logits difference no greater than 0.001 by default. Set
`AKV_LOGITS_MAX_ABS_TOLERANCE` only when a separately justified numerical
contract requires another threshold.

## 8. Remaining boundary

Milestone 5 closes a strict, real-model Decode profile, not a universal
Attention backend. Prefill, D=64, GQA ratios other than six, multiple query
tokens or batches, sinks, ALiBi, softcap, and unsupported layouts continue to
use standard RVV. Native execution must be enabled only on a platform known to
implement the AKV capability query and command ABI. QEMU emulation validates
software integration but does not predict AKV cycles or the native vector
exponential's instruction-order result.

The next attribution step is a portable multi-row tiled-RVV baseline. Wider
shape support should be added only with a concrete register plan, numerical
contract, and RTL validation rather than inferred from the broader descriptor
capacity.
