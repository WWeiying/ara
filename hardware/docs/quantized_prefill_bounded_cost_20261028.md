# 分组规划的有界成本核算

`boundary_cost_bounded.h` 是独立实验实现，未接入生产路径。它不改变成本
定义，而是把相邻、行状态完全相同的 tile 合并计数。

一行可见前缀为 L 时，以 token tile 起点观察，仅在 `floor(L/32)*32`
和 `ceil(L/32)*32` 发生 full/partial/empty 转换。相同状态区间内的命令
分解相同，可用单 tile 命令数乘区间 tile 数精确累加。八行至多十六个
转换点，不需要按上下文中的每个 tile 重复扫描。

## 测试

命令：`python3 -B -m unittest test_boundary_plan test_boundary_cost`。

- 2256 个组合与旧逐 tile 成本函数比较，values/commands/panels 全部一致。
- 覆盖 1..8 行、非单调随机前缀、非零数组起点、31/32/33 等边界及
  65503/65504/65505/65535/65536。
- 实测最大 16 个状态区间；代码要求区间数不超过 `2*rows+1`。
- 将新成本函数用于相同反向边界调整后，160 个调度形状输出与原型完全相同。
  仍是 22 点改善，其余不变，三个工作量指标均未增加。
- GCC 与 Clang UBSan 均通过；实际 C scheduler 的回调计数核对仍保留。

## 能说明与不能说明的内容

可说明成本核算不再随上下文 tile 数线性增长，且在测试域内没有采用近似
或抽样。不能说明规划免费、周期必然下降或所有分组缺口已修复。
相邻组调整依然只利用尾部空余空间；满八行组的限制未被改变。

生产入口、已有 RTL/模型通过点和默认开关保持不变。下一步应选择真正
改变分组且具有真实模型输入的点，验证输出、活动及包括规划成本在内的
完整周期，再决定是否安装。不能仅凭 callback 工作量更少默认启用。
