# 矩阵链路平衡优化：分段累积与取消恢复验收

## 验证目的

长 K 运算可能通过多条命令完成：前一段的 FP32 部分和成为后一段的 seed。
只验证从零开始的整段点积，不能证明中途保存、恢复后仍保持相同的运算顺序。
本测试在相同候选计算模块上分别执行不分段和分段模式，检查每个累积器的
中间值、实际 seed 写入、后续 FMA 的 addend 和最终结果；不只检查最后的和。

RTL 与完整控制器验收使用相同的七份候选计算模块。此测试的 payload 输入宽度
为 128 位，矩阵计算配置为 wide=1、balanced=1、SeedRestore=1；输入宽度不同
仅用于计算部件的功能验证，不用于与 256 位控制器或 SoC 比较吞吐。

## 实测与检查

| 指标 | 不分段 | 分段 |
| --- | ---: | ---: |
| 原始数值场景 | 36 | 36 |
| 累积请求数 | 2792 | 2792 |
| 最终 FP32 输出数 | 1428 | 1428 |
| K 中间分段次数 | 0 | 362 |
| 检查的 seed 写入字数 | 0 | 1364 |
| M4 非零检查点字数 | 0 | 596 |

362 次中间分段不是 362 个独立随机程序：其中包含长 K 场景的连续前缀。
M4 场景具有 21 个 K 中间前缀；每个前缀均要求有真实非零部分和，避免用全零
seed 掩盖恢复错误。每个实际 seed 写入均与相应检查点逐位相同，首个继续请求
必须关闭 first-block，其后 FMA addend 必须使用该 seed。

两种模式的每个累积器按 K 顺序记录的 FMA 操作数完全一致。全部最终输出使用
原始独立 C 数值期望，fflags 和有效工作量检查保留。两种模式均完成 fault 与
reset 的 seed 取消测试、四个流水阶段的 fault drain/recovery 及 fault discard。
取消后先执行数值恢复场景，不能仅靠后续 reset 清空状态来掩盖 fault 恢复错误。

## 结论与边界

候选计算模块通过非零 seed、分段 K、取消和恢复的功能验收。它还不代表 ISA 的
VRF seed 采集路径、真实 lane 写回、完整 SoC、Linux 或 FPGA 已验收，也没有
提供性能、面积或功耗结果。完整控制器结果见
`LLAMA_BALANCED_CONTROLLER_ACCEPTANCE_20261106.md`。
