# QBS and AKV Model-Level Closure

## 1. Scope

This closure establishes functional, numerical, coverage, logical-traffic,
and representative RTL-cycle evidence for QBS plus AKV-v2. It deliberately
excludes synthesis, area, power, timing closure, place-and-route, and any claim
that a complete model was simulated cycle accurately in RTL.

The mechanism-level entry point is:

```bash
python3 hardware/scripts/akv/check-goal-closure.py
```

The checker reads `hardware/scripts/akv/goal-closure-manifest.json`, validates
the raw artifacts, and writes `hardware/qbs_akv_model_closure_20260831/`.
The generated `ablation.csv` and `support_matrix.csv` are derived from the same
checked artifacts rather than manually copied tables.

The cross-model architecture/topology closure is generated by
`hardware/scripts/akv/summarize-model-generality.py` and is archived under
`hardware/qbs_akv_model_generality_20260831/`. Its `complete` marker is written
only after all Host, QEMU, ABI, provenance, representative-shape, and RTL
cross-checks pass. The cross-model verifier also requires every QEMU summary
to carry the current model-closure summarizer hash, preventing results with
different activation-accounting semantics from being combined.

## 2. QBS Activation Lifetime

The real Qwen trace identifies reusable activations by graph epoch, source
tensor and data object, activation profile, shape, and byte content. Q/K/V and
gate/up reuse is admitted only when this semantic identity is equal; pointer
equality alone is insufficient. The optimized and baseline traces retain an
identical QBS matrix-command stream.

| Metric | Per operation | Cross operator | Eliminated |
|---|---:|---:|---:|
| Quantizations | 394 | 309 | 85 |
| F32 quantization-input bytes | 21,971,968 | 21,449,728 | 522,240 |
| Quantized Q8_K bytes | 6,265,444 | 6,116,524 | 148,920 |

The controlled three-operation RTL workload holds matrix work constant. It
reduces cycles from 48,634 to 25,480 (`1.91x`) and removes exactly 15,792
logical read bytes. The complete Decode projection improves by only `0.94%`,
which bounds the mechanism's model-level importance honestly.

## 3. AKV Shape and Fallback Closure

The frozen derived-real matrix covers:

- head dimensions `64` and `128`;
- GQA ratios `1`, `4`, `6`, and `8`;
- KV lengths `16`, `63`, `64`, `65`, `128`, `256`, and `1024`;
- scalar-reference and ordinary-RVV execution.

All `112/112` case/mode pairs pass. KV lengths around 64 exercise both exact
tiles and tails. This matrix remains regression evidence for the original
D64/D128 and GQA1/4/6/8 contract; it is not used to infer the newly admitted
D96 or GQA2/3/5/7 cases.

Four real-model RTL leaves additionally prove command and traffic identities:

| Shape | Cycles | Commands | Q bytes | K/V bytes | Read payload | Replay bytes |
|---|---:|---:|---:|---:|---:|---:|
| D64/G8/KV64 | 43,357 | 1,026 | 1,024 | 16,384 | 17,472 | 131,072 |
| D128/G6/KV128 | 52,995 | 387 | 1,536 | 65,536 | 67,136 | 65,536 |
| D128/G4/KV63 | 37,069 | 766 | 1,024 | 32,256 | 33,344 | 129,024 |
| D64/G1/KV65 | 12,828 | 196 | 128 | 16,640 | 16,832 | 16,640 |

For every point, external Query bytes equal `GQA*D*2`, K/V bytes equal
`KV*D*4`, and read payload equals Query plus K/V plus the 64-byte descriptor.
The checker also verifies FULL/REFILL, row/column load, RELEASE, replay, success,
fault, rejection, and final zero-mismatch conditions.

The generalized production rule admits D64/D96/D128 and every integer
`q_rows`/GQA ratio from 1 through 8. D96 is a D-axis tail in the unchanged D128
physical slot. The immutable seven-model Host logs were re-evaluated under this
rule into `hardware/akv_context_census_generalized_20260901_r4/`. Its
`support_matrix.csv` and provenance freeze the exact rule and prove all 28/28
model/KV cases at effective KV 16, 128, 512, and 1024. Real SmolLM2 D64/GQA3
and Phi-3.5 D96/GQA1 RTL leaves pass with zero mismatches in 30,853 and 10,073
cycles, respectively.

D256 is deliberately different. The runtime, reference model, and directed
RTL tests implement a two-D128-phase contract without increasing K/V context
capacity. A real Gemma D256 leaf is functionally correct at 47,191 cycles, but
the matched strong tiled-RVV leaf takes 36,043 cycles. The resulting 0.764x
ratio fails the required 1.2x admission gate, so D256 remains an explicit
production fallback rather than an unprofitable fast path.

## 4. Real-Model Closure

The architecture/topology suite contains six dense models and one real MoE
model across five GGML architectures. The frozen full-model QEMU runs contain
one Prefill and one Decode graph; the current Host table below reports only the
one-token Decode graph, so its candidate counts are not doubled.

The current Host census gives the following production-selection matrix. Node
counts are per one-token Decode graph; the full-model QEMU runs contain one
Prefill and one Decode graph.

| Model | GGML arch./topology | Head dimension | GQA | Decode AKV candidates | Current disposition |
|---|---|---:|---:|---:|---|
| Qwen2.5-1.5B | qwen2/dense | 128 | 6 | 28 | execute |
| TinyLlama-1.1B | llama/dense | 64 | 8 | 22 | execute |
| SmolLM2-135M | llama/dense | 64 | 3 | 30 | execute |
| Llama-3.2-1B | llama/dense | 64 | 4 | 16 | execute |
| Gemma-3-1B | gemma3/dense | 256 | 4 | 26 | D256 performance fallback |
| Phi-3.5-Mini | phi3/dense | 96 | 1 | 32 | execute |
| OLMoE-1B/7B | olmoe/MoE | 128 | 1 | 16 | execute |

The frozen `hardware/qbs_akv_model_generality_20260831/` QEMU suite predates
the D96/GQA3 extension. All seven runs in that artifact pass and execute
908,688 native QBS commands with zero emulated commands. QBS operator work
equals command work, token and Top-1 checks pass, and every AKV non-execution is
accounted for by the then-current selector. It remains valid evidence for QBS
and the unchanged AKV shapes, but its SmolLM2 and Phi fallback records are not
evidence against the generalized selector.

The generalized QEMU reruns cover both shapes newly admitted by this work.
SmolLM2 executes all 30 Decode D64/GQA3 AKV operations (90 Query groups) and
retains 30 intentional Prefill shape fallbacks. Phi-3.5 executes all 32 Decode
D96/GQA1 AKV operations and retains 32 intentional Prefill shape fallbacks.
Neither run reports runtime, capability, threading, feature, layout, or mask
fallback. For both models, QBS-only and QBS+AKV runs have identical generated
text, top-1 result, and recorded logits (`logits_max_abs=0`). Their separately
reported QBS-versus-RVV logits are not asserted bit-identical; token output and
top-1 nevertheless match. These QEMU results are kept separate from Host
eligibility and directed RTL evidence, so no Host count is substituted for an
executed model operation.

The Host census covers all seven models at effective KV lengths
16, 128, 512, and 1024, for 28/28 passing cases. Candidate Attention work is
reported for every shape, while AKV-eligible work includes only admitted
D64/D96/D128 and GQA1..8 shapes. Gemma D256 retains its real workload counts
while executing through ordinary RVV fallback.

OLMoE contributes 48 `MUL_MAT_ID` nodes per Decode graph and uses a real
64-expert/top-8 routing layout. Source activation rows, dynamically routed
matrix rows, and resident all-expert tensor capacity are counted separately.
The legacy QEMU trace lacks source shape for 96 Prefill-plus-Decode
`MUL_MAT_ID` records, so those activation counts are marked unavailable rather
than inferred; the newer Host graph supplies the exact source accounting.

All model files carry the published `Q4_K_M` label, but this does not imply
identical quantizer versions, importance matrices, or calibration data across
publishers. This seven-model suite tests the architecture/topology axis; the
separate nine-profile closure tests the format datapath axis. It is not a
seven-model by nine-profile Cartesian product.

### 4.1 Independent Qwen3 compatibility and numerical closure

Qwen3 is checked separately rather than retroactively changing the immutable
seven-model suite. The real Qwen3-1.7B-Q4_K_M file is a dense 28-layer model
with hidden size 2048, FFN size 6144, 16 Query heads, 8 KV heads and
D128/GQA2 Attention. It therefore changes the GGML architecture, matrix
shapes, vocabulary and GQA ratio relative to the Qwen2.5 anchor while staying
inside the existing profile and Attention contracts.

A matched Decode run produces the following dynamic evidence:

| Mechanism | Candidate/executed work | Dynamic execution evidence | Unexpected fallback |
|---|---:|---:|---:|
| Q4_K QBS | 169/169 tensors | 33,152 `qbexec` | 0 |
| Q6_K QBS | 30/30 tensors | 12,184 `qbexec` | 0 |
| AKV-v2 D128/GQA2 | 56/56 calls | 56 functional-v2 calls | 0 |

The ordinary-RVV, native-QBS, and native-QBS with functional AKV-v2 variants
each produce two comparable logits records. RVV-to-QBS and QBS-to-AKV both
have maximum absolute difference 0, KL divergence 0, cosine similarity 1,
Top-5 overlap 1, equal Top-1 decisions and equal generated output. Exact post-node digests also
match for all 394 selected `MUL_MAT` records in RVV versus QBS and all 450
selected `MUL_MAT`/`FLASH_ATTN_EXT` records in QBS versus AKV.

This exact result follows two localized numerical corrections. The specialized
ordinary-RVV Q4_K GEMV/GEMM path formerly computed min correction as a rounded
multiply followed by subtract, whereas numerical-contract v1 requires the
second FP32 update to be a fused negative multiply-add. It now uses standard
RVV `vfnmsac`, matching QBS without weakening the RVV baseline. The AKV
functional model formerly contracted score scaling and mask addition into an
FMA while the native path performs separate operations; its reference path now
preserves that native ordering. No QBS or AKV RTL arithmetic was changed.

These runs establish Qwen3 dense-model functional compatibility and precise
localization of the previous mismatch. They are QEMU functional evidence, not
full-model RTL timing, 40K-context quality, Qwen3-MoE coverage, synthesis or
PPA evidence.

Wide-M is also exercised rather than inferred from the planner. With an
explicit diagnostic `WIDE_M=1`, the short Qwen3 run executes 2,560 native Q6_K
M8 commands; Q4_K remains narrow because its exact padded-byte comparison does
not admit M8 for that shape. Focused real-data RTL tests pass Q4_K and Q6_K at
M4, M7, and M8 with zero mismatches and zero prefetch waits. However, M8 takes
7,638 versus 7,200 cycles for Q4_K and 44,493 versus 41,939 for Q6_K, regressions
of 6.08% and 6.09%. A fixed M33 model run also changes the Prefill Q6_K output
projection and the second Top-1 decision under WIDE_M=1. Production therefore
keeps `WIDE_M=0`; the wide path remains explicit diagnostic coverage, not a
traffic-only optimization claim.

Qwen3 Prefill exposes a second, independent boundary. GGML uses sequential
`one_chunk` Attention below 64 Query tokens and tiled Attention from 64 onward.
AKV implements the tiled numerical schedule. A pre-fix M33 probe found the
first score differences at one and three FP32 ULPs and measured the AKV
operator at 406,205 cycles versus 320,275 for the independent standard-RVV
Q64/KV64 tiled baseline. The latter is a strong measured denominator, not a
measurement of GGML `one_chunk`.
Accordingly, the production selector now returns M<64 to GGML. The selected
M33 Attention node then matches bit-for-bit. A real M84 D128/GQA2 graph does
execute AKV Prefill and matches all 172,032 output words, with 57,120 causal
pairs and 14,622,720 MACs accounted for. This is a decision-preserving
algorithm-boundary policy, not a tolerance relaxation.

The complete fixed M33 run also passes `decision-preserving-v1`: RVV/QBS and
QBS/AKV each compare two logits records with zero difference, equal Top-1, and
equal generated output. Q4_K and Q6_K execute 162,688 and 22,424 native M4/M1
commands respectively, with zero emulation and zero unexpected QBS fallback.
All 28 Decode Attention calls execute AKV-v2; the 28 Prefill candidates are
reported as the intentional `fallback_size` cases required by the M64 policy.

340 calibrated ordinary-RVV nodes. Applying exact activation-lifetime decisions
and representative real-model RTL rates gives:

| Component | Instances | Projected cycles | Share |
|---|---:|---:|---:|

These are RTL-calibrated component projections. They exclude scheduler,

6,116,524 effective quantized-activation bytes after lifetime reuse, 86,016
AKV Query bytes, and 315,392 AKV K/V bytes.

## 6. Regression and Support Boundary

All nine QBS RTL profiles pass 432 profile cases, and the command, descriptor,
read, commit, context, SRAM-macro-context, and end-to-end fault suites pass.
The formal Q4_K context point is 119,894 cycles versus 119,883 previously
(`+0.009%`); Q6_K remains exactly 208,863 cycles. An ordinary-RVV Attention
leaf also passes with zero mismatch, preserving the fallback path.

The multi-model layer reuses one guest `llama-simple` binary, one QEMU binary,
one VLEN=1024 CPU contract, and QBS ABI v2 with hash `b70836b84701...` across
all seven runs. The 28 selected representative QBS shapes cover 95.743% of
pooled projected one-token Decode work and include every observed GGML
architecture, topology, profile, and QBS operator. This is a work-weighted RTL
selection rather than one redundant leaf per model.

AKV-v2 currently admits Decode F32 Query, F16 K/V and mask, F32 output, one
batch, D64/D96/D128, GQA 1..8, and arbitrary positive KV lengths tiled by 64.
Unsupported GQA, sinks, ALiBi, softcap, incompatible layout, malformed mask,
or unavailable capability returns to ordinary RVV before hidden AKV state is
modified. D96 uses the D-axis-tail capability without increasing context SRAM.
D256 has a verified segmented software/RTL contract but remains outside the
GGML selector because it fails the performance gate. Generic admitted shapes
are correctness-complete but do not imply the same speedup as the specialized
D128/GQA6 arithmetic path.

The full-model QEMU layer is functional evidence: QBS executes native custom
instructions, while AKV uses its GGML functional-emulation path to check
selection, fallback, and numerics. Native AKV cycle evidence comes from the
representative RTL leaves; neither layer is a cycle-accurate full-model run.
