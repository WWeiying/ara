FPGA-only request timing boundary
================================

Scope
  Only hardware/fpga/ara_dsa_vcu118/rtl/cva6/core/acc_dispatcher.sv changes.
  Main RTL, clock frequency, QBS/AKV arithmetic, and Windows frozen build
  packages are unchanged. Old bitstreams do not contain this modification.
  Retain this FPGA overlay on future mainline imports; do not describe the
  resulting FPGA copy as byte-identical to mainline. The manifest's upstream
  source_sha256 records are provenance, not hashes of this new overlay.
  SHA256SUMS now records the actual overlaid dispatcher bytes. Its upstream
  source_sha256 is deliberately unchanged. Package verification checks file
  integrity only, not functional or timing acceptance. Future upstream sync
  must retain this explicitly documented overlay rather than discard it.
  acc_request_fpga.py now implements that export transformation, pinned to
  reviewed upstream and overlaid SHA256 values. Unknown revisions fail closed;
  repeated application to the tested overlay is a no-op. export.py invokes it
  without changing mainline. IntegrationPatchTests passed 8/8.

  Expanded checks exposed pre-existing baseline-selection differences:
  test_export.py ran 34 cases with one failure and one error in MainlineSyncTests
  (live-main simd_mul hash and historical db90e341 provenance replay).
  The FPGA simd_mul matches the requested qbs-akv-validated-20261029 tag exactly
  (6f2796c849dbfdcac556791d6b31be11ef2769441453c5bfcfc1db296dbf8471);
  current main has a later optional ExternalProduct interface. Do not import
  it just to satisfy a test comparing the wrong baseline.
  test_signoff_export.py passes 2/3 but dependency comparison fails on
  fpu_div_sqrt_mvp/hdl/defs_div_sqrt_mvp.sv: the frozen package uses upstream
  rounding codes unlike the locally modified dependency. Actual unit selection
  and pinned dependency provenance need review before deciding whether this is
  an active functional issue. These failures are not waived or called passes.

Evidence / hypothesis
  qakv_diagnosis_20261031/timing_summary.rpt:2786 reports a 64-level path from
  CVA6 CSR state through flush, the accelerator request bypass, Ara decode /
  reshuffle, response, operand forwarding and scoreboard. Placed slack is
  +0.134 ns (19.889 ns data delay), NOT final routed signoff.
  Registering forward request data/valid must remove this specific unbroken
  path. Other paths through live sidebands may remain and require measurement.

Implementation
  Replace the two-entry fall-through FIFO instance with the existing
  common_cells spill_register, explicitly Bypass=0. It retains two entries,
  breaks forward data/valid and reverse ready combinational propagation, and
  does not flush accepted requests. Authorization and instruction-queue pop
  logic remain unchanged. Both dependency sources already occur in sources.tcl.

Performance contract
  Empty-queue input-to-output latency increases by one clock (20 ns at 50 MHz).
  Sustained throughput remains one request per cycle with a ready consumer.
  Full-to-drain recovery can still have a ready bubble; no zero-bubble promise
  is made for a previously full queue. A serial request/response workload can
  lose performance; throughput alone cannot establish end-to-end neutrality.
  Do not add further pipeline stages or change QBS banking without evidence.

  those behaviors or real-program performance.

Required before deployment acceptance
  - Focused integrated checks of commit/flush, CSR ordering, transaction-ID
    reuse, preview/load hints and response backpressure/ownership.
  - Representative short dependent instructions and long QBS/AKV workloads
    against the same software/model baseline; report throughput AND latency.
  - Actual FPGA synthesis and per-clock timing reports showing the named chain
    no longer crosses the request boundary, followed by legal routed timing.
  - Independent QBS congestion analysis; this edit does not fix or prove that.
  No global Windows implementation restart is part of this focused change.
